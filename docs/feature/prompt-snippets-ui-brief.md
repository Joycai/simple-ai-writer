## 明确没做的（都是有理由的，不是漏了）

- **1f 的 `/` 行内唤起**：作者把它留给未来的 skill 系统，本轮不做。设计稿自己也把它排在右键之后（1l 开放问题 4）——右键补的是**唯一**一条保存路径，`/` 只是第二条取用路径。
- **1d① 新插入那段 240ms 的淡染**：三个输入框都是裸 `textarea`，给一段文字上底色需要一层镜像 div。扮演的 composer 有一层，另外两个没有——只给一个surface 加，等于让三处的反馈不一致；而给三处都加，是拿一个已知会出 bug 的机制（镜像层的滚动同步、组字期间的重挂）去换一次淡入。提示位那行字和入口下的赭石细线都在。
- **从气泡存片段时，痕迹画在片段入口而不是那条气泡的右下角**（1c⑤）：一条「你的库 +1」的确认，挂在库的入口上比挂在来源上更说得通，也不用把 trace 的坐标穿过每一层气泡组件。
- **1g 页头的「导入 / 导出」**：片段已经随应用配置备份整体走（设置 → 同步与备份），再开一条单独的片段文件通道是另一个功能。
- **1k 的「键盘连续 ↑↓ 时禁用行过渡」**：用把 `transition` 只写在 `:hover` 上近似——进入 hover 才有 120ms 淡入，键盘移动游标不带过渡。效果一致，不用跟踪输入模式。

# 设计任务：为一款桌面写作应用设计「提示词库」

## 产品背景

这是一款给小说 / 剧本 / 标书 / 公众号文案作者用的桌面写作应用（Tauri + React，Mac 和 Windows）。左边文件树，中间 Markdown 编辑器，右边呼出一个很宽的 AI 抽屉。

作者在**三个地方**对 AI 打字，这三个输入框是本次设计的全部战场：

1. **生成面板**的「自定义指令」多行输入框（AI 抽屉第一个 tab）
2. **对话**的聊天输入框（第二个 tab，旁边已有 `@` 引用文件/条目、子代理开关、发送按钮）
3. **扮演**的对话输入框（第四个 tab，作者以第一人称和自己写的角色对话）

作者会反复敲同一批指令：「把这段改写得更冷一点，保留对话」「检查以下条款与招标文件的偏差」「按人物卡口吻续写，不要上帝视角」。**这些指令值得被存下来，一键填回输入框。**

## 现在有什么，以及要补的四个缺口

已经有一个能用但很单薄的版本：设置里可以存「片段」，输入框底部会冒出一个小小的 ⚡ 按钮，点开是一个纯文字的下拉菜单，点一条就把正文追加到输入框末尾。

它在三个片段的时候刚好够用，在三十个的时候完全塌掉。**本次要解决的就是下面四件事，别的都不动**：

1. **存的地方和用的地方是断的。** 作者刚在聊天窗口里敲出（或看到）一段很好的指令，想留下来，得跑去「设置 → Prompt」，开一个抽屉，重新粘一遍，还得在一个七选一的「场景」下拉里认出「snippet」这一项。**顺手存下来的路径根本不存在。**
2. **取用列表只有名字。** 一个纯文本菜单，没有搜索、没有分组、没有正文预览、没有键盘导航。作者记不住三十个名字分别对应什么。
3. **一个片段都没有的时候它完全不渲染**，所以不知道有这功能的人永远不会知道。
4. **概念被混在了一起。** 管理界面里，「片段」和「覆盖 AI 的内置系统指令」是同一张列表里的两种行，靠一个小徽章区分。这两件事的风险和心智完全不同：一个是随手存的便签，另一个改错了会影响所有生成。

**明确不在本次范围内**（已经决定了，请不要重新设计）：
- 插入位置就是**追加到输入框末尾并换行**，不跟光标走，也不处理选中文字。这不是问题。
- **没有占位符替换引擎**。占位符（比如 `{{在这里补上条款原文}}`）只是片段正文里的**字面文本**，插入后原样出现，由作者手动补。不做自动填充、不做 Tab 跳转、不做变量语法。设计上只需要让它在预览和输入框里**看得出来是待填的**即可。

## 这个界面要解决的核心张力

**片段库必须同时是「随手扔进去」和「三十条也不乱」。**

偏向：**取用侧和保存侧要快到不假思索，管理侧才承担组织成本。** 输入框旁边那个入口是每天点几十次的东西，多花 200ms 就会被放弃；而整理片段是一个月一次的事，可以更重、更完整。

**同时，输入框不能因为这个功能变重。** 三个输入框已经各自挂着 `@` 引用、子代理开关、模型选择、发送按钮、快捷键提示。片段入口要在「看得见」和「不添乱」之间找到位置。

## 视觉规范（硬约束，必须遵守）

这个应用有严格的既定视觉语言，新界面必须无缝融入：

- **风格**：克制的、现代的、Apple 式的。整体气质是"手稿"——像裁切的纸，不像圆角卡片。
- **圆角：全局为 0。** 所有容器、按钮、输入框、下拉都是直角。唯一允许的圆形是状态圆点、加载指示器、单选标记和头像。开关是方形的。
- **强调色：只有一个** —— 赭石色 sienna（浅色 `#A0522D`，深色 `#D9925B`）。禁止多色渐变；需要区分状态时用中性灰阶 + 这一个强调色的深浅。
- **层次靠阴影，不靠边框**。四级阴影（sm/md/lg/xl），取能读出来的最小那一级。
- **字体**：正文衬线（手稿感），UI 标签无衬线，代码/角标等宽。中文正文默认宋体系。
- **动效**：120–320ms，Apple 缓动，"几乎察觉不到但很顺"。不要弹跳、不要大位移。
- **深浅双主题都要出**，不是深色改个背景色了事。
- **选中 vs 悬停要分开**：选中用强调色淡染，悬停用中性灰。把悬停也染成强调色会让人以为选中了。
- 现有那个 ⚡ 按钮的量级可以参考：11px 无衬线、5×9px 内边距、1px 静态描边、悬停才变强调色。**新入口不应该比它重多少。**

## 画布尺寸

两块画布，都要出：

- **AI 抽屉**：从右侧滑出，宽 **1180px**（最大 94vw），高度占满窗口。输入框在抽屉底部，宽度约 1100px。取用和保存都发生在这里。
- **设置页**：占满整窗的独立页面，左侧一列导航（通用 / 工作台 / 供应商与模型 / 子代理 / **Prompt** / 用量 / 同步与备份 / 快捷键 / 关于），右侧是内容区，编辑用**右侧滑出的抽屉**而不是弹窗——这是本应用既定的模式，请沿用。

## 需要设计的界面

### 1. 片段选择器（最重要）

从输入框旁的入口点开的浮层。**请直接沿用本应用「模型选择器」已经确立的那套语言**，让它一眼就是同一个家族的控件：

> 模型选择器打开后是：顶部一个带放大镜的搜索框，下面一排筛选 chip（全部 / 常用 / 本地 / 长上下文），再下面是**按供应商分组**的列表，每组一个小标题；当前选中项用**左缘一道细规则线**标记，而不是填充高亮块（"高亮块会盖过它所在的列表"）。

片段选择器要有对应的四件事：

- **搜索框**：同时搜名字和正文。请设计搜到正文时的命中高亮方式。
- **筛选 chip**：至少「全部 / 常用（最近用过）」，剩下的由你定——这是留给你的设计判断。
- **分组**：片段需要一个分组轴。**这个字段目前不存在，会为这次设计新增**，所以请你顺便决定它是什么形态：是单选的「分组」（像供应商那样，一个片段只属于一组），还是多选的「标签」？两者对这套 UI 的影响不同（分组能直接套用现成的分组列表，标签则需要一排可切的 chip）。**请给出你的选择和理由。** 没分组的片段落在哪里也要画。
- **行的样子**：名字 + 正文头一行的灰色预览。请给出 3 条、12 条、30+ 条三种密度。

键盘要全程可达：唤起、打字过滤、↑↓ 选择、Enter 插入、Esc 取消。

**插入行为是既定的**：正文追加到输入框末尾并换行，浮层关闭，输入框保持焦点。请画出插入瞬间的反馈——**要克制，不要 toast**。

### 2. 右键「存为片段」——这是本次最关键的补丁

作者在**对话窗口里选中一段文字**，右键，菜单里就能存成片段。两个位置都要覆盖：

- **输入框里**：作者自己刚敲的一段指令
- **消息气泡里**：作者上一条发出去的提问，或者 AI 回复里的一段话

**一条硬约束**：这三个输入框现在是裸 textarea，右键出的是**操作系统自带的剪切/复制/粘贴菜单**。一旦换成应用自己的菜单，作者就会失去这些——所以你设计的菜单**必须自带剪切 / 复制 / 粘贴 / 全选**，「存为片段」是加在它们下面的一项（本应用的编辑器右键菜单已经是这个结构，请对齐）。请把有选中和无选中两种状态下的菜单都画出来（无选中时「存为片段」是禁用还是存整框？请给出你的答案）。

选完之后要给名字。请设计这个命名步骤的形态——它必须**轻**：作者是在写东西的中途顺手存的，任何一个把他拽出上下文的大弹窗都会让这条路径失效。可以考虑就地小浮层、名字预填正文头几个字、Enter 直接存。分组/标签在这里要不要选，你来判断（**倾向：不要，事后在管理页整理**）。

存完的确认同样要就地、要小，作者需要知道"它进库了"，但不该被打断。

### 3. 零片段时的入口

**入口永远存在，不隐藏。** 一个片段都没有的时候，按钮照常显示，点开是一个空的选择器——空态本身就要说清片段是什么、怎么存第一条（指向右键那条路）。这是这个功能唯一的自我介绍机会。

### 4. 管理界面（设置 → Prompt）

这一页现在把两件不同的事塞进了一张列表：作者自己的片段，和对六条内置指令（系统提示词、续写、润色、改写、总结、知识库生成）的覆盖。

**这一页交给你重新设计**，不预设结构（两个 tab？上下两区？主次分栏？）。要满足的只有这几条：

- 片段是主角：能搜索、能按分组/标签筛、能改分组、能删。行里要看到正文预览。
- 内置指令覆盖是高级区，要在视觉上明确"更危险"、更靠后——但**只能用中性灰阶和唯一那个强调色**做出这个区别，不能引入警示红/黄。每条能展开看当前全文，能写一份覆盖版，已被覆盖的要一眼可见。
- 编辑片段的抽屉：名字、分组/标签、正文（大的多行输入）、以及一个「它在选择器里长什么样」的预览。正文里的 `{{…}}` 占位符如果能被轻轻标出来更好——但记住这只是**字面文本**，不要把这个输入框设计成富文本编辑器。

### 5. 各种状态（全部要画）

- 零片段（见 §3）、搜索无结果、只有一条结果
- 名字很长、正文很长（预览怎么截）、正文只有一行
- 30+ 条时的滚动与分组表现
- 右键菜单：有选中 / 无选中
- 深色 + 浅色
- 中文与英文（应用双语，英文名字会长很多）

## 开放问题（如果设计上有更好的答案，请直接推翻我的假设）

1. **分组还是标签？** 见 §1，这是本次最需要你拍板的一个数据形态问题。
2. **片段是装机级的，不是项目级的**——同一份库会同时出现在写小说的项目和写标书的项目里。分组/标签够解决吗，还是列表需要更强的组织轴？
3. 三个输入框（生成 / 对话 / 扮演）要不要各自看到不同的片段？现在是共用一份。
4. 除了点按钮，要不要支持在空输入框里敲 `/` 就地唤起同一个选择器？（这个应用的 `@` 引用已经是这套行内 typeahead 交互，复用成本低。）**这是加分项，不是必须。**

## 交付

- 片段选择器：3 / 12 / 30+ 三种密度，深浅两套
- 右键菜单（两种选中状态）+ 命名步骤 + 存入确认
- 零片段空态
- 重新设计后的设置页 + 编辑抽屉
- 边界态一组
- 关键交互（选中 → 右键 → 命名 → 存入）和（唤起 → 过滤 → 插入）两段流程说明；动效标出时长与曲线
- 用到的间距 / 字号 / 灰阶层级，说明取自哪一级

## 不要做的事

- 不要圆角，不要多色，不要渐变按钮，不要 emoji 图标
- 不要把选择器做成一个大弹窗——它是打断
- 不要 toast 通知；反馈要就地、要小
- 不要给片段做「一键发送」——片段是个开头，作者要补完再发，自动发送会把半成品打出去
- 不要设计占位符的自动替换 / Tab 跳转 / 变量语法（见前文，已明确排除）
- 不要动插入位置（永远追加到末尾）
- 不要把正文编辑做成富文本 / 所见即所得
- 不要引入第二个强调色来区分「片段」和「内置指令覆盖」
