# 导出 Excel（.xlsx）——agent 产出工作簿

> 状态：`shipped`（一期，PR #394 已合并）。Beta 开关：设置 → 通用 → 实验功能 → 「Excel 导出」，默认关。
> 需求：**能导出 xlsx**。落点和 docx 那条一样是「agent 能产出」，不是导出菜单里多一个格式——
> 理由见 §7。读的方向早就有了（`src-tauri/src/xlsx.rs`，calamine），这一片补上写的方向。

## 1. 现状盘点（动手前逐项核实）

| 环节 | 现状 | 位置 |
|---|---|---|

| Beta 三件套 | `flag.ts` + `routeTools` 剥离 + 设置页开关 | pptx / docx 各一套 |

## 2. 四条不变量

### I1 模型只写 markdown 表格，类型由确定性代码判

模型产出的是这个 app 的原生格式——一张 markdown 表格，作者在预览里读得到、在编辑器里
改得动、下一轮还能让模型改。**转换本身不跑任何模型**：哪个格子是数字、哪个是日期、哪个
是公式，由 `lib/xlsx/cells.ts` 的规则判定。同 docx I1。

### I2 一张表格 = 一个工作表，名字来自它上面最近的标题

和导入侧严格对称：`xlsx.rs` 把一份工作簿写成 `## 工作表名` + 表格，这里把同样的形状读
回去。作者因此**不需要学任何新写法**——他们已经见过这个形状了，那是导入产生的。

### I3 数字必须是数字

一份所有格子都是文本的 .xlsx 不是电子表格，是表格的截图：求和不出数、排序按字典序、
日期筛选整个不存在。作者要 .xlsx 而不是要一张表，要的就是这些。**这一条是这个功能的
实质，其余都是管道。**

推论（`cells.ts` 的兜底方向）：**判不出来就留成文本**。把文本错判成数字是静默的数据
损坏（`007` 变 `7`，18 位单号末三位变 `000`），把数字留成文本作者一眼就看见。

### I4 Beta 关 = 工具缺席，不是拒绝

同 docx I4、pptx。关着的时候 `routeTools` 把 `export_xlsx` 整个剥掉，模型根本看不见它，
所以不会提出一次自己执行不了的导出，也不会为它付一个 token。

## 3. 数据流

```
作者：「把这些报价做成 Excel」
  → 模型 create_file 写一份 markdown（表格 + 标题）        ← 第一张卡（普通的写文件审批）
  → 模型 export_xlsx(source_path)
      lib/xlsx/sheets.ts   markdown → SheetSpec[]（复用 lib/docx/blocks 的 token 流）
      lib/xlsx/cells.ts    每个格子 → 有类型的 Cell
  → XlsxProposal（**工作簿此时已经建好**）                  ← 第二张卡（工作表清单 + 类型统计）
  → 批准
      lib/xlsx/write.ts → invoke("xlsx_write_workbook") → Rust → base64 → writeBinaryFile
```

两张卡的理由同 docx §2.1：markdown 那张是内容，xlsx 这张是「转换成什么样」。

**一处和 pptx / docx 都不同，并且是有意的**：工作簿在**提案时**就建好，落盘时不再读一次
源文件。pptx 非等批准后不可（它得先有 DOM 才能量版面），而这条链上没有任何东西非等不可，
于是「作者批的」和「写下去的」可以严格是同一本——中间源文件被改一笔也不影响。作者在
卡片上核对的正是这些类型判定，那就不该让它们在批准之后重新算一遍。

## 4. 单元格类型判定（`cells.ts`）

判定顺序是设计的一部分，不能换：公式 → 布尔 → 百分数 → 日期 → 数字 → 文本。

| 写法 | 判成 | 说明 |
|---|---|---|
| `12000` | 数字 | |
| `1,200` / `¥12,000.00` | 数字 + 格式 | 千分位、货币符号原样保留成 number format |
| `12%` | 数字 `0.12` + `0%` | **不是 12**，见下 |
| `2026-08-06` / `2026/8/6` | 日期 | 可带 ` 13:45` |
| `=SUM(B2:B9)` | 公式 | 与 Excel 的输入规则一致 |
| `true` / `FALSE` | 布尔 | 导入侧就是这么写的 |
| 其余 | 文本 | |

### 4.1 五个「看起来对、其实是数据损坏」的细节

全部有测试钉住（`__tests__/cells.test.ts`）：

1. **前导零留成文本。** `007`、`0512`（区号）、`00123`（工号）转成数字就少了字符，而作者
   是照着原样核对的。
2. **超过 15 位有效数字留成文本。** f64 只有 15–16 位十进制有效数字，18 位身份证进去
   出来末三位是 `000`——**而且文件打开时看起来完全正常**。这是电子表格最经典的那个坑。
3. **百分数存分数。** `12%` → `0.12` 配 `0%` 格式。存 `12` 的话同一列求和会错整整一个
   数量级，而单元格显示出来还是「12%」——错得看不见。
4. **不学 Excel 把 `1-2` 读成日期。** Excel 自己会（著名的基因名事件就是这么来的）。这里
   只认写全了的年月日，并且 `2026-02-30` 是文本而不是二月三十号。
5. **带单位的数留成文本。** `12000元` 是一句话，不是一个数；货币**符号**只认前缀
   （`¥12000` 是数）。单位跟在后面时无法既保住数值又保住那个字。

### 4.2 转义与导入侧互为逆运算

`xlsx.rs` 的 `escape_cell` 把 `|` 写成 `\|`、换行写成 `<br>`；`unescapeCell` 逐条撤销它。
**往那边加一条转义，就要往这里加一条**——否则一份工作簿导进来再导出去，备注里会多出
反斜杠、多行会变成字面的 `<br>`。Rust 侧有一个跑通整条往返的测试
（`the_grid_survives_a_round_trip_through_the_importer`）。

## 5. 分层与文件落点

抄 `lib/pptx/`、`lib/docx/` 的分法：**不碰库就能决定的，都不在碰库的文件里决定。**

```
src/lib/xlsx/
  flag.ts    # Beta 开关
  cells.ts   # 一个字符串 → 一个有类型的格子。纯，测试全在这里
  sheets.ts  # markdown → SheetSpec[]（复用 lib/docx/blocks，不新开第二份 markdown 方言）
  write.ts   # SheetSpec[] → 字节。唯一知道生成端在 Rust 的文件
  index.ts   # 编排：读盘、摘 frontmatter、规划、落盘
src-tauri/src/xlsx_write.rs   # 唯一知道 rust_xlsxwriter 的文件
src/lib/agent/xlsxTools.ts    # export_xlsx：查路径、建工作簿、摆卡片
```

## 6. 决定与弃案

### D1 生成放 Rust（`rust_xlsxwriter`）

- crate **已经在树里**（dev-dependency，给 xlsx.rs 的往返测试造 fixture），提升成正式依赖
  是一行；lockfile 里的版本没变。
- JS 侧的可选项就是 xlsx.rs 当初读的时候已经否掉的那些：npm `xlsx` 构建陈旧且带
  advisory，ExcelJS 是启动包里的一兆。
- webview bundle **零增长**（docx / pptx 各懒加载一兆多）。

**这和 docx 00-feasibility D5「生成放 TS」不矛盾，是同一条规则的两次应用——跟着已有的
那一份走。** docx 要生成就得先解析 markdown，而 markdown 方言（含本项目的 `lore_cite`
token）在 TS，用 Rust 生成就要再实现一遍方言，两份必然漂移；这里**方言一个字都不过界**：
`sheets.ts` 已经解析完、`cells.ts` 已经判完类型，过去的是一张定了型的格子表，Rust 侧一个
字符都不解析。而 xlsx 的读写库早就在 Rust。

### D2 边界是 base64

字节按 base64 回来，不按 JSON 数字数组——数组把体积撑成四倍。xlsx **导入**那条
（`data: Vec<u8>`）是全树唯一的例外，不复制它。同 pptx-plan D3。

### D3 弃用【工具参数里直接给一个 JSON 网格】

看起来更直接：模型把二维数组写进 `export_xlsx` 的参数。否掉，因为**没有任何地方能审**——
作者要改一个数字就得再跑一轮模型，200 行的表要付两遍 token，而卡片上只能渲染一份存在于
工具调用里、编辑器打不开的数据。markdown 表格是这个 app 里唯一一种「模型写得出、作者
改得动、下一轮还能接着改」的表。

### D4 弃用【HTML 表格 → xlsx】

pptx 那条链最贵的一步是「把页面渲染出来量版面」，而电子表格**根本没有版面**这件事可量：
它是格子和值。走 HTML 只会白付一次渲染，还把源头换成一种作者不会拿来记数据的格式。

### D5 弃用【合并成一个 `export_document(to: ...)`】

三个导出的转换契约不一样（docx 要格式预设、pptx 要 .html、xlsx 要表格 + 类型规则），合并
只会把三段说明并成一段更长的、每句都带「仅当 to=… 时」的说明，schema 反而更贵，模型也
更容易把参数配错。

## 7. 一期不做（说清楚，不假装）

| 内容 | 现状 |
|---|---|
| 合并单元格 | 不做。导入侧把合并写成 `**Merged cells**: A1:C1` 一行文字，读回去是可以的，但那是第二套解析规则，单独一期 |
| 导入产生的 `**Formulas**` 块 | 同上：不读回去。要公式就把它写在格子里（`=B3*2`），那是模型和作者都直觉的写法 |
| 图表、条件格式、数据验证、图片 | 不做 |
| 多级表头 | 不做：首行是表头，其余是数据 |
| 导出菜单里的「Excel (.xlsx)…」 | 不做。当前打开的文档不一定是表格文档，而这个入口在 docx 那条上也没有做——出口是 agent |
| 多份 md 合成一本工作簿 | 不做：一份文档一本工作簿，一张表格一个工作表 |

**公式没有缓存结果。** `rust_xlsxwriter` 不写缓存值，Excel 和 LibreOffice 打开时自己算；
只读存储值的预览器（快速查看、部分网页预览）在重算之前那几个格子是空的。这一条**报给
模型让它转告作者**（agentStore 的 xlsx 分支），不做绕开——绕开意味着这个 app 自己实现
电子表格求值。

## 8. 审批卡

两端 + **一行一张工作表**：名字、`行×列`、以及这张表里有多少格子被判成了数字 / 日期 /
公式。理由同 docx §7.3——可审的是**判断**，不是产出的字节：一张明明是报价表却写着
「数字 0」的表，在卡片上一眼就能看见，而不是等到 Excel 里求和栏出现 0 才发现。所以
「数字」那一栏**为 0 时也照样显示**（只是安静下去），过滤掉它就等于把唯一的警报删了。

表格之外的段落数在卡片最后一行报出来：工作表没有地方放一段话，但悄悄扔掉是错的。

## 9. 工具预算

实测 `export_xlsx` 的 schema **+274 token**，全预设 14,861 → 15,135，棘轮从 15,000 抬到
15,200。抬之前按那个文件的要求读了 `agent-tool-context-lld.md` §5，结论是**那套延迟装载
的机制在这里不适用**：`lore_write` 能安全推迟，是因为有一道让它们在开门之前**必然失败**
的闸（没有已批准的方案，每次调用都只拿回一段错误文本），所以推迟不改变模型的路径；导出
工具没有这样的闸，它从第一轮起就是可调用的，推迟只会让模型看不见一个作者已经打开的功能。

它真正的闸是 Beta 开关，而那个开关**本来就不花钱**：`routeTools` 在请求组装之前就把工具
剥掉了，没开 Excel 导出的作者这 274 个 token 一个都不付。棘轮量的是**三个 Beta 全开**的
最坏情况。

## 10. 实现出入

1. **`escape_cell` 的逆运算写在 TS。** 原打算让 Rust 侧一并处理，但那样这条规则就有两份
   实现，而它必须和 `xlsx.rs` 逐条对应——放在 `cells.ts` 里，两边的测试都指得到同一条规则。
2. **表头行一律写成文本。** 一个写着 `2026` 的表头是标签而不是数值（没人会去求和它），
   所以 `xlsx_write.rs` 在 `header && r == 0` 时无视类型判定直接写字符串并加粗。
3. **工作表名的清洗只在 TS 做一次。** Rust 侧遇到 Excel 拒收的名字**报错而不是就地修**——
   两处各修一次，规则一定会漂。
4. **空格子不写。** 空单元格和一个长度为零的字符串在 `COUNTA` 里算得不一样，看起来却
   一模一样，这是最坏的一对性质。
5. **`cargo test` 在这台开发机上起不来**（既知问题，见 `docs/reference/ci.md` 的同类记录），
   Rust 侧的 9 个内联测试由 CI 跑；本地过的是 `cargo fmt` + `cargo clippy --all-targets`
   （测试代码已编译）。
