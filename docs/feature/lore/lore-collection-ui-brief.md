## 0. 这一轮不是「对齐」

前几轮都是把已有界面搬到设计稿上。**这一轮是加一根新的轴**，知识库的信息架构会真的变，
墙面大概率要重画。请不要为了兼容现状而克制。

## 1. 作者要解决的问题（原话）

> 我有时候需要在里面放多个不同的小说人物和条目，或者多个不同项目报告，他们有时候需要
> 互相引用来写作，有时候我又希望引用材料在某个集合内。现在这样 lore 完全无法满足。

一个项目的知识库里同时躺着好几摊互不相干的活（小说 A 的人物、小说 B 的人物、项目甲的
材料）。现在它们平铺在同一面墙上，既看不清，AI 取材时也会串味。

## 2. 概念定义（已定，请照此画）

知识库从此有**两根正交的轴**：

| | 分类 category | **集合 collection（本轮新增）** |
|---|---|---|
| 回答的问题 | 这条**是什么** | 这条**属于哪一摊活** |
| 例子 | 人物 / 世界观 / 势力 / 物品 | 小说A / 小说B / 项目甲报告 |
| 来源 | 能力包定义（+作者自建分类） | 全部由作者自建 |
| 归属数 | **恰好一个** | **可多个，也可以一个都没有（未归集）** |
| 磁盘上 | 是文件夹 | 不是文件夹，是条目上的一个字段 |
| 带类型 schema | 是（特征槽位/配图槽位） | 否 |

**取材范围（scope）**——集合真正的用处：

- 全局一个开关，默认「全部」。切到某个集合后，**AI 只看得见这个集合的条目**：自动匹配、
  agent 的条目列表与读取、一致性检查，全部同一个围栏。
- **手动切换，切换后记住**（本轮不做「跟当前文档自动切换」）。
- **围栏只挡「自动发现」，不挡「显式指定」**：作者置顶的条目、`@` 引用的条目、点开的
  条目、`[[lore:…]]` 引用照常生效——显式指定＝作者坚持。这条要在界面上说得清楚，否则
  作者会以为围栏漏了。
- **取材方式不变**：仍然是条目的名称/别名在正文里出现才注入。集合只是把候选池缩小，
  不是「整集塞进上下文」。

**术语纪律**：文档侧的文件夹在 UI 上叫**分组**（`terms.group`），知识库这根新轴一律叫
**集合 / Collection**。两个词不要互串，也不要再造第三个词。条目 / 知识库 / 特征 / 配图
的既有叫法不变。

## 3. 现状（不用重画、但要接得上的部分）

- **墙**（屏 14）：格纸底 + 微旋转硬阴影索引卡。头部一行 = eyebrow / 标题 / `N 条` 统计 /
  搜索 / 「AI 提取」/「＋ 新建条目」/「⋯」；下面一行是分类 chips = `全部` + 六色分类
  （带计数）+「＋ 新建分类」。卡片 = 分类标签 / 方头像 / 名字 / 别名行 / 特征名标签 /
  底部 `N 特征 · M 配图`。
- **详情页**（屏 15）：三栏 `主条目 320 | 特征 flex | 配图 300`，每栏自己滚，左栏底部有
  mono 文件树。
- **视觉语汇**：`--lore-*` 族、六色分类（`catColor.ts`）、硬偏移阴影、全局零圆角、
  计数用 mono、AI 新增内容用 diff 绿。

## 4. 需要的屏

1. **墙 · 有集合的常态。** 两根轴怎么同时呈现？分类 chips 还在，集合放哪？
   （可能的方向由你定：集合做墙面分区/泳道、集合做第二排 chips、集合做侧栏……）
   **必须回答：一个条目同时属于两个集合时，墙上出现几次？**
2. **墙 · 取材范围生效中。** 取材范围切到「小说A」时墙长什么样。**这是本轮最重要的一屏**：
   要一眼看出「AI 现在只看得见这些」，并且**不能和普通筛选混淆**——普通筛选只影响眼睛，
   取材范围影响模型。两者若长得一样，作者迟早会在不知情的情况下用错范围写一整章。
3. **取材范围切换器（展开态）。** 列表项：全部 / 各集合（带条目数）/ 未归集。要能表达
   「当前生效」。同一个控件会出现在**两处**：知识库墙头部、AI 面板。请一并给出它在
   AI 面板窄栏里的形态。
4. **给条目归集。** 两种：单条（详情页 / 右键菜单）和**批量**（墙上多选 N 条 → 归入集合）。
   多归属，所以是多选勾选而不是单选。批量是刚需——作者现有几十上百条要一次分完，
   没有批量这功能等于没做。
5. **集合管理。** 新建 / 重命名 / 删除。**删除集合不删条目**（只解除归属），这句话要
   写在界面上。
6. **详情页里的集合。** 三栏结构不变，集合显示在哪、怎么改（主条目栏的元信息区？面包屑？）。
7. **未归集的处理。** 切到某集合后，未归集的条目对 AI 不可见。要不要提示、怎么提示而
   不变成噪音？（也请给出「一条都还没归集」时整面墙的空态/引导。）
8. *（可选）* **AI 面板的取材范围指示带**：这次运行会从哪里取材，一条带子说清。

## 5. 数据模型的边界（画之前请读）

**现成的、随便用：**
- 集合有 id + 名字，可重命名、可删除、有稳定顺序
- 条目可属于任意多个集合，也可以零个
- 每个集合的条目数、集合内按分类的分布
- 空集合（先建集合再往里放）
- 条目的头像、别名、特征数、配图数、分类色

**没有数据，请不要画**（画了就只能落成永远为空的空态，前几轮踩过）：
- 集合的封面图/缩略图（条目有头像，集合没有）
- 集合的最近编辑时间、活跃度、完成度进度条
- 集合的层级/嵌套（本轮明确不做）
- 集合级的字数/token 统计（条目数以外的数字都没有）
- 关系图谱、出场密度（v2 已把它们移出详情页，不要复活）

如果你认为某样东西非有不可，请在稿上标注「**需要新数据：xxx**」，我来判断值不值得加字段。

## 6. 视觉语言约束

- 沿用 `--lore-*` 族、格纸墙、硬偏移阴影索引卡、全局零圆角（圆形只走 `--radius-round`）。
- **分类六色已经被分类占满了。集合不要再引入第二套彩色**——同一面墙上两套颜色会互相打架，
  而且分类色还兼着头像底色和候选徽标。请用非色彩手段区分集合：分区标题、线、装订、留白、
  层级。可参考扮演那一轮的结论——*同一批数据的两种装订，用装订而不是颜色来区分*。
- 「取材范围生效中」**不是错误态**：不要红、不要警告黄。它是一句陈述，像类型系统那一轮
  「缺口是邀请、降级是陈述」的口径。
- 计数一律 mono。
- 中英双语文案。

## 7. 请在稿子里明确回答的四个问题

1. 多归属的条目在墙上出现几次？（重复出现 = 好找但计数会骗人；只出现一次 = 诚实但归属不直观）
2. 取材范围和普通筛选，视觉上靠什么分开？
3. 批量选择模式（勾选框 / 框选 / ⇧ 连选）落在卡片的哪里，才不与「点开条目」「点头像换图」冲突？
4. 集合数量多（>10）时，切换器和墙面分区怎么退化？
