# 设计任务：在本项目里新建 `03f 设定集 · 分类操作与词典 Lore C.dc.html`

## 这三个面是什么

知识库墙（`03a 设定集 · 条目与类型 Lore A`）上，**分类**是第一根轴（恰好一个、用颜色），**集合**是第二根轴（多归属、用装订，`03b 设定集 · 集合 Lore B`）。这一轮补的三个面都已经在应用里跑着，稿上却没有它们：

1. **删除分类**——右键墙上的分类 chip、或在设置 → 工作台里移除一个自定义分类时弹出的确认。它存在的理由是它取代的那个东西：一颗不确认、不报数的 `×`，按下去分类从项目里摘掉、磁盘上的文件夹和条目一条不动，随即以「未声明」的样子继续挂在墙上、标签退化成文件夹 id。作者的感受是「我删了，它还在，而且名字变丑了」。「不删条目」那一半是对的，错的是不说。
2. **移到分类**——墙上多选之后把这一批搬进另一个分类。分类是磁盘文件夹，搬一次是真搬家；分类是替换语义，一条只能在一个分类里。
3. **词典标准化**——勾了「翻译词典」的条目，正文本应是一行一条 `原文->译文 #备注`，但作者常常拿一张表格或一段散文来。这个模态让模型**一次性**把词对搬进规范格式：模型只做搬运、一个译名都不许改，格式由代码渲染，产物必然能被翻译流水线读回。

其余背景请直接看 `03a`（卡片墙 / 详情三栏 / 屏 09、12 的设定模态外壳 / 屏 13 的条目 AI 中心 / 屏 17 的运行进度词汇）和 `03b`（多选动作条与归集清单，屏 26–28）。不用重新解释产品和视觉规范。

## 这次要解决的张力

### A · 删除分类（2 屏 + 降级态）

**A1. 两条出口是并列的两张卡，不是一个复选框。** 「连同 N 条一起移到…」和「只移除分类，保留文件夹与条目」的结果差得很远，复选框会让「没勾」也成为一个默认后果。今天是两张带单选标记的卡、默认一条都不选、确认键跟着禁用——作者必须主动说出他要哪一条。请给这两张卡一个形制：选中的那张怎么亮（赭石 tint + 左边竖条是这套语言里「选中」的写法），未选的那张怎么安静，第一张展开后的目标分类 chips（带分类色点）怎么排。

**A2. 「保留文件夹」那一条不是安全选项，它有代价。** 文案已经写着「分类会退化成『未声明』，标签变成文件夹名『id』，也不能再在里面新建条目」。这句话要被读到，但不能画成警告——它是一个合法的选择。

**A3. 三种降级要有样子。** ① 空分类：没有出口可选，整张卡收成一句「这个分类是空的。移除它只是从项目里去掉这个筛选。」+ 确认键。② orphan 分类（有条目、但没有能力包声明它）：没有声明可摘，「保留」对它等于什么都不做，所以只剩「搬走」一条，眉题换成「清空分类」、确认键换成「搬走并清空」。③ 没有别的分类可搬：第一张卡禁用，注「没有别的分类可搬——先新建一个」。

**A4. 「不可逆」怎么画，不用红。** 这套语言里没有红。确认键现已照 `05f Word 排版格式（二）` 屏 1l 的删除确认做成**深中性填色**（墨色底 + 纸色字）——有分量、不诱导，赭石留给「这是你要的那个」。请核一下这个形制在两张出口卡下方是否成立，并决定那枚 ⚠ 图标留不留。

### B · 移到分类（1 屏 + 状态）

**B1. 影响面先于动作。** 头部那行「当前：人物 3 · 地点 1」是这块板子的第一句话：作者在决定之前先看见这一批从哪来。已在目标分类里的条目会被跳过、不计入——所以列表里每行的尾注「2 条已在」/「全部已在」（整行禁用）不是装饰，是「报一个不含水的数字」。

**B2. 点一下就搬，没有「应用」。** 和旁边的归集清单（`03b` 屏 27/28：三态勾选、攒一串再应用）刻意不同——选一个分类不用攒。两块板子并排出现在同一条动作条上，请让它们**一眼分得开**：单选替换 vs 多选累加，靠形制不靠颜色。

**B3. 常驻脚注。** 「分类是磁盘上的文件夹，这一批会连文件夹一起搬走；写成 [[lore:分类/id]] 的引用会改指新位置。」归集清单没有这一行，因为归集不搬文件。它该长什么样：脚注、还是头部那句的第二行？

**B4. 位置。** 它从多选动作条第一颗按钮向上弹出（`03b` 屏 26 那条动作条：分类在集合两颗之前）。请画出它与动作条的关系，以及 orphan 分类**不出现在目标列表里**（往降级态里搬东西是在手工制造更多降级态）。

### C · 词典标准化（3 态 + 入口）

**C1. 分工要在稿面上被看见。** 「AI 只搬运词对，格式由代码渲染，不改任何译名」今天是页脚一句小字。它是这个模态和别的 AI 模态的本质区别（别的是「生成」，这个是「搬运」），值得一个更靠前的位置——但不要变成横幅。

**C2. 结果态是一张词表，不是一段文本？** 今天结果是一块可编辑的 textarea（原样 `原文->译文 #备注`）。阅读模式（`03c 阅读模式 · 知识库同步` 屏 1e）已经给了词表一个三栏形制（原文 mono / 译文正体 / 备注 italic）。请决定：结果态是否按那张词表**预览**，编辑再切回原文？约束只有一条——**应用前必须可编辑**，作者要能改掉模型搬错的那一行。

**C3. 「N 条逐字找不到」是唯一的警示。** 启发式防改写：原文或译文在原正文里逐字找不到的条数以黄字报出（今天复用了错误样式）。它挡不住所有幻觉，但把「模型顺手改了译名」从不可见变成一行字。请给它一个不等于「出错了」的样子——它是「请核对这几行」，最好能把那几行**在结果里点出来**，而不只是报一个数。

**C4. 三态与既有词汇。** 输入态：「当前正文 · 可解析 N 条」的原文块 + 页脚「整理为词典格式」；生成中：`03a` 屏 17 的状态行 + 三步（读取词典正文 → 提取词对 · 原样搬运 → 交给你核对后写回条目）+ 思考过程；结果态：见 C2/C3，页脚 重新生成 / 应用（结果里没有可解析词对时禁用）。页脚左侧是 ModelPicker（`03a` 屏 10 的下拉位）。

**C5. 入口。** 条目 AI 中心（`03a` 屏 13）今天是 2×2 四格：更新条目 / 优化元数据 / 生成配图 / 拆分整理。勾了「翻译词典」的条目**多出第五格**「词典标准化」——请画出五格时的排法（第三行一格？还是别的），以及它只对词典条目出现这件事要不要在格子上写明。

## 交付什么

一个 `.dc.html`，屏号 1a 起，浅 / 深两套，带设计说明侧栏：

- **1f** 词典标准化 · 结果态：46 条里 2 条逐字找不到；C2 的词表预览若采用，请给预览 / 原文两种。

```
targets[]                      可以搬去的分类：非 orphan、且不是它自己（可以为空）
orphan                         true = 有条目但没有能力包声明它
choice                         "move" + target | "keep"（空分类只有 keep；orphan 只有 move）
busy / error                   执行中 / 失败一行
```
移到分类：
```
entities[]                     多选中的条目；每条有 category
from[]                         按 category 分组的计数：「人物 3 · 地点 1」
rows[]                         全部非 orphan 分类：{ id, label, color, here }（here = 这一批里已在该分类的条数）
```
词典标准化：
```
entity                         名称 / 头像（只有首字占位）/ dict: true
body                           index.md 正文原文；parsedNow = 今天能解析出几条
phase                          input | generating | result
steps[3] / elapsedSec / model / reasoning     运行进度（同 03a 屏 17）
draft                          结果文本（一行一条 原文->译文 #备注），可编辑；parsedDraft = 其中可解析几条
unverified                     原文或译文在 body 里逐字找不到的条数（≥ 0）
error                          一行
```
**没有**的东西：条目预览图、分类的条目缩略列表、词对的置信度、逐条的「来自原文第几行」（只有整体计数）、撤销。

## 沿用 `03a` / `03b` 的方言，以及这一轮容易踩的几条

- 分类用**颜色**（六色 `--lore-cat-*` + 自定义），集合用**装订**——三个面里出现的只有分类，所以只有色点，**一根装订线都不要**；`3px double` 是取材围栏的专用记号，这里一次都不许用。
- 全局零圆角（圆只留给状态点 / 单选标记 / 头像）；唯一强调色赭石；选中用赭石 tint，悬停用中性底。
- **危险不用红**（A4）；「N 条逐字找不到」也不是错误，是「请核对」（C3）——两处都要找到不靠红的写法。
- 计数 / id / 文件夹名 / `原文->译文` 一律 mono；文案照今天的 i18n 键（本文上半部分表格里引了原句），不要新造术语——是「分类」「条目」「知识库」，不是「标签」「词条」「设定集」。
- 生成中的进度词汇不重画，直接引 `03a` 屏 17；设定模态的外壳（头 / 正文 / 页脚 + ModelPicker）直接引 `03a` 屏 09。
- 不做：批量删除多个分类、删除时预览每一条条目、词典的逐条对照编辑器、撤销搬家、给 orphan 分类「重新声明」的入口（那是能力包的事，在设置 → 工作台）。
