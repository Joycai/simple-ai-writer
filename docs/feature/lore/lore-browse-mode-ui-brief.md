# 知识库条目 · 阅读模式 —— 给 Claude Design 的任务书

> 状态：`planned`。本文档两段：**现状与数据层**（写这份任务书时的代码实况，供实现时回查）· `---` 之后是**发给设计师的任务书原文**，自包含，不需要它读代码库。

## 为什么要有这个模式

条目详情页（屏 15 的三栏 `主条目 320px | 特征 flex | 配图 300px`）是一张**管理台**：
它回答「这条会怎么注入、由哪些文件构成、去哪里改」。但作者点开一张卡片，更多时候
只是想**把这条读一遍**——回顾一个人物的全部设定、给新读者（合作者、自己三个月后）
一页看完。三栏台面对这个诉求是失败的：

- 主条目正文挤在 320px 窄栏里，长文的行长只有 20 字上下；
- 特征只显示元数据行（标题 · 模式 · 触发词 · 字数），**正文要逐条点开弹窗**——
  一个有八条特征的人物，读完一遍要开关八次 640px 表单；
- 配图在 300px 右栏里排成单列小卡，描述被截断；
- 三栏各自滚动，没有一个「从头读到尾」的动线。

所以加一个**阅读模式**：单栏、书页版式、主条目 + 特征正文 + 配图一次排开，
注入语义退成边注。三栏管理台原样保留，两个模式互相切换。

## 数据层（阅读模式要展示的每一样东西都已存在）

`LoreEntity`（[`lib/lore/model.ts`](../../../src/lib/lore/model.ts)）：

| 数据 | 字段 | 阅读模式里的角色 |
|---|---|---|
| 名称 / 别名 | `name` / `aliases` | 档案头；**别名 + 名称一起就是这条的激活标签**（命中任一即注入）——阅读模式把这层语义写明，管理台从来没说清过 |
| 概要 | `summary` | 题头导语（命中即注入，挂常驻记号） |
| 分类 / 类型 | `category` + profile schema | 六色记号 + `类型 novel/人物` 行 |
| 集合 | `collections` | 装订语汇（卡片的 22px 装订边放大到书页左沿） |
| 头像 | `avatarPath` | 档案头方形头像，分类色底 |
| 词典标记 | `dict` | 词典条目的正文是 `原文->译文 #备注` 行——阅读模式渲染成双栏词表 |
| 主条目正文 | `index.md` body | 正文主体（详情页本来就读进来了） |
| 特征 | `facets[]`（title/slot/keys/group/priority/mode/charCount） | 每条一节：标题 + 边注元数据 + **完整正文** |
| 特征正文 | 磁盘 `*.md`（懒加载） | **唯一要新读的数据**：进入阅读模式时按 `mdFiles` 批量 `readFile`，frontmatter 剥掉只留 body |
| 配图 | `images[]`（file/desc/slot） | 图库节，`desc` 做 caption，`slot` 分组 |
| 引用 | `refs` | 「引用」节，经 `citations.ts` 解析成可点链接 |

分组逻辑全部现成：`facetSections`/`imageSections`（slot 分段）、`buildFacetBlocks`
（互斥组盒）、`slotCoverage`（缺口）。阅读模式**复用同一套分组，只换渲染**。

## 实现注意（设计稿回来之前就能定的）

- **模式是偏好，不是路由**：`app:loreDetailMode`（`read | manage`）进 `PREF_KEYS`
  （绝不 `localStorage`），全局记住上次用的模式；墙右键「编辑」仍直达管理台 + 表单。
- **特征正文懒加载**：只在进入阅读模式时读，读失败的那条显示占位行（同
  `contentLoadFailed` 的既有处理），不阻塞其余节。
- **渲染走 `MarkdownPreview`**，容器挂 `md-body` + 阅读模式自己的 `--md-size`
  （任务书里请设计师定，倾向 16px——比详情页 15 大一档、比编辑器预览 17 小一档）。
- **lightbox 复用**：阅读模式的图片点击接现有 `previewIndex` 机制，不做第二个。
- **导航历史**：模式切换不进 `navStore`（同一条目的两种看法，不是两个位置）。
- **性能**：特征正文是若干独立 `MarkdownPreview`，不拼成一个大字符串——拼接会让
  一节的语法错误（未闭合代码块）吃掉后面所有节。

## 设计回来之后要能回答的三个问题

1. 一个 8 特征 + 12 图的人物条目，从头滚到尾**是不是一篇连贯的文章**——中途有没有
   任何一处需要点击才能继续读；
2. 注入语义（常驻/自动/手动、触发词、互斥组）在阅读版式里**退到了哪里**——还找得到、
   但不打断行文，这两头都要占住；
3. 想改某一节时，从阅读模式到「正在编辑这一节」要几步。

# 知识库条目 · 阅读模式 —— 设计任务书

请在既有 claude.ai/design 项目（**`03 设定集 Lore`** 一族）里**新增屏**，延续屏
14（卡片墙）/ 15（详情三栏）/ 16（特征编辑）的语汇。那三屏一律不动——这一期是给
条目详情**加一个并列的阅读模式**，不是重画管理台。

## 0. 这是什么应用

桌面写作应用（Tauri + React），面向小说 / 跑团 / 文案 / 周报作者。**知识库**存放
作者的设定条目（人物、地点、组织…），写作时按名称/别名命中自动注入 AI 上下文。
视觉语言是**「手稿」**：深浅两套主题，衬线正文，**单一赭石强调色**（`--color-accent`
浅 #A0522D / 深 #D9925B），**全局零圆角**（圆只留给状态点、spinner），层级靠背景
深度 + 1px 细线。知识库自己的方言是**索引卡**：网格纸墙（`--lore-wall-bg` +
36px 网格线）、微旋转硬阴影卡片、分类六色（`--lore-cat-*`）、集合用**装订**语汇
（卡片左沿 22px 装订边 + 竖排 mono 短名，中性色阶 `--lore-bind-*`，**绝不用颜色**
——颜色已经归分类）。

一个条目在磁盘上是三样东西，UI 语汇也照此三分：**主条目**（概要 + 正文）、若干
**特征**（可独立注入的切片——一套服装、一段往事；各带注入方式）、**配图**（图 +
一句话描述）。

## 1. 现在这块长什么样

点开一张卡片进入详情页。顶部一条 crumbBar：`← 返回 · 知识库 / ●人物 / 沈青梧 ·
id: shen-qingwu · [编辑] [⋯] · ‹上一条 下一条›`。下面是三栏：

```
┌ 主条目 320px ─┬ 特征 flex ────────────┬ 配图 300px ┐
│ 头像+名+别名  │ ◇ 外貌段基线 ───── ＋ │ [图]       │
│ 概要(命中即注)│  常驻|奔袭装 · 214字   │  desc…     │
│ 正文(挤在320) │  自动|冬装 · 触发词…   │ [图]       │
│ …滚动…       │ ┌互斥组·虚线盒┐        │  desc…     │
│ mono 文件树   │ …每条点开弹窗才见正文… │ …单列滚…   │
└──────────────┴───────────────────────┴────────────┘
```

三栏各自滚。**注入语义写在每一行上**（这套记号阅读模式要沿用）：常驻 = 3px
`--color-sienna` 左边、自动 = `--color-border-strong` 描边徽标、手动 = 灰描边徽标
+ 降透明；**互斥组是虚线盒子**（同组只注入一条），组内按优先级降序、行尾
`优先级 N · 字数` mono。特征若有类型 schema 则按**面**分段（段基线 =
`名字 · mono 计数 · 细线 · ＋`）。

它作为管理台是称职的。作为**读物**是失败的：正文行长 20 字、特征正文要逐条开
640px 弹窗（8 特征 = 开关八次）、配图描述被 300px 截断、没有从头到尾的动线。

## 2. 这一期要加的东西

给详情页加一个**阅读模式**，与三栏管理台并列切换：

1. **单栏书页版式**——主条目正文、每条特征的**完整正文**、配图，一次排开从头读到尾；
2. 档案头集中呈现：头像、名称、**激活标签**（名称 + 别名，命中任一即把这条注入
   AI 上下文——这层语义要第一次被写明白）、分类、集合、类型、概要；
3. 注入语义（常驻/自动/手动、触发词、互斥组、优先级）**退成边注**：读得到、
   不打断行文；
4. 排版跟随作者选的 markdown 主题（应用有 手稿/素雅/杂志/公众号/打字机 五套，
   预览、导出共用——阅读模式就是又一个 `md-body` 面）。

数据全部现成，没有新功能——这一期纯粹是**给同一份数据一个能读的版式**。

## 3. 需要设计的屏 / 态

### 3a · 版式总纲：这一页是什么材质

核心决定：阅读模式是**墙上摊开的一张大纸**，还是**独立的一页文档**？我倾向前者
——网格墙做底，中央一张宽纸（内容量出高度），卡片语汇自然延伸：卡片的 22px
**装订边**放大成纸的左沿（集合竖排短名照旧，未归集空着），分类色作为纸顶的一道
细色带或只留头像底色。请定：

- 纸的宽度与正文**行长**（我倾向正文测量 620–680px，纸面再各留呼吸边距）；
- 正文字号（现行详情 15px、编辑器预览 17px——阅读模式落在哪一档）；
- 纸与墙的关系：贴墙滚动？纸自己滚？硬阴影用卡片的 `--lore-card-shadow-lg`
  还是更大的一档。

### 3b · 档案头与激活标签

头部一次讲清「这是谁 + 什么时候会被 AI 读到」：

- 方形头像（分类色底，无头像时的字符占位沿用墙卡）、大号衬线名称；
- **激活标签行**：名称 + 全部别名做成一排 chips，配一句 mono 注记（类似
  `命中任一 → 注入`）。这行是这一期唯一的**语义新增**——别名从来只被当成
  「又名」，其实它们就是激活关键词。chips 的形制请与既有 chip 分级（描边中性 /
  虚线缺席）区分开：这些是**会触发注入的词**，值得一个自己的样子；
- 元数据行：`●分类 · 类型 novel/人物 · 集合×2 · N 特征 · M 配图 · 总字数`
  ——哪些进这行、哪些沉底部落款，请取舍；
- **概要**：命中即注入的那句话，作为题头导语排出来（导语级字号/斜体衬线），
  挂**常驻记号**（3px sienna 左边——它和正文一样「会进上下文」，记号要一致）。

### 3c · 特征的阅读呈现（这张屏的核心难题）

每条特征 = 一节：**节标题（特征名）+ 边注元数据 + 完整正文**。要解的题：

1. **边注放哪**：模式徽标、触发词、互斥组、优先级、字数——全塞标题行会变回
   管理台，全藏起来则违背「注入语义恒可见」。可选：标题行下一条 mono 细行；
   宽屏时推到右页边空白做真边注；hover 才完整显形。请选并说明；
2. **常驻/自动/手动在整节上的记号**：管理台是 3px 左边/描边徽标/降透明。阅读
   版式里一节可能一屏长，3px 左边随节高延伸是否还成立？手动特征（要作者点名
   才注入）在读者眼里和常驻正文**内容上并无贵贱**——降透明会惩罚阅读，请给出
   不降可读性的记号；
3. **互斥组**：虚线盒装着两三节完整正文会很重。怎么在阅读版式里说清
   「以下几节，AI 每次只读其一」——组头一条说明线？骑缝式的组边？请设计；
4. **面（slot）分段**：有类型 schema 时特征按面分组（外貌/性情/往事…）。阅读
   模式里面名是**章节标题**的好素材——但缺口（`+ 补上这一面`）在读物里是否
   还出现？我倾向阅读模式**只读不催**：缺口一行都不画（管理台已经画了）；
5. **空正文/读取失败**的特征：一行占位，不断文。

### 3d · 配图

- 图库作为一节（2–3 列网格？瀑布？），`desc` 做 caption，按配图组（slot）分段；
- 点击进既有 lightbox（左右翻页 + 描述），不用重画；
- 无描述的图在读物里显示什么（管理台是「无描述—点击添加」的催办文案——阅读
  模式同 3c-4，不催）；
- 要不要让**首图/人设图**升进档案头（头像旁的大图）？请给意见——数据上
  `imageSlots` 分组是现成的，但「哪张是主图」没有字段，若需要请说明交互上
  怎么指定（我们可以加）。

### 3e · 阅读 ↔ 管理的切换，与「读到一半想改」

- crumbBar 里的模式切换件：两态 segmented（`阅读 | 管理`）？单个图标扭转？
  位置（面包屑侧还是动作侧）？应用记住上次用的模式，墙上点开卡片进上次的模式；
  右键「编辑」永远直达管理台；
- **阅读中的编辑动线**：hover 一节 → 页边浮出一枚轻编辑记号 → 直接开那条特征
  的编辑弹窗（改完回到阅读模式原位）。主条目正文、概要、配图描述同理。请设计
  这枚记号的形制与显隐（键盘焦点也要能到它——纯 hover 显形是焦点陷阱）；
- 前后条目导航（‹ ›）在阅读模式里是否升级——读完一条顺势读下一条，页底要不要
  一条「下一条：xxx」的过渡行。

### 3f · 长文导航

8 特征 + 12 图的条目在阅读模式是很长的一页：

- 宽屏（纸外还有余量）时给**页边目录**：概要/主条目/各面/配图的锚点列，随滚
  高亮当前节。窄屏收掉。请定宽度阈值与形制（mono 竖列？细线刻度？）；
- 有没有必要做「折叠某一节」——我倾向不做（折叠是管理台的事，读物就该摊平），
  如果你认为长节需要，请说明判据。

### 3g · 特殊条目

- **词典条目**（`dict` 标记）：正文是逐行的 `原文->译文 #备注`。阅读模式渲染成
  **双栏词表**（原文 mono、译文正体、备注 faint），比原样 markdown 好读得多。
  请给这张变体屏；
- **降级条目**（分类所属能力包被停用）：管理台顶部有一条降级说明。阅读模式
  正文照读，说明还出不出现、以什么姿态；
- **空条目**（刚建、只有名字和概要）：这一页长什么样——不要用空态卡片填满，
  一句邀请即可。

### 3h · 两种宽度

编辑区宽度随窗口与侧栏变化。请给：纸 + 页边目录都放得下的宽态、只放纸的常态，
以及纸被压到最小（约 560px 内容区）时先牺牲什么（页边目录 → 边注收进行内 →
图库降列数）。

## 4. 必须遵守的约束

- **零圆角**；唯一强调色赭石；hover 中性底、选中才赭石 tint；
- 分类用颜色（六色 `--lore-cat-*`）、**集合用装订**（中性 `--lore-bind-*`）——
  两根轴绝不互借语汇；`3px double` 线是取材围栏的专用记号，这里一次都不要用；
- 索引卡的**硬偏移阴影**（`--lore-card-shadow*`）是纸感不是海拔——不要换成模糊阴影；
- 正文排版跟随应用的 markdown 主题（你只定容器、测量、字号档，五套主题的字体
  细节不用你管）；注记/计数/字数/id 一律 mono——与全应用同规；
- 颜色一律标 token 名，新颜色要说明映射到哪个既有角色并给浅深两套；
- 动效 120–320ms + Apple 缓动，`prefers-reduced-motion` 退化；阅读↔管理切换
  可以有一个方向感（应用里墙↔详情已是 push 过渡），但不要翻书特效；
- 图标全部 lucide。

## 5. 一个词的问题，请一并定掉

这个模式叫什么。候选：**阅读**（我倾向——「浏览」和墙的浏览混淆，「预览」在
编辑器里已另有所指）· 展卷 · 通读。请定中英两套：模式名、切换件的两个标签、
（若有）页边目录标题、词典变体的栏头（原文/译文/备注）。另外「激活标签」这个
说法本身也请校——数据上它就是「名称 + 别名」，界面上叫 激活标签 / 触发词 /
命中词 哪个，不要和特征的「触发词」（keys）撞车——两者机制不同（条目命中看
名称别名；特征触发词是命中之后的二级开关）。

## 6. 交付
