# 设计任务:为一款桌面写作应用重整「同步与备份」设置页,并给「知识库」加上同步在场感与快速推拉

## 产品背景

这是一款给小说 / 文案 / 跑团模组作者用的桌面写作应用(Tauri + React,Mac 和 Windows)。左边文件树、中间 Markdown 编辑器、右边 AI 面板。作者在应用里维护一个「**知识库**」——人物、世界观、势力、道具这些**条目**,每个条目是一张带头像和多段特征的卡片,全部条目铺成一面「墙」。

作者可以自建一台**备份服务器**(自己的 NAS / VPS),然后:

- 把**应用配置**(AI 供应商、模型、提示词、偏好)备份上去,换机器恢复——这件事**不需要打开任何项目**;
- 把某个项目的**知识库**绑定到服务器上一个有名字的库,之后**推送**(本地覆盖远端)或**拉取**(远端覆盖本地)。同步是单向镜像,没有合并——所以**每次推 / 拉都必须先经过一个预览**,作者逐条看到会发生什么、哪些条目有风险,才能确认执行。这是产品的第一铁律,界面绝不能提供任何绕过预览的「一键同步」。

服务器地址和 token 是**装机级**的(整台机器一份,多个项目共用);绑定关系是**项目级**的(每个项目各自绑一个库)。

最近刚加了两个能力,这次设计要把它们放进合适的位置:

- **谁比较新**:应用能给出五档判定——`一致` / `本地较新(N 处没推)` / `服务器较新(N 处没拉)` / `两边都有改动(本地 L 处 · 服务器 R 处,有风险)` / `还没同步过(无法判断)`。
- **最近同步记录**:服务器为每个库存最近 20 次同步——方向(推 / 拉)、服务端时间、来自哪台机器、新增 / 覆盖 / 删除的条数。任何一台机器都能看到**所有**机器的记录。

## 现状与痛点(为什么要重设计)

### A. 设置 → 同步与备份(内容区最大宽 960px,行式布局)

现在从上到下是:**服务器**(地址 + token + 连接按钮,或已连接的一行)→ **应用配置**(本地导出导入 + 服务器备份档)→ 未绑定时:**远程知识库**列表(单选 + 绑定按钮)→ 已绑定时:**当前绑定**(本地项目卡 ↔ 服务器库卡,加「谁比较新」一行)→ **同步**(推送行、拉取行、拉取前自动备份、解绑)→ **最近同步记录** → 绑定但断线时:页面**最底部**再出一个「服务器」区放重连按钮。

痛点,按作者实际抱怨的顺序:

1. **两个「连接」。** 绑定的项目断线时,页顶的连接表单和页底的重连区同时存在——同一个动作,两个入口,一头一尾。作者不知道该点哪个,也不知道两者有没有区别(没有)。
2. **三种作用域混在一页,没有视觉分层。** 服务器(装机级)、应用配置备份(装机级)、知识库同步(项目级)从上到下排成一样的行,作者分不清「这个按钮影响整台机器还是只影响当前项目」。
3. **日常动作埋得太深。** 写作中想推一把,要 打开设置 → 点到同步与备份 → 滚到中段找推送按钮。设置页适合放"配置一次"的东西,不适合放"每天用"的东西。
4. **状态零散。** 连接状态、绑定状态、谁比较新、上次同步时间、历史记录,各自一行散在页面各处,没有一个"一眼看懂现在什么状况"的锚点。

### B. 知识库墙

墙本身经过几轮迭代,能力已经很多。**这次不要求重画墙的卡片和已有语汇**(它们有严格的既定设计,见下面视觉规范),但头部工具带需要梳理,并且要新增"同步在场感"。现有能力清单,供你理解拥挤程度:

- 顶带:搜索(⌘K)、按**分类**筛选的 chips(六色,3px 左边色带)、新建分类、新建条目(手写 / AI 生成两个入口)、置顶、导入 / 导出、重新扫描、打开文件夹、更多菜单;
- 第二根轴「**集合**」:左侧装订栏(按集合筛选、管理集合)、卡片左沿 22px 装订边、批量归集;
- 「**取材范围**」围栏:限定 AI 自动取材只看某些集合——围栏外的卡片**翻面**(灰底虚线,只剩名字),顶部出一条 `3px double` 骑缝带。**围栏 ≠ 筛选**,筛选让卡片消失,围栏让卡片翻面,这条分界是既定设计,不许动;
- 卡片点开是条目详情:特征分段、配图、别名、AI 中心(改写 / 拆分 / 配图生成 / 词典整理…)。

痛点:

1. **没有任何同步在场感。** 项目绑没绑服务器、现在谁比较新、上次谁同步过——在墙上完全看不见。想推拉必须离开墙去设置页。
2. **头部工具带信息密度已经到顶**,再直接塞两个按钮进去只会更糟。需要设计一个**分层**:高频(搜索、筛选、新建)常驻,低频(导入导出、重扫、打开文件夹)收纳,同步作为一个**新的、有状态的**成员放进来。

## 这次要解决的三件事

1. **重整设置 → 同步与备份的信息架构**:装机级与项目级要一眼可分;「连接」只有一个入口;状态有一个锚点。
2. **给知识库墙一个同步在场感**:绑定后,墙上能看到连接状态 + 谁比较新 + 一步直达的推 / 拉入口。
3. **快速推拉的形态**:点推 / 拉之后打开的是**已有的预览模态**(不用重画),所以这两个按钮的本质是"带着方向打开预览"。设计要传达"这不是立刻执行"——作者应该敢点。

## 业务硬约束(不是视觉偏好,是产品规则)

- **没有预览就没有同步。** 任何入口、任何状态下都不存在"直接执行"的推 / 拉。快速按钮 = 打开预览。
- **推 = 本地覆盖远端,拉 = 远端覆盖本地**,方向语义必须在每个入口处无歧义(现有设置页用"以本地为准 / 以远端为准"的副标,和一条双头箭头连接两张卡,这个心智模型可以沿用)。
- **「两边都有改动」是唯一需要警示色调的判定**——但它是"需要作者裁决",不是"出错了"。其余四档都是中性陈述。
- **服务器地址 + token 装机级,绑定项目级,应用配置备份装机级**(没打开项目也要能恢复配置——刚装好的新机器正是最需要它的时刻)。
- **围栏、装订、分类色**这些墙上的既定语汇一律不动;`3px double` 双线是"AI 视野变了"的专属记号,同步的任何状态都**不许**借用它。
- 术语固定:知识库 / 条目 / 分类 / 集合 / 取材范围 / 推送 / 拉取 / 备份。不要发明新词(例如不要出现"云端""上传""同步中心")。
- **不在本次范围**:同步预览模态内部、条目详情内部、应用配置备份的两个模态(恢复 / 导入)。可以给它们留接口(按钮、入口),不要重画。

## 视觉规范(硬约束,必须遵守)

这个应用有严格的既定视觉语言,新设计必须无缝融入:

- **风格**:克制的、现代的、Apple 式的。整体气质是"手稿"——像裁切的纸,不像圆角卡片。
- **圆角:全局为 0。** 所有容器、按钮、输入框都是直角。唯一允许的圆形是状态圆点、加载指示器、单选标记、以及头像。开关是方形的。
- **强调色:只有一个** —— 赭石色 sienna(浅色模式 `#A0522D`,深色模式 `#D9925B`)。禁止在交互元素上用多色渐变。需要区分状态时用中性灰阶 + 这一个强调色的深浅。警示另有一个琥珀 / 红的语义色,但用得极省。
- **层次靠阴影,不靠边框。** 有一套四级阴影(sm/md/lg/xl),取能读出来的最小那一级。
- **字体**:正文用衬线(手稿感),UI 标签用无衬线,数字 / 代码 / 机器名 / hash 用等宽。中文正文默认宋体系。
- **动效**:120–320ms,Apple 缓动曲线,"几乎察觉不到但很顺"。不要弹跳、不要大位移。
- **深浅双主题**:两套都要出,不是深色改个背景色了事。
- **选中 vs 悬停要分开**:选中用强调色淡染,悬停用中性灰。把悬停也染成强调色会让人以为选中了。
- 设置页是全窗口界面,左侧一列导航,右侧内容区**最大宽 960px**,由"区块标题 + 行"组成;已有的行 / 区块 / 卡片 / chip 词汇尽量沿用,可以引入新的区块形态(比如状态锚点卡),但要和行式布局共存。

## 需要设计的界面

### 1. 设置 → 同步与备份(重整,最重要)

对信息架构的期望(你可以给出更好的方案,但要回答这些问题):

- **一个状态锚点**:页面顶部(或某个固定位置)一眼回答——连没连上哪台服务器、当前项目绑没绑、谁比较新、上次同步是什么时候谁做的。四件事一处说清,而不是散在四个区块里。
- **「连接」只出现一次**。断线重连、改地址、换 token,都收敛到同一个地方。想清楚"已连接"时这个区域退化成什么样(现在是一行地址 + 断开按钮)。
- **装机级 / 项目级的分界要被看见**。可以是分组、可以是标注、可以是视觉上的两个地带——但作者必须能回答"我现在动的这个东西,换个项目还在吗"。没打开项目时,项目级地带如何表达("先打开一个项目"目前是一行灰字)。
- **绑定流程**(已连接、未绑定时):服务器上的库列成单选列表(每行:库名 · N 条 · 最后更新时间 · 来自哪台机器),可以新建一个库,选中后绑定。这个流程保留,但请把它放进新架构里合适的位置。
- **谁比较新 + 最近同步记录**:判定五档(见产品背景)+ 每条记录"推送 / 拉取 · 时间 · 来自哪台机器 · 新增 N · 覆盖 N · 删除 N"。记录里**别的机器**的行值得有一点可辨识度(这正是这个功能的意义:看见室友的台式机昨晚推过)。
- **推送 / 拉取按钮**在这一页仍然保留(设置页是完整功能的家,墙上是快捷方式)。

### 2. 知识库墙:同步在场感 + 快速推拉

- 绑定后,墙的头部区域出现一个**同步状态件**:连接状态、谁比较新、以及推 / 拉两个动作。未绑定的项目**完全不出现**(不要放"去绑定"的常驻广告;最多在更多菜单里留一项)。
- 五档判定在这里要**压缩到极小**——墙的主角是卡片,这个状态件是页边注,不是横幅。想想一枚小的状态点 + 一句话 + 两个动作能不能承载;悬停或点开可以展开更多(上次同步、最近几条记录)。
- 「两边都有改动」时,这个状态件是作者**最需要**它的时刻——它要能引起注意,但仍不许用 `3px double`、不许像报错。
- 断线时它如何表达(点击重连?灰掉?),同步进行中如何表达(预览确认后有一个逐条执行的进度)。
- 推 / 拉点击后打开既有预览模态——按钮本身如何暗示"会先给你看预览"(文案?图标?),避免作者因为怕误触发而不敢用。
- 顺手给头部工具带一个**分层建议**:高频常驻 / 低频收纳 / 同步状态件放哪一侧。不要求重画每个控件,给出布局和层级即可。

### 3. (小)侧栏知识库面板的同步状态

编辑器左侧的侧栏也有一个精简的知识库列表。绑定后是否值得一枚最小化的状态点(仅指示,点击跳墙或设置)?给一个建议即可,一张小图。

## 状态清单(每个态都要有画面)

设置页:

1. 冷启动:没有服务器地址,没有项目
2. 填写中 / 连接中 / 连接失败(错误一行)
3. 已连接,没打开项目
4. 已连接,项目未绑定(库列表:有库 / 空列表 / 新建中)
5. 已连接,已绑定:五档判定各一(至少画 `一致`、`服务器较新`、`两边都有改动` 三张),含同步记录列表(有记录 / 空)
6. 已绑定,断线(重连入口——只有一个)
7. 解绑确认

墙上的同步状态件:

1. 未绑定(= 不存在)
2. 已绑定 · 一致
3. 已绑定 · 本地较新 / 服务器较新(其一)
4. 已绑定 · 两边都有改动
5. 已绑定 · 断线
6. 同步执行中(预览确认之后)

## 禁止事项

- 任何形式的"立即同步 / 一键同步"。
- 圆角、多色渐变、第二个强调色、彩色图表。
- 借用 `3px double` 双线、借用集合的装订语汇、借用分类六色来表达同步状态。
- 把"未绑定"渲染成缺陷(空状态不是错误,和墙上"未归集不写字"同一条哲学)。
- 新造术语。
