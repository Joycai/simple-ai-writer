# 知识库服务端管理后台（`/admin`）

`server/` 那个二进制原来是纯命令行的：配 token 要改环境变量再重启，想知道谁在写
只能 `journalctl` 翻日志，删一个库、清一次 `tmp/`、做一次备份都要 ssh 上去。
这份文档记录**为什么后台长成现在这样**，以及哪些地方和设计稿不一样、为什么。

- 界面本身：设计稿 `07 服务端管理后台 KB Admin`（claude.ai/design，12 屏）
- 服务端是什么、API 长什么样：[`../server/README.md`](../../../server/README.md)
- 怎么部署运维：[`../server/DEPLOY.md`](../../../server/DEPLOY.md)
- 这个服务端为什么是这个形态：[`remote-knowledge-base-feasibility.md`](remote-knowledge-base-feasibility.md) §13–§18

## 1. 配置：从「只有环境变量」到「文件为主，环境变量覆盖」

原来的 `config.rs` 顶上写着一句自信的注释：*"every deployment style it is likely
to meet already speaks environment variables"*。那对 systemd 和 docker 成立，
对真正需要这个后台的人不成立——在自己机器上双击运行的 Windows 用户，设六个环境变量
是一趟对话框旅行，而且忘了就没了，重启一次机器就得重来。

所以现在的优先级是 **内置默认值 < 配置文件 < 环境变量**。环境变量一个都没删，
因为容器化部署里它仍然是最顺手的临时覆盖手段。

### 1.1 每个值都记得自己从哪来

`Config` 带一张 `sources: BTreeMap<String, Source>`，每一项标 `default` / `file` / `env`。
这不是装饰：**配置页必须能解释「你在文件里看到的值不是服务器正在跑的值」**。
一个默默显示文件内容、而进程跑在环境变量覆盖上的配置页，比没有配置页更糟——
它会让人反复修改一个不生效的地方，并且怀疑是自己写错了。

被环境变量覆盖的行在后台里是**锁着的**，并写明是哪个变量覆盖了它。写接口也会
拒绝这种键（`env_override` / 409）：写进去会成功、文件会显示新值、服务器会继续
跑旧值——「静默什么都没发生」是配置页唯一绝不能产生的结果。

### 1.2 找不到配置文件时生成一份，而不是拒绝启动

第一次启动时如果没有配置文件，服务端会生成一份带随机 token 和随机后台密码的文件，
并把两者打印到 **stdout**（不是 `tracing`——它不能被日志级别过滤掉，也不该躺在
一份没人盯着的 journal 里）。

这**仍然是 fail-closed**：服务端从不在没有凭据的情况下起来。变的只是凭据由谁生成。
原来的行为（打印「请先配置 token」然后 `exit(1)`）在一台没有开着终端的机器上是死路，
而那正是这个东西最常见的部署形态。

### 1.3 写回配置用 `toml_edit`，不是重新序列化

一个配置文件的注释是它的**理由**所在——为什么 bind 是 `0.0.0.0`，为什么上限被调大过。
把结构体序列化盖回去会删光它们，而一个保存一次就吃掉注释的后台，没有人会再手工
编辑那个文件第二次。

`confedit.rs` 有一个不显眼但关键的细节：改一个**已经存在**的键时，用
`get_mut` + 替换 `Item::Value`，而不是 `Table::insert`。TOML 里键上方的注释存在
该键的 decor 里，`insert` 会连 decor 一起替换掉——于是唯一一次改动 `max_entry_mb`
的保存，恰好删掉了那条解释「为什么调大它」的注释。这个 bug 在实现时真的出现过，
第一版单元测试没抓到（它改的那一项恰好没有注释），现在测试里那一项**上方和行尾
都带着注释**。

## 2. 两套鉴权，故意不合并

|  | 谁在用 | 凭据 | 范围 |
|---|---|---|---|
| 同步 API | 桌面 app | bearer token（`[[tokens]]`） | `/v1/*` |
| 管理后台 | 操作者本人（浏览器） | 用户名 + 密码（`[admin]`） | `/admin` |

同步 token 不能登录后台，后台的会话 cookie 不能调 `/v1`。合并的诱惑很大（少一套
凭据、少一个登录页），但那意味着**每一台装了 app 的笔记本都握着一个能删光服务器
的凭据**——而 app 的 token 是按「能读写知识库」发的，不是按「能删库」发的。

三个由此而来的决定：

- **失败限速只在后台**。32 字节的随机 token 在 HTTP 上猜不出来，所以 `/v1` 不需要；
  一个人选的密码可以，所以后台连续 5 次失败锁 5 分钟。锁定期间**正确的密码也拒绝**，
  否则这把锁只挡得住一直猜错的人。
- **用户名和密码永远一起比对，且都用常数时间**。先比用户名、错了就返回，等于告诉
  对方「这个用户名存在」——而那正是攻击者缺的另一半。
- **会话只在内存里**。重启即全部失效，这是对的：一次重启通常正意味着配置
  （可能就是密码）刚刚被改过。

### 2.1 `allow_anonymous` 是唯一的例外

它同时关掉两边的鉴权。给一栋没有墙的房子锁一扇门没有意义：同步 API 已经对所有人
敞开，后台再要密码只是表演。

但后台**不会直接进去**：它先渲染一张红色警告卡（设计稿 07-1b），要点一下
「仍然进入」才进。第一版实现里这张卡其实是够不到的——匿名模式下 `whoami` 直接
返回「已认证」，页面跳过了登录屏。而这张卡存在的全部意义就是**别让这个状态被
默默跳过**，所以现在客户端保留一个 `anonymousAck` 标志，服务端说什么都要先点一次。

## 3. token 明文，而列表默认只显前缀

设计稿 07-6 写的是「服务端只存 token 的 hash，全文只显示一次」。实现里没有这么做，
是一个明确的取舍：

- token **必须**能和客户端递过来的值逐字节比对，所以它在配置文件里本来就是明文；
  真要哈希，那也只是给 token 哈希，密码仍然要能被手工设置。
- 而如果密码要哈希，想手工设密码的人就得先跑一个子命令去算哈希——**又把这个功能
  想消灭的命令行请了回来**。

所以两者都是明文，保护它们的是**文件权限**（新建时 `chmod 600`，健康自检会检查这一条），
不是加密。这是「本地/内网服务器」这个部署形态下的正确权衡，如果哪天它要面向公网
多租户，这一条是第一个要重新考虑的。

列表默认只显示前缀、点一下才展开全文——不是因为服务端不知道，而是**为了让这一页
可以被截图**。新建时仍然有一次性全文展示，因为那一刻的动作是「复制到另一台设备」。

## 4. 活动日志：唯一一份「算不出来的」记录

`store.rs` 里有一条贯穿全文件的原则：**没有索引，manifest 靠遍历现算**，因为索引是
真相的第二份副本，它引入的失效模式客户端看不见。同样的论证会直接否掉一份日志。

日志还是留下来了，只有一个理由：**别的东西都答不出「为什么」**。文件系统知道一个
条目现在的 hash；只有日志知道它不是你以为的样子，是因为 11:52 另一台机器推了一次、
你拿到了 412。那是操作者真正会问的问题，而在这之前唯一的答案是 `journalctl`。

它被**放在真相通路之外**，所以那份论证不适用：

- 没有任何同步判断读它，`manifest()` 从不看它，删掉 `audit.log` 只损失历史；
- 它在 `<data>/audit.log`，不在任何一个知识库目录里——同步协议不知道有这个文件；
- 写失败一律吞掉：这个服务器的职责是存知识库，丢掉「解释 412 的能力」不是拒绝
  上传的理由。

一个具体的判断分歧被保留了下来：**总览的「24h 写入」只数落地的写**（201/204），
**而图表数的是尝试**（含 412）。它们是两个不同的问题——「今天存进去了多少」和
「今天这台服务器上发生过什么」——所以故意是两个数。

## 5. 前端：三个文件，没有构建步骤

`admin/index.html` + `app.css` + `app.js`，`include_str!` 进二进制。没有 npm、没有
打包器、没有会和源码对不上的 `dist/`，`cargo build` 就是全部构建。

一个服务端半边只有五个依赖的仓库，为了一个管理页引入整套前端工具链是划不来的；
几千行 vanilla JS 也确实装得进一个文件。代价是没有类型检查和组件框架，所以：

**所有来自服务端的名字都用文本节点渲染，永远不拼 HTML。** 知识库名、条目路径、
设备名（`X-Source-Device`）全都是客户端上传的字符串，服务端明确声明过它不解析、
不清洗它们。后台是它们唯一一次被显示的地方，`el()` 因此只接受字符串和节点。
一次 `innerHTML` 的疏忽，等于把 XSS 交给任何一个能推送条目的人。

`el('div#id.a.b', …)` 里的 `#id` 是在 `el()` 内部拆开的，不能直接进 `createElement`——
`createElement('div#offline-banner')` 在浏览器里是 `InvalidCharacterError`。这个 bug
在验证时抓到过（见 §7）。

### 5.1 动效：动的六处，和不动的七处

这个后台的动效词汇很小，也应该很小——一个在排查问题的运维者，每多一帧都是延迟。
原来缺的不是"更多动效"，是**对称**（浮层只有进场没有退场，来路和去路对不上）和
**状态到达时的信号**（几处状态变化是硬切）。全站一共只有六处动，其余**明确不动**
（下面列了）。

补对称：

- **模态与抽屉**（`.backdrop` / `.drawer-wrap`）原来的 `close()` 是裸的 `.remove()`——
  滑进来，然后眨眼没了。现在加 `.closing`，动画放完再摘。
- **toast** 原来从右边滑进来，却用一段内联 `opacity` 原地淡掉。现在沿同一条轴出去。
- **窄屏侧栏的遮罩**（`.nav-scrim`）原来是同步 `remove()` 的，而侧栏要滑 240ms——
  于是侧栏最后那 240ms 是悬在一张亮着的页面上滑走的。现在两者同为 240ms。

补状态信号：

- **配置页的保存栏**原来从 `display:none` 硬切出现。它是整页从"在看"切到"有未保存
  改动"的**唯一**信号，而它出现在视口底缘、操作者视线之外（视线在刚编辑的那一行上）——
  硬切等于没信号。现在 240ms 上滑。
- **断线横幅**原来硬切进页面顶部。现在 200ms 下滑，让它读成"一条告警到达了"。
- **健康自检**的「重新检查」原来 `clear()` 之后塞回一条 40px 骨架——一屏高的面板
  塌下去再弹回来，把下面所有东西推上去又推下来，而新一版通常和旧的一模一样。
  现在就地变暗（`opacity .45` + `pointer-events: none`），骨架屏只留给真正空手的
  那一次（首次加载、上一次自检报错）。

六个不显眼但都踩过的点：

1. **退场用独立的 `-out` 关键帧，不给进场那三条加 `reverse`。** 动画名不变时，浏览器
   把它当成"同一个已经跑完的动画改了参数"，可能直接落到终点——于是浮层还是"啪"地
   消失，而 CSS 看上去完全正确。
2. **一对遮罩/面板的退场时长必须相等**（模态 160/160，抽屉 200/200）。`dismiss()` 听的是
   第一个冒泡上来的 `animationend`，不相等就会被短的那条提前掐掉。
3. **`dismiss()` 不用写死的 `setTimeout` 对齐 CSS 时长。** `app.css` 末尾那条
   `prefers-reduced-motion` 覆盖把全站动画压到 `.01ms`，固定等待会让一个已经看不见的
   节点又挡上几百毫秒；反过来，标签页在后台时动画根本不跑，`animationend` 一个都不会来。
   所以是"听事件 + 留兜底"两条腿。验证时正好撞上后一种：浏览器面板的标签页
   `visibilityState === 'hidden'`，两个事件都没来，节点是被兜底摘掉的。
4. **保存栏用 `@starting-style` 而不是 JS。** className 从 `hidden` 换成 `save-bar` 就是一次
   `display:none → flex`，正是它的触发条件；而之后每敲一个键 `drawSaveBar()` 都会重设
   同一个 className，`display` 没变，动画不会跟着重播（实测第二、三次改动产生 0 个过渡）。
   起始样式的层叠是独立的，`@starting-style` 必须写在规则**之后**。不支持的浏览器退化成硬切。
5. **断线横幅反过来，不能用 `@starting-style`。** 它对一个**初次渲染就可见**的元素同样
   生效，而 `shell()` 在 `S.offline` 为真时创建的横幅正是这种——于是断线期间每点一次
   导航（shell 整个重建）都重播一遍。所以改成由 `setOffline()` 挂一个 `.arriving` 类：
   动画标记的是"断线这件事刚发生"，不是"横幅在这里"。分界线是**节点是不是每次出现
   都新建**：遮罩每次打开都是新的、保存栏每次渲染都从 `hidden` 起步，都适用
   `@starting-style`；横幅不是。
6. **断线横幅没有退场，是故意的。** 服务器回来时 `startReconnect()` 紧接着 `route()`，
   整个 shell 连同横幅一起被重建——给一个马上要被销毁的节点做退场没有意义。
   另外横幅占流内空间，下方内容仍会一次性下移它的高度；消掉那次位移要动 `height`，
   不划算，所以只做"到达"这一半。

**故意没有动的地方**（每一条都是频率或功能的理由，不是没想到）：

| 位置 | 为什么不动 |
|---|---|
| 骨架屏 → 页面内容的整页淡入 | `route()` 是通用刷新路径——导航、每个「刷新」按钮、活动日志的每次筛选、断线后每 5 秒重连，都会清空整个 `#root`。加淡入等于每换一次下拉筛选整页闪一下 |
| 知识库列表的入场 stagger | `draw()` 绑在搜索框的 `input` 上，每敲一个字符全表重建，stagger 会逐字符重播 |
| `.row` / `.table .tr` 的悬停过渡 | 扫一张表就是几十次悬停，加过渡会在快速划过时拖出一串亮着的行 |
| `.dot.live` 的呼吸脉冲 | 运维台上一颗永不停歇的点是噪声，而它已经有一圈静态 `box-shadow` 表达 live |
| 磁盘占用条从 0 生长 | 动的是 `width`（布局属性），而且每次刷新都会重播 |
| token 前缀展开成全文 | 这一刻的动作是读它并复制到另一台机器，宽度动画只会推迟这件事 |
| 批量选择条的显隐 | 和保存栏是同一种硬切，但它的问题不是动效：`.strip` 不是 sticky，被 append 在一张可能有 200+ 行的表**后面**，勾第一个复选框时那条栏出现在屏幕外。先把它钉住再谈动效 |

## 6. 和设计稿不一样的地方

| 设计稿 | 实现 | 为什么 |
|---|---|---|
| 07-1 登录页有「服务器地址」输入框，可指向另一台实例 | 去掉了 | 后台由它管理的那台服务器自己伺服，会话 cookie 是同源的。填另一台地址不可能工作，留着只会误导 |
| 07-1「记住此浏览器」勾选 | 去掉了 | 会话时长由 `admin.session_hours` 决定，一个不改变任何行为的勾选框是假的开关 |
| 07-6「服务端只存 token 的 hash」 | 明文，可展开查看 | 见 §3 |
| 07-9 运行配置**只读**、列的是环境变量 | 可编辑，列的是配置文件项 + 来源徽标 | 设计稿画于配置改成文件之前（TURN 1）；可编辑是后来定的方向 |
| 07-1b 匿名模式可「仍然进入」 | 保留，但**必须**点一次才进 | 见 §2.1 |
| 07-3 新建弹窗预览 `kb-<拼音/哈希>` | `kb-<名称摘要前 6 位>`（不做拼音） | 拼音要一张表；摘要同样能把三个中文名字区分开，而这正是原来 `kb`/`kb-2`/`kb-3` 做不到的 |
| 07-7 每一条失败都带一段说明 | 只有 412 永远带；其他失败**连续相同的只显示一次** | 一串被同一个失效 token 打出来的 401 会刷出五块一模一样的琥珀色横条，把真正不一样的那行淹掉 |
| 07-8「备份期间写入会被短暂阻塞（读锁）」 | 不加锁，文案改成说明为什么不用加 | 每个条目都靠 rename 提交，归档里不可能有半个文件。为一次几分钟的 tar 阻塞全部同步是更差的交易 |

**没有做的**：会话列表 / 强制注销其他会话（设计稿没有这一屏；改密码时会自动踢掉
其他会话）、首次运行的安装码引导（`[admin]` 缺失时后台直接是关闭状态，并在登录页
和日志里说清楚怎么加——比一个只在首启出现一次的向导更难错过）。

由此产生的一个连带改动：`ids::slug_for_kb_name` 对无 ASCII 的名字从返回 `kb`
（靠调用方补 `-2`、`-3`）改成返回 `kb-<摘要>`。`kb-2` 和 `kb-3` 在 URL、备份清单
和 shell 里互相分不清，而那三个地方正是 id 存在的意义。

## 7. 验证时抓到的三个 bug

后台没有类型检查也没有测试框架，所以它是在**真浏览器和真服务端**上验证的：
happy-dom 把 `app.js` 跑在真实 DOM 上、fetch 打到真的 `aiw-kb-server`；
再用 Chrome DevTools 协议设真视口截图。三个 bug 只有这样才会露出来：

1. **`app.js` 的第一段根本没写进文件。** 写入那一步是 `cd server && cat > …`，
   而当时 cwd 已经在 `server` 里，`cd` 失败让 `&&` 短路。文件语法完全合法
   （`node --check` 通过），但 `el()` / `api()` / `ICON` 全都不存在，页面停在
   「正在连接服务器…」。**教训:能解析 ≠ 能运行。**
2. **`el('div#offline-banner.offline')`** —— `createElement('div#offline-banner')`
   在 happy-dom 里被容忍，在 Chrome 里抛 `InvalidCharacterError`，会炸掉整个外壳。
   宽松的测试替身会藏起严格环境里的错误。
3. **`toml_edit` 的 `insert` 吃掉注释**（见 §1.3）。

另外两个是幻觉，值得记下来免得下次再追：headless Chrome 的 `--window-size` 在这台
机器上不生效（它按更宽的视口渲染再把 PNG 裁到目标宽度，看起来就像窄屏溢出——
用 CDP 的 `Emulation.setDeviceMetricsOverride` 量，`scrollWidth` 和视口一样宽）；
happy-dom 会**自己再执行一遍**页面里的 `<script src>`，那一份没有 cookie，
渲染出的登录页盖掉了 eval 的那一份。
