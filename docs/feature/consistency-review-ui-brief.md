# 22 一致性检查 · 设计任务

在本项目里新建 `22 一致性检查 Consistency.dc.html`。画布、token、字体角色、墨色方言全部沿用
`02 AI 面板`——这是 02 里那个抽屉的第三个 tab（生成 / 对话 / **一致性检查** / 扮演）的重做。

## 0. 这一轮是什么

「一致性检查」把当前文档对着知识库读一遍：人物用错了惯用手、地名换了写法、上一章死了的人又
出现、周报里的数字和上周对不上。它今天已经存在，但停在半年前：点一个按钮、等一次、出一列卡片。
**02 里没有它的屏**——现在的样子是代码里长出来的，可以推翻。

它现在要搬到和对话助手（02 屏 2a）同一套引擎上。新流程：

1. 作者**选范围**——拿知识库的哪一部分当尺子：全部 / 某几个集合 / 某几条条目（可到特征）。
2. 作者**（可选）写一句重点**——「只看角色外貌」「只核对数字和日期」。空着就是全面核对。
3. 点开始。应用把文档按模型能装的量**切成 N 段**（大多数时候 N = 1），每段起一个 AI 运行：
   它自己决定翻哪些条目、回头搜前面哪几章、要不要派长文 / 联网子代理；每查实一条矛盾就
   **当场记录一条**，查过没问题的也记一条「通过」。
4. 记录**即时**变成卡片出现在面板上——不等结束。
5. 结束后是一份报告：冲突 / 提醒 / 已通过，每张卡有「跳到原文」「应用建议」「忽略」「更新
   条目」四个按钮。

**四条必须吃透：**

1. **它只读不写。** 「应用建议」是作者在卡上点的一次确定性替换，「更新条目」只是跳转过去。
   核对是量尺子，不是改尺子。
2. **一条发现 = 一段逐字引文。** 没有引文的发现不存在——它必须能被跳到、被替换。
3. **「没查」和「没问题」必须长得不一样。** 模型一条都没记、文档太长后半没查、某一段失败、
   作者中途停了——这四种都不是绿勾。绿勾只给真的核对过的。这是整个界面最容易撒谎的地方。
4. **N = 1 是常态**，切段只在文档一次装不下时发生。「段」这个概念不能在常态下占地方。

## 1. 已定的决定（照此画，不要重开）

- **范围三档**：全部（跟随 `03 设定集` 屏 25/26 那个「取材范围」围栏）· 集合（多选，可含
  「未归集」）· 条目（多选，可精确到某条的某个特征）。按项目记住上次选的档。
- **重点**是一行自由文本，**不做成预置 chip 菜单**：能力包太多（小说 / 周报 / 模组 / 文案），
  任何一列预置词都会在别的包上全错。placeholder 给两个例子就够。
- **头部一条分配条**，就是 02 生成 tab 那条（10px 凹槽、2px 内衬、图例恒展开），段换成
  系统+工具 · 原文 · 知识库 · 前情 · 余量，**颜色沿用那条的段色，不新增色**（原文用「选区/附加」
  的色，知识库用「条目」的色，前情用「前情」的色）。读数写「本次 3 段 · 并行 3 · 每段 ≤ 9.2k tk」。
  它有实际意义：作者一眼看出文档为什么被切成 3 段，换个档、缩个范围，段数就变。
- **执行日志原样用 02 屏 2a 那套**（轮次手风琴 / 工具行 / 子代理嵌套 / 便签 / 截断徽章），
  N > 1 时每段是一条可展开的工具行。**不要重新发明一套日志。**
- **子代理芯片行**用 02 屏 5a/5b 那一排（联网 / 识图 / 长文 / PDF …，只能关不能开）。这里
  **没有写手**（12 写手那条分隔线不出现——核对不成文）。
- 引文在运行中就被校验过，所以旧版那句「这段原文已找不到」只剩一种成因：作者查完之后自己
  改了那一句。

## 2. 可借的现成件

- **集合档的选择器**：直接借 `03 设定集` 屏 25/26 的取材范围弹层（集合列表 / 条目数 / 按
  分类拆分 / 超过 8 个折起加过滤）。但那边的 **3px double 骑缝线全应用只属于「全局围栏」**，
  这里是一次性的范围——**借弹层，不借骑缝线**。请在稿子上确认你同意，或给出更好的理由。
- **条目档的选择器**：借 02 屏 2b 对话输入框的 `@` 引用选择器（搜条目 / 特征，选中变成一枚
  `@[名称]` 引用芯片）。
- **旧版一致性检查**（无稿，仅供接得上）：顶部 mono 统计行「12 项核对 · 3 冲突 · 2 提醒 ·
  7 一致 · 4.2s」；分类筛选 tab；发现卡 = 3px 左侧色条（冲突红 / 提醒琥珀）+ 严重度小标签 +
  标题 + `分类 · 条目名` + 三行「本文 / 知识库 / 建议」+ 按钮行；底部折叠的「已通过 N 项」；
  页脚「全部忽略 / 应用 N 项建议」。那条 3px 左侧色条是全应用少数被允许的 semantic 左边框，
  可以留，也可以换一种严重度语汇——但不要再往上叠。

## 3. 核心张力

### 张力一（最重要）：设置区的重量

三档范围 + 它的选择器 + 一行重点 + 芯片行 + 分配条 + 开始按钮。**第一次跑之前，这就是整个
面板**，它该像一张准备好的表格。**跑完之后，它必须退成一行**（「范围：小说A ＋1 · 重点：外貌
· 3 段」），把整个面板让给报告——但「改一下范围再跑一遍」是最常见的下一步，那一行必须一点
就展开回来。

请给出：跑前 / 跑中 / 跑后三个态里设置区各占多少，以及它折叠和展开的样子。

### 张力二：「没查」和「没问题」

四种非绿勾的态各自要有面孔，而且不能靠一条红色横幅：

| 态 | 事实 | 作者该读出的话 |
|---|---|---|
| 空 | 模型一条都没记（它没调用记录工具） | 「这次没查成，不是没问题」→ 换个会调工具的模型 |
| 截断 | 文档超过 12 段的上限，后 x 字没查 | 「后面这一截没看」 |
| 失败段 | 第 k 段网络 / 上限出错 | 「这段没查」+ 只重跑这一段 |
| 中止 | 作者按了停止，已记的发现保留 | 「查到第 k/N 段」+ 半份报告仍然可用 |

统计行「12 项核对 · 3 冲突 · 2 提醒 · 7 一致」在这四种态下分别该怎么写？

### 张力三：边查边出

运行中，面板上同时有：段条（N > 1 时）、执行日志（在长）、发现卡（在增加）。三样都在动。

- 谁在上谁在下？作者最想看的是发现，但日志是「它现在在干什么」的唯一证据。
- 日志运行时缩到多小？折成一行时那一行写什么（「第 2 段 · 第 4 轮 · 正在读〈林辰〉」？）
- 结束那一刻的过渡：日志折起、统计行出现、发现流「变成」报告——这是一个动作还是三个？
- 停止按钮在哪？02 屏 2d 的停止是输入框右侧那个赭石方块——这里没有输入框。

### 张力四：段条和日志的工具行是同一件事的两个视图

N > 1 时，「第 k 段：等待 / 核对中 / 完成（3 条）/ 失败」这个信息，日志里每段那条工具行也有。
单独画一个段条会不会是重复？如果段条只在运行时存在、结束后消失，它的价值够不够？给出你的
判断——**可以决定不画段条**，只要日志的工具行承担得起「一眼看出第 3 段失败了」。

## 4. 本轮容易踩的规范（其余照 02 既有方言）

- **不新增颜色。** 严重度用既有的三个语义色；范围三档、段的状态、子代理，全部用灰阶 + 赭石
  阶梯 + 虚线 / 实线。
- **等宽给每一个数字**：段号、token 数、秒数、条数、文件路径，无一例外。衬线只给「给人读的
  话」：引文、条目名、总评。
- **一个容器最多一圈边框**；内部分组用发丝线 + 10px 大写字距节头（标签 + 发丝线撑满 + 右对齐
  mono 数字）。
- **术语纪律**：界面上只说 文档 / 知识库 / 条目 / 特征 / 集合 / 分类。**不要出现「章」「设定」
  「词条」**——这个应用不只写小说。
- 深浅两版，深色是主参考。

## 5. 需要画的

### 5.1 跑前：设置区

一张准备好的表格。从上到下（顺序可以改）：

- **范围**：三档分段控件（全部 / 集合 / 条目）。选「集合」出现集合选择器，选「条目」出现
  `@` 引用芯片行 + 一个「＋ 添加」。「全部」时要有一句小字说明它跟随的围栏当前立在哪
  （「跟随取材范围：小说A」），否则作者会以为「全部」真的是全部。
- **重点**：一行输入，placeholder「例如：只核对角色外貌 · 文中的数字与日期」。从 `21 全局搜索`
  的「核对一致性 · 关于 “xx”」进来时它是预填好的——预填态请画。
- **子代理芯片行**。
- **分配条** + 读数。模型没声明上下文大小时的退化态：条不画，一句静态说明。
- **开始按钮**。

两个小态：范围里有失效项（集合被删了 / 条目被移走了）→ 「2 条失效」怎么标、怎么剔；当前
没有打开任何文档 → 整个 tab 的空态。

### 5.2 跑中

按张力三、张力四给出布局。请画两版：**N = 1**（一个运行，日志里能看到它翻条目、搜前文、
派了一次长文子代理）和 **N = 4**（并行 3，一段完成、两段在跑、一段等待，其中一段稍后失败）。
发现卡在两版里都已经出现了两三张。

### 5.3 跑后：报告

- 设置区折成的那一行。
- 统计行 + 分类筛选 + 发现列表 + 折叠的「已通过」+ 页脚。可以沿用旧版骨架，也可以重排，但
  每一项信息都要在。
- **总评**：模型收尾时写的一两句话（N > 1 时是每段一句的列表）。它是这份报告里唯一一段
  「模型对着你说的话」，放哪、用什么字体？
- 报告头上的「范围 · 重点」一句——它和「已通过」是同一个目的：让作者知道这次查到了哪。

### 5.4 发现卡

内容不变：严重度（冲突 / 提醒）· 标题 · 分类 · 条目名 · 本文引文 · 知识库怎么说 · 建议替换
（可无）· 四个按钮（应用建议 / 忽略 · 这是有意为之 / 更新条目 / 跳到原文）。

- **引文是衬线**（它是作者自己的句子），「知识库怎么说」是不是？「建议」是不是？三行的字体
  角色要分得清「引的」和「说的」。
- 三张卡叠在一起时严重度怎么一眼分开——3px 左侧色条是旧答案，可以留，可以换。
- 「已忽略」和「已应用」之后卡去哪：消失、淡掉、还是折到底部？作者常常想撤销一次忽略。
- 作者跑完之后自己改了那句 → 「引文已找不到」态。
- 切到别的文档之后报告还在，但按钮全部失效（「这份检查针对的是《xx》」）——只读态。

### 5.5 四种非绿勾 + 一种绿勾

空 / 截断 / 失败段 / 中止，各画一个报告头。再画唯一的绿勾：真的一条问题都没有——它和「空」
态的差别就在「已通过 N 项」那一列有没有内容。

## 7. 不要做的事

- 不要新增颜色，不要加圆角。
- 不要重画执行日志、分配条、芯片行、`@` 选择器、取材范围弹层——它们在 02 / 03 里都是现成的，

## 设计稿回来之后（2026-09-03）

### 它怎么回答四条张力

- **张力一 · 设置区退到哪**：不在结束时折，在**点开始的那一刻**折成一行——「范围 《漕运纪》＋1 ·
  重点 外貌 · 3 段」，跑中锁住（右端灰字「运行中 · 不可改」，无箭头），跑后同一行右端换成
  「改范围重跑 ▾」。折叠只发生一次，结束那一刻不再有任何布局跳动。点那一行，表格原地展开
  压在报告上方，报告下移不消失，开始按钮变「重新核对」。折叠行里只放三样：范围 · 重点 · 段数
  ——都是「换一个就得重跑」的量；子代理和模型不进那一行。
- **张力四 · 段条不画**：N > 1 时日志表头写「2/4 段核对中 · 1 完成 · 1 等待」，每段是 02 屏 2a
  的一条工具行（勾 / 闪点 / 虚线圈 / 赭石实方块 四种行首记号）；失败行右端自带「重跑这一段」。
  结束后段的事实搬进报告头的**覆盖条**：一条细带，实心＝核对过、斜纹＝没查、方块＝失败——
  这就是「没查」和「没问题」长得不一样的那张脸。
- **张力三 · 边查边出**：设置行（锁）→ 执行日志（默认只有表头一行，点开出尾部）→ 发现节头
  （活计数「已记 3 项 · 1 冲突 · 1 提醒 · 1 通过 · 00:14」）→ 发现流。停止 ■ 住底栏：跑中底栏
  是「正在核对 · 00:14」＋ ■，结束后同一条底栏原地变成「全部忽略 / 应用 N 项建议」。结束是
  一个动作：活计数定格成统计行、总评在它下方出现、表头的闪点变成勾，卡片不动。
- **张力二 · 五张报告头**：统计行永远只数「真核对过的」，不足的部分写在同一行末尾并用斜纹
  覆盖条画出来。空态不是一张空报告，是一段话：「这次没查成，不是没问题」。绿勾唯一的凭据
  是「已通过 N 项」那一列有名字。
- **借件**：集合档借 03 屏 26 的弹层，**不借** 3px double 骑缝线（同意任务书的理由）。
- **卡的三行字体角色**：本文＝衬线亮色＋引文底色；知识库＝衬线灰色，条目名略亮；建议＝无衬线，
  只有替换的字词回到衬线。严重度靠三样叠加：3px 左侧色条 · 首词颜色 · 引文底色，不再加图标。
- **已忽略 / 已应用**折成一行落到列表底部，撤销就在行里，不要确认弹窗。

### 实现出入

- 「历史检查」头部按钮、空态的「查看那份报告」、「上次核对 3 天前」没做——方案 §10 决定不落盘。
- 条目档的特征不是芯片上的二级展开：选择器直接列出「条目」与「条目 · 特征」两级行，效果相同。
- 日志的段行用的是 `AgentLog` 现成的子运行卡（band ③，标签改为「段」），行首记号沿用它的四态，
  没有另画一套。
- 空态的「换模型重试」实现为「重试」：模型选择器就在抽屉头部，一步之遥。
