| 7 | 「已固定」按固定顺序 | 新固定**追加在末位** | 照 1b 的动效说明（「滑到已固定末位」）：追加在末位，已经在那里的行不会在光标底下移位 |

其余按稿实装：六种行态与 120ms 交叉淡出、200ms 行重排（Motion `layout` + `layoutId`，
`prefers-reduced-motion` 下 0ms）、就地确认条（240ms 展开 / 5s / 160ms 收起，⌘Z 同样撤销）、
三种空状态、三档密度、固定 > 6 条时小节可折叠（折叠态是组件内 state —— 面板一打开项目
就整个消失，持久化没有意义）。

**撤销带来的一条时序**：清空**不再**顺手回收被清项目的 per-project 偏好
（`ai:pinnedLore:<path>` / `lore:scope:<path>` / 开启时间戳）——五秒后的撤销要还回来的是
一整个项目，不是一个名字。回收改在撤销窗口关闭时发生（`collectUnlistedProjectPrefs`，
定时器到点或面板卸载都算），应用在窗口内退出则留给下次的同一次回收。

浏览器实测过的屏：1a 常态（浅/深）· 1b 悬停/固定/取消固定/右键菜单 · 1c 清空 → 确认条 →
撤销 · 1d 三种空状态 · 1e 160 / 240 / 500 三档与 8 条固定的折叠。

## 数据层

固定名单是**自己一行偏好** `app:pinnedProjects`（JSON 数组，机器本地 ——
它装的是绝对路径，到下一台机器上没有意义），语义是**「最近打开」这一列的标记集**，
不是第二份项目列表。纯逻辑全部在 [`lib/recentProjects.ts`](../../src/lib/recentProjects.ts)，
store 只做接线。

| 规则 | 落点 |
|---|---|
| 上限只数**未固定**的条目，固定的白坐 | `capRecentProjects(list, pinned)`；`sanitize`/`parse`/`merge` 都透传 `pinned` |
| 多实例合并要带上固定集 | `mergeRecentProjects(db, ours, pinned)` —— 不带的话，另一个实例开个项目就能把一条固定的挤掉 |
| 固定是**合并写**，取消固定是**覆盖写** | 同 `removeRecentProject` 的老理由：合并会把刚取消的固定原样递回来 |
| 清空只清未固定的 | `clearRecentProjects`：列表按固定过滤；全空才 `deletePref` |
| 清空**不再**顺手扫掉留下来的项目的 per-project 偏好 | 同一处：`prunePrefsWithPrefix` 的谓词从 `() => false` 变成「还固定着就留」。原来它无条件清掉 `ai:pinnedLore:<path>` / `lore:scope:<path>`，那对留下来的条目是丢数据 |
| ✕（从列表移除）连固定一起解 | `removeRecentProject`：留着的话，那一行照样会从固定组里冒出来 |
| 取消固定当场重新收口 | `unpinProject`：条目重回上限管辖，超了就地淘汰，不等下一次打开 |
| 分组是**视图**，不是存储顺序 | `splitProjects(recents, pinned)` —— 固定组按**固定行**渲染（不是从 recents 里滤），所以跨实例竞态把某条挤出 recents 之后，作者仍看得见、仍解得开 |

固定名单**不设上限**：每一条都是作者亲手按的，上限只能表现为「按了没反应」。

+ [`pinnedProjects.test.ts`](../../src/lib/__tests__/pinnedProjects.test.ts)（store 的三条承诺：
清空 / 上限 / ✕）。

除此之外还有两行给界面用的：`app:projectOpenedAt`（上表第 4 条）和 `app:pinHintDone`

# 文件面板 · 「最近打开」加固定（pin）—— 设计任务书

请在既有的 **`01 工作区`** 这一屏上更新，不要另起一套。只改左侧「文件」面板在
**未打开项目时**的那段空状态；文件树、IconRail、TitleBar 一律不动。

## 0. 这是什么应用

桌面写作应用（Tauri + React），面向小说 / 跑团 / 文案 / 周报作者。视觉语言是
**「手稿」**：深色墨底或浅色纸面，衬线正文，**单一赭石色**（`--color-accent`
浅 #A0522D / 深 #D9925B）是唯一强调色，**全局零圆角**（圆形只留给状态点、头像、
spinner），层级靠背景深度 + 1px 细线，不靠描边和阴影堆叠。侧栏是玻璃 chrome
（`--glass-bg-strong` + 模糊）。悬停用**中性底** `--color-bg-hover`，**选中**才用
赭石 tint —— 把悬停也染成赭石会读成一个并不存在的选中态。

## 1. 现在这块长什么样

左侧「文件」面板宽 **240px 默认，可拖 160–500px**。**没有打开项目时**，整个面板
内容是这样一段（打开项目后它被文件树整个替换掉 —— 这份列表**全应用只有这一个
入口**，作者每次启动最先看见的就是它）：

```
┌ 文件面板 240px ───────────────┐
│ 打开一个文件夹以开始写作       │ 14px 正体
│ 系统将自动初始化项目结构       │ 13px 衬线斜体 muted
│                               │
│ [ 打开文件夹 ]                 │ 赭石实心按钮 12px sans
│                               │
│ ───────────────────────────── │ 1px 细线，上留 28px
│ 最近打开            清空       │ 左：10px 全大写字距很开 赭石
│                               │ 右：11px faint，hover 转 error 红
│  我的长篇                      │ 13px sans 正文色
│  D:/writing/我的长篇      ⧉ ✕ │ 10px faint 完整路径，从**头部**省略
│  跑团模组                      │ 两个图标 22×22，**只在行 hover 时显形**
│  D:/ttrpg/模组             ⧉ ✕ │ ⧉=在新窗口打开（中性 hover）
│                               │ ✕=从列表移除（红 hover）
└───────────────────────────────┘
```

行 hover = `--color-bg-base` 底。列表**上限 10 条**，超出淘汰最旧的一条。

## 2. 这一期要加的东西

给条目加**固定（pin）**，等价于收藏。被固定的条目：

1. 点「清空」时**保留**；
2. **不被 10 条上限淘汰**（它不参与那个淘汰队列）；
3. 恒在列表**上方**，不因为很久没打开而下沉。

功能就这三条，剩下的全是设计要拿主意的地方。

## 3. 需要设计的屏 / 态

### 3a · 常态：有固定项 + 有最近项

核心问题是**两组东西怎么分**：一个「已固定」小节 + 一个「最近打开」小节（两个标题
两条线），还是一张列表里固定的排在上面、带一个标记？请给出你选的那个，并在说明里
写清为什么 —— 判据是作者一眼能不能答出「按下清空之后，哪几行还在」。

固定态**必须在静息时可见**（不能只在 hover 时才看得出来），否则上面那个问题答不了。

### 3b · 固定 / 取消固定的交互

难点：这一行现在已经有两个 hover 才显形的图标，240px 宽（最窄 160px）再塞第三个
就挤了，而且路径那行会先被吃掉。可选路子（不限于此）：

- 第三个 hover 图标，重新分配这一行的空间；
- 右键菜单（应用已有共用的 ContextMenu 组件，知识库墙和文件树都在用）；
- 固定后图标**常驻**（因为它此刻是状态而不只是动作），未固定时才 hover 显形。

请给出：hover 态、已固定态、正在按下、以及**取消固定**长什么样。lucide 的
`Pin` / `PinOff` 已在应用里用着，沿用它们。

### 3c ·「清空」语义变了

现在它清掉一切；之后它只清未固定的。要设计：

- 按钮本身的文案/形态是否要变（保留「清空」，还是「清空最近」，或加一行小注）；
- 按下之后作者怎么知道「留了 N 条」—— 应用惯例是**就地展开的确认条**，不弹模态；
- **全部都被固定**时「清空」是什么状态（禁用？隐藏？还是照点但什么都不发生）。

### 3d · 三种空状态

1. 从没打开过任何项目 —— 现在是整段「最近打开」不出现，保持；
2. 只有固定项、没有最近项（清空之后的常见结果）；
3. 有最近项、一条都没固定 —— 要不要给一个「固定常用的项目」的极轻提示？如果给，
   它不能压过「打开文件夹」这个主行动。

### 3e · 两个极端宽度

160px（路径那行基本没法读）和 500px。请说明在窄栏下先牺牲什么（路径？图标？）。

### 3f · 密度与滚动

固定 N 条 + 最近 10 条可能超过一屏。给出：滚动从哪里开始、固定小节是否随滚动
钉住、以及固定项很多（比如 8 条）时列表会不会喧宾夺主。

## 4. 必须遵守的约束

- **零圆角**；唯一强调色赭石；hover 中性、选中赭石 tint。
- 颜色一律标 token 名（`--color-text-faint`、`--color-border-soft`、
  `--color-accent-tint`…），不要给裸十六进制；确实需要新颜色时说明它映射到既有的
  哪个角色，并同时给浅/深两套。
- 动效 120–320ms + Apple 缓动，`prefers-reduced-motion` 下退化。固定/取消固定的
  行重排要有动作，但**不要弹跳**。
- 不弹模态做确认。
- 图标全部来自 lucide。

## 5. 一个词的问题，请一并定掉

应用里 `Pin` 图标已经有一个含义：知识库条目的**「置顶」**＝越过取材围栏强行进
上下文。这里的 pin 是「留在列表里」，是另一件事。请给出这里用哪个词（我倾向
**「固定 / 取消固定 / 已固定」**，把「置顶」留给知识库），并给出中英两套文案：
固定、取消固定、已固定（小节标题或标记）、清空按钮、清空后的那句反馈、以及 3d-3
那个可选提示。
