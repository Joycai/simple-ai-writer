# MCP 服务管理：界面、交互与目录缓存

> **Status: `shipped`.** 2026-10-29。设计已确认，正式实现已完成；真实服务发现、目录恢复和桌面详情已验证。现状以 [mcp-support.md](mcp-support.md) 为准。

## 目标与现状

让作者能直接添加、修改和理解一个 MCP 服务，重启后仍能浏览它的工具。
现有 `McpServers.tsx` 把服务器列表、JSON 输入、操作结果放在实验室的一个区块里；
所有操作共用 busy/status，错误归并为同一句提示。`tools.ts` 仅有按运行 signal
缓存的 Promise；聊天工具浏览另有组件级目录。没有持久目录，也没有编辑入口。

本方案包括表单添加、JSON 批量导入、编辑、详情、工具浏览和持久缓存。
继续支持当前 HTTP 连接范围；stdio、OAuth、工具试运行和逐工具开关不纳入本次。
原因：先完成已有连接的管理闭环，不混入新的连接方式和授权机制。

## 页面结构

设置 → AI 配置新增「MCP 服务」，紧邻「子代理」。导航始终可见；实验室仍持有
唯一的 MCP Beta 总开关，并提供「管理 MCP 服务」跳转。
总开关关闭时仍可查看、编辑配置和离线目录，页面显示「MCP 未启用 · 前往实验室」；
不自动联网，也不向助手暴露服务。显式连接测试可用，说明它仅检查连接与目录。

管理页页头：标题、已启用/总数、次级「导入 JSON」、主按钮「添加服务」。
有多个服务时使用列表—详情布局，左列约 260px，右侧占剩余宽度。
以下数值用于原型评审，正式样式应使用现有或新增的尺寸令牌。

```text

                          │ dashscope.aliyuncs.com/…/EnhancedSearch/mcp
```

名称是列表主信息；域名、工具数和更新时间为次信息。选中状态使用强调色浅底，
hover 使用中性底。失败、停用、从未检查分别显示文字，不能只靠颜色区分。
页面不使用「在线」常亮标签：短期 HTTP 会话不能证明服务持续在线。
重启后显示「上次检查成功」及时间，不能恢复成「当前已连接」。

内容区不足 840px 时改为列表 → 详情的单列导航；详情顶部提供「返回服务列表」。
搜索词、选中服务、滚动位置在来回切换时保留。长 URL 截断展示，可复制完整值。
零服务时只显示说明和两个添加入口，不保留空详情栏或常驻 JSON 大文本框。

## 添加与编辑

「添加服务」打开右侧表单抽屉，窄窗口改为整页。编辑复用相同表单。

| 字段 | 交互 |
| --- | --- |
| 服务名称 | 必填；重复名称在字段下报错，不自动覆盖 |
| 服务地址 | 必填；URL 示例与支持范围就在输入框旁；逐字段校验 |
| 身份验证 | 无 / Bearer Token / 自定义请求头；默认选择 Bearer Token，可切换 |
| Token | 密码输入；明确填写 Token 本身，程序组装一次 Bearer 前缀 |
| 自定义请求头 | 名称和值的行式编辑；添加/移除行；阻止重复名称及保留协议头 |
| 启用此服务 | 默认为开启；总开关关闭时说明保存后仍需前往实验室启用 MCP |

底栏固定「取消」「保存」「保存并检查」。保存不依赖网络成功；保存并检查先完成
持久化，再执行 initialize + initialized + tools/list。检查失败保留已保存配置，
详情中给出重试和编辑入口，不能把保存成功描述为全部失败。
保存期间避免重复提交；取消检查只停止检查，不撤回保存。

编辑已有凭据时显示「已保存」及「替换」「移除」，默认不加载密钥明文。
空白替换框不等于删除；只有明确选择移除才删除。请求头名称可展示，已有值按
保留/替换/移除处理。鉴权方式变更时显示将被替换的请求头名称，避免遗留冲突。
未保存离开有丢弃确认；未改动直接关闭。字段错误保留输入并聚焦首个错误。

名称变更保留服务 id；地址或凭据变更生成新的连接修订号，使旧目录失效。
名称/启停等授权相关变更仍使已有批准失效，但不应丢弃同一连接的工具目录。
因此目录身份与现有授权 revision 分开，不能直接复用当前一个 revision 做所有用途。

JSON 是辅助导入入口。弹窗流程：粘贴 → 解析预览 → 确认导入。
预览逐服务展示名称、域名、鉴权是否存在、校验错误；不展示密钥。
同名服务明确选择「更新已有服务」或改名后新增，不再静默覆盖。
多项写入逐项报告成功/失败；只对失败项重试，成功项不重复新增。
导入完成清空含密钥的输入；不把脱敏占位符当作可直接重新导入的有效凭据。

## 服务详情与工具浏览

顶部常驻启停、编辑连接、检查并刷新；删除移到更多菜单并有确认。
删除成功同时清除目录与相关运行内缓存，沿用先清凭据后删配置的顺序。
停用保留目录、允许浏览与显式检查，但禁止助手发现和执行。

「工具」默认页签：搜索名称/说明、目录数量、更新时间、刷新状态。
工具为可展开列表，展开显示完整说明和参数表：参数名、类型、必填、说明、
默认值/枚举。嵌套对象与复杂 schema 提供折叠层级及「查看原始 JSON Schema」；
不把 oneOf/$ref 等复杂规则简化成有误导性的平面表。
支持复制工具名、复制 Schema；不提供会实际执行远端操作的「测试工具」按钮。
服务描述以纯文本呈现，不执行其中链接、HTML 或指令。

「连接详情」：完整地址（可复制）、HTTP 连接方式、鉴权类型及请求头名称、
服务端名称/版本、协商协议版本、上次尝试时间、上次成功时间、耗时、目录更新时间。
首次未检查的元数据显示「尚未获取」；工具数未知显示「尚未获取」，不是 0。
仅成功取得空数组才显示「服务未提供工具」。

## 持久目录与刷新策略

目录是本机快照，不是连接，也不是调用授权。缓存里不存密钥、调用参数、工具结果
或会话 id。保存工具名、说明、完整 inputSchema，以及服务端元数据、协议版本、
fetchedAt、目录格式版本、连接修订号和规范化定义指纹。

实现使用 appDataDir 下 `config.db` 的独立 `mcp_catalogues` 表，事务替换并限制总量；
相较原方案的 JSON 文件，它复用现有事务桥且不新增文件权限。可重建数据不放
PREF_KEYS，开关等偏好仍通过 `lib/prefs.ts`。目录纳入 appReset 清理，排除配置备份。
单服务磁盘快照上限建议 8 MiB、总量 64 MiB；超限只提供本次内存目录并明确说明
「目录过大，本次未保存到本机」。不把截断 schema 伪装成完整定义；沿用现有网络
响应、工具数和分页上限。损坏/未知格式文件忽略并允许刷新，不影响启动。

| 触发点 | 行为 |
| --- | --- |
| 启动应用 | 读取本地快照；不阻塞启动，不对全部服务发请求 |
| 打开详情、聊天 /mcp 或命令候选 | 立即展示匹配连接的快照；缓存不足 24h 不自动刷新 |
| 可见服务无缓存或超过 24h | MCP 和服务均启用时后台刷新；已有目录保留可浏览 |
| 手动检查并刷新 | 无视缓存时间，执行连接与完整目录检查；不调用工具 |
| 刷新成功 | 全部分页成功后原子替换；显示新增/移除/定义变化数量 |
| 刷新失败/取消 | 保留旧快照与原更新时间；显示失败/取消，不覆盖为零工具 |
| 地址/鉴权变化 | 立即撤下旧目录，显示「连接已更改，需重新获取工具」 |
| 停用再启用 | 保留目录；按新鲜度规则刷新，不继承调用授权 |

24h 是目录浏览的默认刷新阈值，不是有效性保证；第一版不增加用户 TTL 配置。
无缓存首次尝试失败后不因重渲染自动重试；失败冷却 5 分钟，手动刷新可立即重试。
所有界面共享同一目录服务，按 serverId + 连接修订号合并请求，后台并发最多 2。
服务 A 慢不锁住服务 B 的编辑。共享请求的消费者取消只移除自身订阅，最后一个
订阅取消才中止网络；用户显式停止该服务检查可统一停止。删除/改连接增加代次，
旧请求晚到的结果不能写回新配置。页面不显示全局「操作未完成」混淆服务。

助手发现和工具方案准备也复用目录服务：新鲜快照可直接返回；过期目录先尝试刷新，
失败时停止助手发现，旧目录仅供界面浏览，避免把离线快照误述为可调用能力。
实际调用保持 `applyMcpCall` 的在线目录校验：已批准工具消失或定义变更就停止，
更新目录并要求重新准备/批准，不能自动改参数、重试调用或沿用旧的会话授权。
这样重启后浏览和准备可复用缓存，而执行仍校验当前定义。
现有 /mcp 工具浏览、斜杠候选与设置页共用同一快照和订阅更新，避免三套列表不一致。

## 状态、错误和可访问性

连接状态与目录状态分开记录：服务可能检查失败但仍有可用的本地浏览快照。

| 情况 | 界面反馈与下一步 |
| --- | --- |
| 获取中，无快照 | 骨架/进度文字 + 取消；不显示 0 个工具 |
| 获取中，有快照 | 目录保持稳定；顶部「正在更新工具…」 |
| 401/403 | 服务内提示「身份验证失败（HTTP …）」；编辑凭据/重试 |
| 超时/网络失败 | 显示阶段、失败时间和重试；有缓存时标记「正在显示上次目录」 |
| 协议不支持 | 显示收到的版本与支持范围；编辑连接入口 |
| 工具列表格式错误 | 明确失败于获取工具阶段；保留最后成功目录 |
| 钥匙串失败 | 凭据保存/读取失败，配置状态不得伪装成可用；重试入口 |
| 取消 | 「检查已取消」；不作为错误、不删除已有快照 |

错误需结构化为阶段 + 安全错误码 + HTTP 状态等允许字段，再由中英文 locale 映射。
不要直接显示服务端错误正文、请求头或完整堆栈；「复制诊断信息」只复制这些允许字段。
成功反馈放在该服务内，短提示不会承担持久状态。刷新按钮进入可取消状态。

沿用 settings 的主题令牌、无圆角、单强调色、统一焦点环与 reduced-motion。
列表、页签、表单、折叠工具均可键盘操作；抽屉管理焦点并在关闭后返回触发按钮。
刷新结果通过局部 aria-live 通知；不自动跳转选中服务，不用动画移走正在阅读的工具。

## 落地顺序与验收

1. 在本地设计工作台制作假数据原型，覆盖列表、详情、添加/编辑、JSON 预览、失败和缓存态；评审后进入应用实现。
2. 配置 CRUD 与凭据更新语义、结构化错误、目录持久化/订阅服务及迁移兼容。
3. 接入独立设置页，实验室保留入口；聊天目录和助手发现接入共用缓存；保留执行前校验。

验收：不写 JSON 能添加并修改服务；重启且断网仍可查看上次工具说明和 Schema；
失败不清空目录；未知与零工具区分；错误属于具体服务；修改 Token 不泄露或误删
旧凭据；旧地址响应不覆盖新目录；同服务并发访问只发一次目录请求；停用服务
不向助手开放；目录变化不能绕过重新批准；删除服务不会因晚到请求重新出现；
浅/深色、窄窗口和键盘流程均可完成。

### 1.99.36 主题控件修正

身份验证选择器复用 `common/Select`；原生 select 的系统弹出菜单无法由主题令牌覆盖。MCP 的通用按钮规则排除 Select 触发器，避免覆盖其输入框外观、展开态和焦点反馈；字段保持全宽，沿用共享菜单的键盘与 Escape 行为。
