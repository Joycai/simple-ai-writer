# 会话代码开发权限

> 状态：`shipped` — 2026-11-27，用户选定「权限菜单」方案；实现于对话助手，默认关闭。

## 决策与理由

在对话窗口标题行加入「会话权限」菜单。开启代码开发前展示授权范围，确认后按钮显示「权限 · 代码开发」，对话顶部持续显示可关闭的状态带。相比常驻独立开关，菜单减少标题行噪声，也给后续不同授权留下位置；本轮只实现代码开发，不提供数据库授权选项。

授权的是可信项目代码执行，不能依靠 node/python/java 的程序名推断代码是否只读。说明明确指出脚本和安装钩子拥有当前账户的完整权限，可能读写文件、访问网络；当前执行器不是沙箱，不能阻止代码内部的数据库访问或发布行为。

## 生命周期与边界

- 只有桌面环境、命令行 Beta 开启且已打开项目时展示入口；关闭能力后不再自动授权开发命令。
- `LiveChat.codeDevelopment` 仅保存在内存，绑定项目路径。跨消息保留，切换到其他打开的会话互不影响；新建、恢复会话、应用重启、项目重置时清除。模型没有开启入口。
- 开启只影响后续提案，已经显示的审批卡保持等待。关闭影响尚未启动的后续命令；已启动的进程由现有停止按钮、超时和杀组机制处理。
- 作用于 Node/Python/Java 解释器、项目相对路径下的虚拟环境或构建包装器，以及 npm/pnpm/yarn/pip/uv/poetry 的开发子命令、Maven/Gradle/Ant、常见测试与检查工具。
- `codeDevelopment.ts` 复用引号感知解析；允许每段均为开发命令或既有只读命令的串联（至少一段开发命令）。shell、提权、数据库客户端、未识别程序、重定向、后台执行、变量/命令替换、环境前缀仍走现有审批。显式 npm publish / mvn deploy 等不在开发入口内；自定义脚本的内部行为无法据名称限制。
- 这份显式代码信任不等于扩大默认只读白名单。纯只读命令仍经过原有 Rust 自动读取检查；`AUTO_READ_DENIED` 必须逐条审阅，不得被本授权或计数连批兜底。
- `agentStore.requestApproval` 验证项目、cwd、所属会话、surface、run/controller 和能力开关；`proposalApply` 在异步依赖加载完成、进程启动前再次读取授权。期间关闭开关、结束运行或切换项目不会留下待自动执行的命令。
- 不消耗、不扩大原来的 1–5 条计数授权；正文、图片、语音、MCP 等授权保持原规则。运行结果记录 `autoApproved`，不会向模型声称有人逐条审阅。

## 主题与可访问性

`SessionPermissionsMenu` / `SessionPermissionsBand` 是纯展示组件；颜色、背景、边框、字体和阴影全部使用既有主题 token，包括强调色上的 `--color-on-accent`。不添加固定配色、不写主题属性，portal 继承根主题。

浮层宽度与位置受视口约束；确认框复用 `ModalShell`。开关带 switch 语义，确认前聚焦取消，Tab 在确认操作内循环，关闭恢复触发器焦点；切换会话卸载旧确认框，避免把授权落在另一段对话。

## 验收入口

三个探索方案已移除。`pnpm prototypes:dev` 的 `/#session-permissions-live` 只复用正式菜单、确认框、状态带与抽屉标题样式，以虚构会话和独立 i18n 验收六个内置主题、自定义莫兰迪暮色、中文/英文与窄宽视口。无应用 store、IPC、真实命令或项目数据。

自动验证：命令范围、PowerShell/POSIX 解析、项目围栏、跨会话/跨轮次、已有卡保留、执行前撤销和中止、新建/恢复/项目重置。完整前端检查使用 `pnpm test`、`pnpm exec tsc --noEmit`、`pnpm build`。
