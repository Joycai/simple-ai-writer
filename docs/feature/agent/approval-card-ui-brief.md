# 设计任务：在本项目里新建 `02h 审批卡片 Approval Cards.dc.html`

（AI 区当前最高是 `02g 助手输入区 Composer.dc.html`，所以取 `02h`；若已被占用，往后取第一个空位并在回稿里说明。）

## 0. 一句话

作者说：「审批卡片看不到编辑的具体内容。」这一稿要重做**整个审批卡片家族的信息层**：让作者在按下「批准」之前看得见**这一次到底动了哪些字**——改了什么、删掉了什么、新增了什么——而卡片仍然是**一个决定，不是一个阅读器**。

## 1. 这套卡片是什么

一个本地写作应用（桌面端，手稿美学，全局无圆角，纸色/夜色两套主题，中文优先）。AI 助手是一个带工具循环的 agent，它的写操作分两层：

- **L2 手稿类**（改文档、新建文件、删除、导出 PPTX/Word/Excel、格式转换、配图、音频转写）→ **阻塞式审批卡**。工具循环停在这张卡上，批准才继续；拒绝时输入框里的理由原样回传给模型。**这就是本稿的主角。**
- **L1 知识库 / 记忆类**（改条目正文、改元数据、建特征、归集、改名、删条目…）→ **不出卡**，模型一调用就落盘，安全阀只有一份自动备份。授权方式是事前的一张**方案卡**：模型先提一份 N 步的方案，作者批准，之后每一次写入必须能对上方案里的某一步，否则被拒。

卡片出现在三个宿主，宽度差别极大：

| 宿主 | 可用宽度 | 说明 |
|---|---|---|
| AI 抽屉里的对话助手 | 抽屉 `min(1180px, 94vw)`，卡片约 1100 | 主场，`02b 助手多会话 Assistant Sessions` |
| 右侧 AI 栏 AiPanel | **可拖 160–500px，默认 280** | 最窄的地方，`02a` |
| 扮演页 RoleplayChat | 同抽屉 | 借同一个组件 |

同一时刻可能**排着好几张卡**（并行工具调用）。卡片是对话流里的一个块，上面是流式输出的正文，下面是输入区。

## 2. 卡片现在的外框（要保住）

```
┌ 1px 赭石描边，inset 底色，无圆角 ─────────────────────┐
│ 标题(12px 无衬线)  文件名(10px mono)      度量(11px mono 右端) │
├───────────────────────── 发丝线 ──────────────────────┤
│ 模型给的一句理由（11px，可无）                          │
│ ← 按 kind 变化的正文，本稿改的就是这一块 →              │
├───────────────────────────────────────────────────────┤
│ [拒绝理由输入框………] [拒绝] [本次对话都批准] [批准]      │
└───────────────────────────────────────────────────────┘
```

头部的「度量」是这张卡的一个数字，各 kind 自己决定它是什么（改动前后字数、几处、几张表、估价…）。**这三段结构和 footer 不要重做**，除非你的方案证明必须。

## 3. 问题：每种卡现在给了什么，作者看不见什么

### 编辑类（本稿的痛点）

| kind | 卡上现在有什么 | 看不见什么 |
|---|---|---|
| **edit** 改一段 | 新文本全文（绿底 mono）在上；原文折在一个「原文」折叠里；`rewrite_lines` 来的多一行「第 120–164 行」；`find` 重复时多一行「第 2 处 / 共 5 处」或红字「全部 5 处」 | **没有任何逐字或逐行对照**。改了一个标点和重写了整段，在卡上长得一模一样——作者要自己把两块 mono 文本在脑子里对齐。也看不出这段落在文档的哪里（除非来自 `rewrite_lines`）。 |
| **rewrite** 整篇重写 | 渲染后的新正文（markdown，超过 600 字折叠），上面一行「少了 812 字」/「多了 300 字」，少了的时候标红 | **看不见少的是哪 812 字。** 一次「顺一下格式」悄悄吃掉一节，作者手里只有一个数字。这是这套卡今天最大的洞。 |
| **delete** 删文件/文件夹 | 路径一行 + 「可从备份恢复」；头部写「3000 字」或「12 个文件」 | **看不见要删掉的是什么**：没有开头几行，文件夹没有文件清单。 |
| **append** 追加 | 只显示追加的正文（原文按定义没动） | 够用。 |
| **insert** 插入行 | 每处一行：`L120` + 插入的文本 + 它落在哪一行之前（引用了那一行原文） | **够用，而且是已经做对的样板**——请把它当作定位语汇的参考。 |
| **create** 新建 | 渲染后的新正文；空文件/空文件夹有专门的空态句 | 够用。 |
| **move / copy** | 两端路径 + 箭头 | 够用。 |

### 已经做对的那一半（请先读，再动手）

`docx` / `xlsx` / `pptx` / `convert` / `transcribe` / `illustrate` 六张卡都遵循同一条纪律：**把「批准之前唯一看不见的那样东西」提到卡上**。

- **docx**：一条「格式从哪来」的带子（默认格式最安静，模仿文件来的带赭石竖条）+ 一张最终规格表，被改过的行高亮；再加一行内容侧预检「12 块 · 标题 5 · 表格 0」——一份作者以为写了三张表的报告在这里写着「表格 0」。
- **xlsx**：每张工作表一行，右边写「数字 87 · 日期 12 · 公式 3」，`数字 0` 标红——因为打开 Excel 之前唯一看不出来的就是数字有没有被当成数字。
- **pptx**：源→目标、幻灯片张数、以及从源码里查出来的、导出时会丢或走样的写法（按规则折叠成一行一条，附行号）。
- **transcribe**：四行规格（文件 / 估价 / 去处 / 写到），因为这一步**要花钱**，卡必须在付费之前出现。

**新的编辑类卡要达到同一档信息密度。** 这一档的判据是：卡上那几行，是不是「批准之前唯一看不见、批准之后就晚了」的东西。

### 知识库那一半（作者点名的第二个痛点）

方案卡（PlanCard）每一步只有三样东西：

```
新建   角色 / 凯尔     补一条新角色，出场在第 3 章
更新   角色 / 莉安 / 外貌.md   把「金发」改成「银发」，与第 12 章一致
删除   地点 / 旧码头   与「港口」重复
```

也就是：动词 + 条目名（+ 文件名）+ **模型自己写的一句话**。**卡上没有一个字是将要写进文件的内容**——作者批准的是一句承诺，而写入在批准之后立刻发生。

批准之后，真正写进去了什么只出现在执行日志的一行里：工具名 + 条目名，展开也只有**截断到 400 字的原始 JSON 参数**和 600 字的结果字符串。作者要知道「莉安的外貌到底被改成了什么」，今天只能去翻文件本身，或者去 `.ai-writer/backups/` 里找那份备份自己比。

对照组：**同一件事在手动路径里早就有评审 UI**——「AI 改善条目」模态（设计稿 `03a 屏 09/17`）是左右两栏 before/after 对照，880px 宽的模态。agent 侧没有。

## 4. 这一稿要回答的问题（按重要性）

1. **编辑类卡的正文该长什么样**，才能同时满足「一眼看清动了哪些字」和「卡片是一个决定，不是一个阅读器」？请具体到：
   - 改动怎么呈现：逐行 diff？行内逐字 diff？只在改动处开窗口 + 上下几行原文？未改动区域怎么折叠？
   - 规模的上限规矩：40 处改动、6 万字整页重写时这张卡长什么样；什么时候折叠，折叠后那句「还有 N 处没显示」怎么写。
   - **删除侧的可见性是硬要求**：今天「没了的字」在任何一张卡上都不出现，这一稿必须给它一个位置。
2. **位置感**：这段改动落在文档的哪里（行号 / 上下文行 / 第几处共几处 / 在文档的哪个小节）。`insert` 卡已经做对了，其它编辑类卡还没有。
3. **知识库**：批准一次知识库改动时，卡上要能看见**将要写进条目的正文**，以及**它替换掉的正文**。请给至少两个方向并说明取舍：
   - 方向 A：方案卡长出内容——但方案是在动手**之前**提的，那时正文还没生成。请判断这条路是否成立，若成立要付什么代价（模型得先写完再提方案 = 一次白跑的生成）。
   - 方向 B：写入之前多一张轻量的内容卡（把 L1 的一部分降级成 L2）。代价是延迟和卡片数量：一次「整理 20 条」会变成 20 张卡，而**读不动的卡就是橡皮图章**，比没有更糟。
   - 方向 C：写入之后一条「已写入 · 这是改动 · 撤回」的可展开条（备份就在那儿，撤回是现成的）。代价是它不再是审批，是事后追认。
   - 也可以给第四种。请把每个方向摆在这条线上：**不要为了看见内容，把 L1 的低延迟和「一张卡管一整轮整理」这两件对的事毁掉。**
4. **自动批准之后**：作者可以点「本次对话都批准 / 本次任务都批准」，此后卡片不再出现。**那之后「改了什么」必须仍然能在某处读到**——执行日志里的一条可展开行？一条汇总？请一并画。这是最容易被漏掉的一屏，但它恰恰是作者最需要的时候。
5. **窄栏**：160–500px 的右侧 AI 栏里这些卡怎么活。左右两栏对照在 280px 里不成立，请给窄栏形态（同一套语汇的降级，不是第二套设计）。

## 5. 视觉与语汇约束（必须遵守）

- **全局无圆角**。卡片是 1px 赭石描边 + inset 底色的一个整框，**没有**彩色左竖条那种卡片语汇。唯一允许的圆是状态点和转圈。
- **已有的 diff 令牌就用它们**，不要引入第三套颜色：`--color-diff-add-bg` / `--color-diff-add-text`（纸色下是青草绿）、`--color-diff-del-bg` / `--color-diff-del-text`（赭红），知识库侧另有 `--lore-add-bg`。夜色下这两组已各自调过，不要写死颜色。
- **字号语汇**：卡标题 12px 无衬线；文件名 10px mono；头部度量 11px mono（等宽数字）；模型理由 11px 无衬线；diff 面 12px/1.8 **mono**（「审阅中的改动」用等宽，「已完稿的正文」用正文字体——`create` / `rewrite` 的渲染正文走 markdown 排版，这条区分要保住）。
- **措辞**：中文，陈述句，动词打头。不写「确定要…吗？」，不用惊叹号，不用「⚠️」。词表：文档（不是章节）、分组、知识库、条目（不是设定/词条）。英文要有对应，两种语言都不许把按钮压到逐字折行。
- **本项目没有 diff 算法**，字级/行级对照要新写或加依赖。请给每个方向标注它对 diff 粒度的依赖（无 / 行级 / 字级），我们好估成本。
- 卡片可能同时排着好几张，且上方正文还在流式输出——**卡不能高到把对话挤出屏幕**，这是「决定不是阅读器」那条纪律的实际来源。

## 6. 要画的屏

1. `edit` 卡：小改动（改一个词）与大改动（整段替换）两态
2. `rewrite` 卡：含「少了 812 字」的那种情况——这是本稿的样板题
3. `delete` 卡：单文件与文件夹
4. `insert` 卡：现状复核；要改动请说明为什么
5. 知识库：方案卡 + 你给的内容可见方案，至少两个方向各一屏
6. 自动批准打开之后的「事后可读」形态
7. 280px 窄栏下的 `edit` 与 `rewrite`
8. 边界态：折叠 / 展开 / 超长 / 改动为空 / 只改了空白字符
9. 夜色下的 diff 面（加与删两种底色在深色上的成色）

## 7. 回稿希望包含

- 每个方向一段取舍，并**点名你推荐哪个**（我们按 `1c` 这样的编号采纳）。
- 一张 `1z` 规则页：颜色 / 字号 / 折叠阈值 / 上下文行数 / 措辞规则，写成能直接实现的表。
- 明确指出你**没有**改的那几张卡（`docx` / `xlsx` / `pptx` / `transcribe` 等），以及它们和新语汇之间有没有冲突。
