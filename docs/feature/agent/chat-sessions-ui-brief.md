# 设计任务：为一款桌面写作应用的 AI 对话助手设计「多个会话」——起名、并排打开、同时在跑

## 产品背景

这是一款给小说 / 剧本 / 跑团模组作者用的桌面写作应用（Tauri + React，Mac 和 Windows）。
左边文件树，中间 Markdown 编辑器，右边呼出一个很宽的 AI 抽屉。作者在应用里维护一个
「知识库」——人物、世界观、势力、道具这些条目。

AI 抽屉顶部有四个模式 tab：**生成 / 助手 / 一致性 / 扮演**。「助手」是一个对话助手：作者
和它聊，它能读文件、查知识库、联网检索、看图，也能提出修改稿件——每次要写文件时会停
下来，弹一张**确认卡**让作者批准或拒绝；它也会在轮数到上限、上下文要截断、或者拿不准
时停下来问作者。这些卡片一出现，那段对话就停在那里，直到作者回答。

「扮演」模式已经解决过一次「多个同时在跑」：左边一列花名册，一个角色一行，最多 3 个
角色同时在生成，第 4 个排队；切走的角色继续跑，跑完了行上亮一个记号。**这次要给「助手」
做同一件事，但助手不是角色——它没有名字、没有头像、没有人设，一段对话只有作者问的
那些话。**

## 今天的样子

「助手」模式的抽屉头部，从左到右：一个机器人图标、标题「对话助手」+ 底下一行模型选择器、
右侧三个按钮「任务」「历史会话」「新会话」、快捷键提示、关闭。

「历史会话」是一个下拉列表，分「已固定」「最近」两节；每行是**第一句话的截断**（60 字）+
`MM-DD HH:mm` 时间 + 一个图钉。**没有标题，没有改名，没有删除。** 未固定的会话只留最新
5 条，多了自动清掉。

一次只有一段对话是活的。**对话在生成的时候，「历史会话」按钮是灰的**——切不走。

## 这次要做的两件事

### 一、会话有标题，作者能改

作者可以给一段对话起名（「第三章改稿」「查一下时间线」）。没起名的，还是显示第一句话的
截断。起过名的会话**不会被自动清掉**——所以要配一个带确认的删除。

两条数据上的事实，设计要尊重：

- 一段**空的**新会话在作者发第一句话之前还没有存过，但作者完全可能一开新会话就先起名。
  改名对作者来说必须**立即生效**，界面不能暴露「存没存过」。
- 改名**随时可以**，包括这段对话正在生成的时候。

### 二、多段对话可以同时活着、同时在跑

作者可以打开好几段对话，最多 3 段同时在生成，第 4 段排队。切到别的一段，原来那段继续跑；
回来的时候，字已经在那里。后台那段跑完了、出错了、或者**停下来在等作者批准 / 回答**，
都要有信号，而且**这三种不一样急**。

每段对话有自己的：草稿、引用的条目、子代理开关、计划模式、状态记忆、自动批准。
**确认卡只出现在提出它的那段对话里**——绝不能在 A 里看到 B 的卡。

## 这个界面要解决的核心张力

### 张力一（最重要）：一个没有身份的东西，怎么并排放

扮演的花名册好做：每一行是一个**人**，有头像、有名字、有人设，行与行天然不同。助手的
会话没有这些——三段对话并排时，区分它们的只有一句作者的问题（或者作者起的名字）和它
们此刻的状态。

要回答的是：**打开着的会话摆在哪、长什么样**。几个候选，请给出你的答案并说明理由：

- 一条**横向的标签条**，在抽屉头部和对话区之间（像文件夹的索引标签，这个应用的气质
  是手稿）。抽屉宽 1180，装 6–8 条标签不成问题；但标签上要放标题 + 状态 + 关闭，多了
  会挤。
- 一列**竖向的侧栏**，像扮演的花名册。一致，但助手的会话没有头像，一列光秃秃的文字行
  会显得空；而且它从对话区抢走一列宽度。
- **不新开区域**，把「历史会话」下拉升级：打开着的会话在列表最上面一节，带状态。最省
  地方，但作者看不见「还有两段在跑」这件事，除非去点开列表。

请画出你选的那个方案；**同时**画出被否掉方案里最强的一个的草图，说明为什么输给了它。

### 张力二：三种信号，三种急法

后台一段对话可能处在：

| 态 | 急不急 | 作者要做什么 |
|---|---|---|
| 正在生成 | 不急 | 等 |
| 排队（并发满了） | 不急 | 可以等，也可以取消 / 插队 |
| **等作者**（一张确认卡 / 一个问题停在那里） | **急**——它一动不动，直到作者过去 | 过去回答 |
| 跑完了，有新回复 | 一般 | 有空看 |
| 出错了 | 一般偏急 | 过去看原因、重试 |

扮演今天只有「正在生成 = 跳动的实心点」「排队 = 空心环」「未读 = 7px 实心方块」三个记号，
**「等作者」没有记号**——只有一个系统通知。这次必须有，而且它和「跑完了」要能一眼分开。
同时记号不能多到变成仪表盘：作者面前是一段正在读的对话，旁边一条标签。

请给出这五个态的记号系统。约束：**只有一个强调色**（见视觉规范），所以急不急不能靠换色；
可以用实心 / 空心 / 动 / 静 / 形状 / 位置。

### 张力三：「打开」「历史」「固定」「命名」四个词

会话有四个互相独立的属性，都要在界面上说清楚，又不能四个记号堆在一行：

- **打开着**：在标签条上（或你选的那个地方）。关掉标签不删除。
- **历史里**：存过就在。5 条未固定的上限之外的会被清掉——除非固定或命名。
- **固定**：列表里住「已固定」那一节，不被清。
- **命名**：有作者起的名字，不被清；不一定固定。

需要回答：历史列表里要不要多一节「已命名」？还是命名只体现在行文字上（作者的字 vs
第一句话的截断，两种字看起来就该不一样）？「已打开」在列表行上怎么标？点一个已经打开
的会话是聚焦那个标签，不是再开一个——行上要不要提前说明这一点？

### 张力四：改名的入口

改名要在**两个地方**都能做：列表行上，和当前对话的头部（作者读着读着想起名，不该先去
翻列表）。头部今天写的是「对话助手」四个字，底下一行模型选择器。会话有了名字之后，
头部该显示会话名还是产品名？两者都要的话怎么排？

改名弹层要给一个动作留位：「让助手起名」——作者点了，助手根据这段对话起个名，**填进
输入框**让作者改一改再回车，不直接落盘。第一期这个按钮可能不做，但位置要在。

## 视觉规范（硬约束，必须遵守）

这个应用有严格的既定视觉语言，新东西必须无缝融入：

- **风格**：克制的、现代的、Apple 式的。整体气质是"手稿"——像裁切的纸，不像圆角卡片。
- **圆角：全局为 0。** 所有容器、按钮、输入框都是直角。唯一允许的圆形是状态圆点、加载
  指示器、单选标记、以及头像。开关是方形的。
- **强调色：只有一个** —— 赭石色 sienna（浅色模式 `#A0522D`，深色模式 `#D9925B`）。禁止
  在交互元素上用多色渐变。需要区分状态时用中性灰阶 + 这一个强调色的深浅。**特别注意**：
  本功能天然想用第二种颜色标「急」，**不可以**。
- **AI 抽屉是不透明的墨色**，层次靠**背景深浅 + 1px 发丝线**，不靠边框叠边框；一个组件
  最多一圈边框；分节用 10px 大写小标签 + 一根发丝线 + 右对齐的等宽数字。
- **字体**：正文用衬线（手稿感），UI 标签用无衬线 11–13px，**所有数字 / 时间 / 计数 / 模型
  名 / 快捷键用等宽**，没有例外。中文正文默认宋体系。
- **动效**：120–320ms，Apple 缓动曲线，"几乎察觉不到但很顺"。不要弹跳、不要大位移。
  正在生成的点可以脉动（已有 1.4s 的 `pulseDeep`），`prefers-reduced-motion` 下停。
- **深浅双主题**：两套都要出，不是深色改个背景色了事。
- **选中 vs 悬停要分开**：选中用强调色淡染，悬停用中性灰。
- **既有记号，直接沿用**：正在生成 = 5px 实心强调色点、脉动；排队 = 5px 空心环；未读 =
  7px 实心强调色方块；抽屉模式 tab 上「别处有事」= 6px 强调色方块；并发读数 = `并发 ▮▮▯
  2 / 3`（三根 14×4 的小条 + 等宽数字）。新记号要和这些是一家的。
- **芯片语汇**：激活 = 强调色淡底 + 强调色边 + 强调色字；中性 = 灰边 + 柔字；「没有」=
  **虚线**灰边 + 淡字（缺席不是错误，不要删除线）。

## 画布尺寸

- **AI 抽屉**：从右侧滑出，宽 1180px（最大 94vw），高度占满窗口。「助手」是四个模式 tab
  之一。
- 抽屉头部高约 56px；输入框在底部，上方有一行芯片（引用 / 子代理开关 / 计划模式 / 状态
  记忆 / 自动批准）和一条上下文构成条。

## 需要设计的界面

### 1. 打开着的会话摆在哪（张力一的答案）

画抽屉的「助手」模式全貌：头部、你选的会话区、对话区、输入框。要有 **4 段打开着的会话**：
一段是当前（正在读），一段正在生成，一段在等作者批准，一段排队。标题长短不一：一个作者
起的短名、一个作者起的长名（超过标签宽度）、两个没起名的（第一句话的截断，其中一个很长）。

标签（或行）上至少要有：标题、状态记号、关闭。要考虑：

- 关闭一段**正在生成**的会话——先停止还是直接关？关闭按钮要不要在这个态下变化？
- 标签多到放不下时怎么办（8 段？12 段？）。
- 当前会话的选中态，和悬停态，要分开。
- 每段会话的累计用量（tokens / 金额）要不要在标签上？还是悬停 / 列表里？

### 2. 五个态的记号（张力二的答案）

一张**记号总表**：正在生成 / 排队 / 等作者 / 有新回复 / 出错，每个态画在标签上（或行上），
外加「当前 + 该态」的组合（当前那段也可能正在生成、也可能在等作者——但当前那段不需要
「未读」，因为作者正看着）。

再画一遍**同一套记号出现在**：
- 抽屉的模式 tab「助手」上（抽屉在别的模式时，「助手」两个字旁边今天是一个 6px 方块，
  表示「别处有事」——现在要能表达「有一段在等你」比「有一段在跑」更急吗？还是不区分？）
- 「历史会话」下拉的行上（一段打开着的会话在列表里也要有它的态）

### 3. 历史会话列表（张力三的答案）

重画这个下拉：分节（已固定 / 最近 / 要不要「已命名」/ 要不要「已打开」）、每行的组成
（标题或截断、时间、固定图钉、**打开着的标记**、状态记号）、行上的动作入口（改名、删除、
固定）。动作入口的问题：

- 三个动作放在悬停出现的图标里？右键菜单？还是行尾一个「⋯」？这个应用的文件树用右键
  菜单，扮演的花名册用悬停图标。
- 删除必须确认，确认文案要带会话名。正在生成的会话不能删（菜单项禁用 + 一句为什么）。

### 4. 改名（张力四的答案）

- **列表行上**改名：就地编辑（行变成输入框）还是弹层？
- **头部**改名：会话名放在头部哪里？「对话助手」四个字还要不要？点名字就编辑？画出
  静止 / 悬停 / 编辑中 / 空名（还没起名，显示的是截断——这时头部显示什么？截断当标题
  会很怪）四个态。
- 编辑态里「让助手起名」的位置。
- 名字上限 60 字，超出怎么反馈；清空 = 回到截断，要不要一句说明。

### 5. 新会话

「新会话」按钮今天在空会话时是灰的。现在它永远可点：已有一个空标签时是聚焦它，不然
新开一个。画按钮的位置和新开一段之后的空态（一段没有名字、没有对话的新标签 + 空的
对话区，作者第一眼要知道「这是新的一段，那三段还在」）。

### 6. 排队

第 4 段发送时进队列。扮演里有一张排队卡：转圈 + 「同时最多 3 个 agent 生成」+ 「插到最前」
「取消排队」。助手里画对应的那张，语气改成对话助手的（它不是 agent，是「会话」）。并发
读数 `并发 ▮▮▯ 2 / 3 · 排队 1` 放在哪——扮演放在花名册脚；助手这边由你定。

### 7. 切到一段在等作者的会话

作者从标签条点过去。那一段的对话区底部是一张停住的确认卡（已有组件：路径、改动内容、
批准 / 拒绝）。画这一屏，重点是**从标签上的「等你」记号到卡片之间的视觉连线**——作者
要立刻知道「就是这张卡让它停的」，不用往上翻。

### 8. 关闭最后一段、切换项目

关掉最后一个标签 → 落到一段空的新会话。换项目 → 所有运行停止（要不要提前问一次？
今天单会话时没有问）。这两个态各画一个，不用大。

## 交付

- **抽屉「助手」模式全貌**，深色 + 浅色两版，4 段打开着的会话（当前 / 生成中 / 等作者 / 排队）
- **被否方案的草图** + 一段为什么
- **记号总表**：五个态 × 三个位置（标签 / 模式 tab / 列表行）
- **历史会话下拉**：分节、行、动作入口、删除确认
- **改名**：列表行 + 头部，各自的态；「让助手起名」的位置
- **新会话空态**、**排队卡**、**切到等作者的那一段**、**关闭最后一段** / **换项目**
- 一段说明：你怎么解决张力一的（没有身份的东西怎么并排），为什么

## 不要做的事

- **不要用第二个颜色标「急」**。用实心 / 空心 / 动 / 静 / 形状。
- 不要加圆角。
- 不要给会话加头像、图标、或者自动生成的 emoji——会话没有身份，硬给一个只会误导。
- 不要把「关闭标签」做得像「删除会话」——一个是收起，一个是丢掉；两者的按钮不能长得一样。
- 不要在标签条里放模型选择器。模型是全局的，在头部；两段对话可以用不同模型跑，但那是
  作者在两次发送之间换的，不是标签的属性。
- 不要把「让助手起名」做成自动的。作者点了才跑，结果填进输入框。
- 不要暗示会话之间互相看得见。四段对话是四段。
- 不要用抽屉之外的地方（标题栏、侧栏图标）显示运行态——那超出这次范围，抽屉关着时
  今天扮演也没有入口。
