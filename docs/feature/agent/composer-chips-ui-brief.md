# 助手输入区的芯片行 —— 给 Claude Design 的任务书

> 状态：`shipped` · 2026-09-07 起草，同日设计稿回（`02g 助手输入区 Composer.dc.html`），同日按**方向 1c** 落地。
>
> 起因：作者反馈「对话框上面的开关有点多，显得很挤」。最坏情况下输入框上方是四条横带 + 一行十六个以上的控件，而这一行里混着四类本质不同的东西（消息材料 / 会话开关 / 模型设置 / 状态指示器），它们穿着同一件芯片衣服。
>
> 本文 `---` 以下是**发给 Claude Design 的任务书原文**。

## 设计稿怎么答的（`02g`，TURN 1）

三个方向都画了，稿子推荐并被采纳的是 **1c**：四类各给一件衣服，同时把输入框上方压回一行。1b 只治「分不清」，1d 把会话级的东西放到了抽屉级的位置（模型名旁边）。

稿子给的分法（1z §3），**框内 / 框外是最硬的一道边**：

| 类 | 长什么样 | 在哪 |
|---|---|---|
| **A 材料**（选区 · @引用 · + 引用） | 有框，12px 无衬线，唯一带 × | 输入框外，左 |
| **B 会话**（计划模式 · 能力） | 无框，7px 方块或带 ▾ 的词 | 输入框外，右 |
| **C 模型**（思考档位） | 等宽 11px 带 ▾ | 输入框**内**的页脚 |
| **D 指示**（自动批准） | 等宽 11px **不**带 ▾ | 页脚 |

框外改的是这段对话，框内是「这条消息会怎么被送出去」。

## 落地清单

1. **六个子代理开关 + 状态记忆 → 一个词。** 新的 `CapabilityMenu`（`能力 N ▾` / `能力 4/6 · 联网、PDF 已停 ▾`）+ 浮层（本次对话 / 换会话即重置 / 每行 7px 方块 + 绑定的模型名 / 停用行写「本次已停 · 恢复」）。`StateMemoryChip` 删除，它变成浮层里分隔线下的一行，Beta 没开时**连分隔线一起不渲染**。
2. **收起的硬规矩**：非默认必点名，回默认即消失；全默认只写数字，有停用才写分数；名字不截断、不缩成数字。
3. **三个「+」合成一个 `+ 引用`**，打开不带 kind 过滤的 `@` 选择器（选择器本来就有分组）。
4. **自动批准与思考搬进页脚**：`AutoApproveChip variant="footer"`（等宽、无框、无盾牌图标，× 留着）、`ReasoningControls variant="footer"`（词由值生成，四种厂商形态都落成一个词；浮层顶上「写进模型行」）。
5. **等待态保住页脚**（屏 1g-4）：框、页脚、停止方块全留，整体浅一档；B 类字还在但不响应；原来的「↑ 卡就在输入框上方」取消。
6. **窄栏**（屏 1e）：B 整组作为一个单位换行并仍靠右；页脚只有 Enter 提示缩成「Enter ↵」（≤1040px），自动批准与思考不缩。
7. **@引用芯片**（屏 1g-3）：320px 上限，`middleEllipsis` 中段省略、扩展名钉在右端，全名进 title。
8. **扮演面板**（1z §4）跟着换成同一个词，不带状态记忆那一行。
9. **一致性检查不动**：那里的六个方框在一个 pre-run 设置块里，是作者开跑前读一遍的表单，收起反而更差。两种渲染共用 `subagentChipModel.ts`（哪些 kind 存在、哪些可用、各叫什么），只有形状不同。

## 与稿子的出入

- **浮层每行加了 `title` 和 `aria-label`**：稿子的行只有方块 + 名字 + 模型名，落地后无障碍树里是六个没有名字的 checkbox。顺手把六个芯片原来那句解释（「联网检索子代理已启用（点击在本次对话停用）」）搬进 title，一举两得。
- **自动批准的措辞调了词序**：「本次对话自动批准中」→「自动批准中 · 本次对话」，和占位「自动批准 —」对齐首词。AI 面板（`02a`）的芯片变体用同一个字符串，跟着变。
- **`思考` 在预算形态下留空时写「默认」**而不是占位数字——占位数字看起来像作者选过。

## 真机没验到的

dev server 上没有项目，所以 @引用芯片的截断、多芯片换行、等待态三处只有代码路径与单测，没有截图；`一致性检查` 的芯片区同理（需要打开文档）。已验：新会话最安静态、六个子代理配齐、停用两个后的点名、能力浮层（浅 + 深）、思考浮层（千问「开关 + 预算」形态）、1024 宽下页脚缩成「Enter ↵」。

## 顺带发现的一处实现错

**已修（2026-09-07，本次一并）。** `translate` 在 `SUBAGENT_KINDS` 里且不在 `OFF_CHIP` 里，所以配了翻译模型就会出芯片；但 `ai.chat.subagentChip.translate` 在两份 locale 里都不存在，`defaultValue` 的兜底链最后落到 `"长文"` ——翻译子代理的芯片今天显示成「长文」，提示语也写成「长文子代理已启用」，和真正的长文芯片重名。补两份 locale 的 `translate` / `translateActive` / `translateDisabled` 即可。

# 设计任务：在本项目里新建 `02g 助手输入区 Composer.dc.html`

（AI 区当前最高是 `02f 音频转写 Transcribe.dc.html`，所以取 `02g`；若已被占用，往后取第一个空位并在回稿里说明。）

## 0. 一句话

对话助手（`02b 助手多会话 Assistant Sessions`）的输入框上方那一行开关已经挤到读不动了。这一稿要的不是装饰，是**分层**：把四类本质不同的控件从一条平铺的芯片行里拆开，让常用的仍然一键可达，不常用的收起来但**开着的时候不许隐身**。

## 1. 现状：输入框上面从上到下有什么

助手是抽屉里的一个标签页，抽屉宽 `min(1180px, 94vw)`，对话占满整宽（没有侧栏，会话是横排标签条）。从上到下：

| # | 条带 | 何时出现 | 已有设计稿 |
|---|---|---|---|
| 1 | 会话标签条（打开着的几段对话） | 常驻 | `02b 屏 1a` |
| 2 | 任务面板（本次会话拆出来的步骤清单） | 有任务时 | — |
| 3 | 记忆条（下一次请求的上下文由什么构成，离压缩还有多远） | 常驻 | `02a 屏 2c` |
| 4 | 写手介绍条（一次性说明） | 只出现一次 | `04d` |
| 5 | 写手线（「接下来谁写」，无框、贯通整宽的发丝线） | 设置里开了写手才存在 | `04d 屏 5a / 8a` |
| 6 | **芯片行 ← 本次的主角** | 常驻 | 没有专稿 |
| 7 | 输入框 + 页脚（片段选择器 · 「Enter 发送 · Shift+Enter 换行」· 发送方块 / 停止方块） | 常驻 | `02b` |

芯片行本身，从左到右：

| 位置 | 控件 | 何时出现 | 点一下会怎样 |
|---|---|---|---|
| 1 | **选区** | 常驻（三态：已附带「选区 128 字」＋叉 / 可附带「+ 选区 128 字」/ 没选中时禁用的「+ 选区」） | 附带或摘掉正文选区 |
| 2 | **@引用 ×N** | 作者引用了才有，0…n 个 | 点叉移除。图片带图标、录音带音波图标，图片被压缩过还要多带一句提示 |
| — | *弹性间隔（`flex:1`）* | 常驻 | 把「这条消息带什么」推到左边，其余推到右边 |
| 3 | **+ 条目** | 常驻，没有可引用的条目时禁用 | 等同于输入 `@` |
| 4 | **+ 文档** | 同上 | 同上 |
| 5 | **+ 图片** | 只在模型链能看图时出现 | 同上 |
| 6 | **子代理开关 ×6**：联网 · 识图 · 长文 · PDF · 绘图 · 翻译 | 每个都是「设置里配了模型」才出现 | 在**本次对话**停用/恢复这一项能力 |
| 7 | **计划模式** | 常驻 | 让模型先立可勾选的步骤清单再动手 |
| 8 | **状态记忆** | 只在这个 Beta 开着时出现 | 每次发送前把上一轮之前的对话折成结构化执行状态 |
| 9 | **自动批准** | 常驻（生效时是实心芯片「本次对话自动批准中」＋叉；没授权时是虚线占位「自动批准 —」） | 只能撤销，见 §4 |
| 10 | **思考档位** | 模型支持思考时出现，**三种形态之一**：①「开启 / 关闭」两个方块；②一个数字输入框（思考 token 预算）；③一个下拉（关闭/低/中/高/…）。千问一类模型是 ①＋② **同时出现** | 改思考深度，见 §4 |

**最坏情况一行里 16 个以上控件**：1 个选区 + 3 个 @引用 + 3 个「+ …」 + 6 个子代理 + 计划模式 + 状态记忆 + 自动批准 + 「开启 / 关闭 / 数字框」。它 `flex-wrap` 折成 2–3 行，把输入框一路往下推——而这一行正压在作者每一句话的必经之路上。

## 2. 真正的问题：四类东西穿了同一件衣服

| 类 | 是什么 | 生命周期 | 现在长什么样 |
|---|---|---|---|
| **A 这条消息带什么材料** | 选区、@引用、+ 条目 / 文档 / 图片 | 一次性，发出去就清空 | 芯片 |
| **B 本次对话怎么工作** | 6 个子代理、计划模式、状态记忆 | 会话级，换会话就重置 | 芯片 |
| **C 模型自己的设置** | 思考档位 / token 预算 | **写进模型行、存进数据库、全局生效**——和 `05c 模型编辑 Model Editor` 里是同一个值，换会话也还在 | 芯片（穿错了衣服） |
| **D 状态指示器，不是控件** | 自动批准 | 由别处的确认卡授予，这里只能撤销 | 芯片（也穿错了） |

今天只有一个弹性间隔把 A 和其余分开，**B / C / D 三类之间没有任何视觉差别**。作者看到的是一排等大的方框，其中有的改这一条消息，有的改这段对话，有的悄悄改了模型的全局设置，还有一个根本按不开。

## 4. 数据边界（这些是事实，设计改不掉）

1. **子代理开关只能减，不能加。** 芯片只在设置里给这一类**绑定了可用模型**时才出现；它永远不能打开一个没配模型的能力。所以不存在「六个位置，三个亮三个灰」——没配的那三个**根本不渲染**。
2. **自动批准不是开关。** 它由消息流里的确认卡上的「本次对话都批准」授予，这里**只能撤销**。没授权时是虚线占位（`02b 屏 1g` 定的「absent」词汇：位置常驻，好让作者知道这儿有这么回事）。别把它设计成能在这里打开的东西。
3. **思考档位改的是模型行，不是这次对话。** 值存进数据库，`05c 模型编辑` 里显示同一个。它的形态由模型厂商决定（开关 / 数字预算 / 档位下拉 / 开关＋预算），**同一个位置会长出不同的控件**——任何方案都得容得下这四种。数字框是失焦或回车才提交（每次提交整行写库）。
4. **写手不在这一行**，它是芯片行**上方**那条贯通整宽的发丝线（`04d 屏 5a` 有整段论证：「写手不是第七个芯片」）。这一稿不许把它收编进来。
5. **计划模式 / 状态记忆是会话级**，换会话即清空；状态记忆只在它的 Beta 开着时存在。
6. **子代理芯片被扮演面板（`04a 扮演 · 主界面`）共用**，那里用自己的一套开关状态，且**不渲染写手线**。这一稿动了芯片的形状，扮演面板会跟着变——请在 1z 里说一句它在那边成不成立。
7. **记忆条和写手线不是开关**，别把它们折进芯片行。
8. 应用里没有「这一轮临时覆盖」这种东西。若你的方案需要它（比如把思考档位改成只影响本次对话），那是一次真正的功能变更——可以提，但要在 1z 里写清代价。

## 5. 不要做

- **不许有「开着却看不见」的开关。** 收起是可以的，隐身不行：一个作者以为关着、实际开着的联网子代理，比一行挤芯片糟得多。任何折叠方案都要给出非默认状态的收起态表达。
- **不许圆角**（全局零圆角是应用级规矩；只有状态圆点、加载圈、单选点是圆的）。
- **不许用彩色区分类别**——全应用单一克制强调色。分层靠位置、密度、发丝线、留白，不靠上色。
- 不许把自动批准做成可以在这里打开的开关（§4.2）。
- 不许让写手变成一个芯片（§4.4）。
- 不要发明新数据、新状态、新的后端支持。这一稿重排的是**已经存在**的十几个控件。
- 不要顺手重画记忆条、任务面板、会话标签条——它们已有各自的稿（`02a 屏 2c` / `02b 屏 1a`），这次只在 1h 里作为上下文出现。

## 6. 沿用的方言

`02a AI 面板` / `02b 助手多会话` 已经定了这块界面的语言，照抄不用重新发明：发丝线分隔、`bg-elevated` 的输入底、13px 横刻度起头的竖线记号系统、禁用态是浅一档而不是打叉、常驻装饰要能说出自己为什么值这块地方。颜色令牌用当前主题（纸 / 夜），两套都要画。

## 7. 回稿时请说清

1. 推荐哪个方向，一句话理由；
2. 被收起的东西在什么条件下重新露头；
3. 四类控件（消息材料 / 会话开关 / 模型设置 / 状态指示器）在你的方案里各自靠什么区分——这是这一稿唯一真正要解决的事；
4. 扮演面板（`04a`）跟着变之后成不成立。
