# 设计任务：为一款桌面写作应用设计「对话归纳」的阈值控制——应用的第一个滑块

## 0. 这是什么应用

一个桌面写作应用（Tauri + React，Mac 和 Windows），面向小说 / 公文 / 标书 / 周报作者。左边文件树，中间 Markdown 编辑器，右边一个很宽的 AI 抽屉，里面住着一个 AI 助手；另有一个「扮演」页，作者以第一人称和知识库里的人物对话。两个页面都是**长对话**：几十轮之后，对话历史会撑满模型的上下文窗口。

应用对此的办法叫**归纳**（compaction）：把最早的几轮对话交给模型压成一段「历史摘要」，换回空间。它今天在两个时刻发生：

1. **自动**：每次发送前检查，历史超过一条固定的线（消息上限的 70%）就归纳。作者调不了这条线。
2. **手动**：AI 助手输入框上方有一根 6px 高的「上下文构成条」，条上画着一根竖线（就是那条 70% 线），条的右端有一个「立即归纳」按钮。**扮演页有同一根条，但没有按钮。**

你们上一轮为它画过设置页的「上下文与记忆」（`18 设置 · AI 配置`，屏 1c）：今天那一页只有「图片」一节一行，页底一行灰字说「知识库注入预算和上下文利用率目前在 AI 面板的工具条里调」。这次要往这一页加**第二节**，也是这一页第一个真正复杂的控件。

## 1. 要做的事（先读需求原文）

作者的要求，逐字：

> 增加一个设置选项，内容为上下文压缩阈值，使用 2 个滑块：
> 1. 一个是 8K～512K，有几个常用刻度位置（比如 16k，32k，128k，256k）也可以去到中间值。
> 2. 另一个是 50%～80%，表示上下文比例。
> 这两个可以独立设置，**以先到为准**（设置为 50%、256k：一个 256k 上下文的模型到 50% 即 128k 时就触发；对于 1M 的模型，则 256k 时触发）。
> 同时给这个区域加一个开关（自动归纳），打开后才会生效，否则只能在 AI 助手和扮演页面手动点击归纳。

翻成界面：「上下文与记忆」页新增一节**「对话归纳」**，里面三样东西——

| 控件 | 值域 | 含义 |
|---|---|---|
| 开关 **自动归纳** | 开 / 关 | 关掉后应用不再自动归纳；两个页面的「立即归纳」按钮是唯一出口 |
| 滑块 **归纳阈值 · token 数** | 8k – 512k，常用刻度 16k / 32k / 128k / 256k，中间值也能停 | 历史到这个绝对量就归纳 |
| 滑块 **归纳阈值 · 窗口比例** | 50% – 80% | 历史到模型上下文窗口的这个比例就归纳 |

两条线**独立设置、先到者生效**。

## 2. 五件必须被设计解决的事

### 2.1 这是应用的第一个滑块

应用里今天**没有任何滑块**。它的既定控件语汇是：方形开关（42×22 轨道、14×14 方块旋钮）、直角输入框、等宽数字、chip 行（几个并排的方块按钮做单选）。请设计一个滑块，让它像是这一家的东西：

- **轨道 / 滑块柄 / 刻度 / 读数**四个部分的尺寸、颜色、状态（默认 / 悬停 / 拖动中 / 键盘聚焦 / 禁用）。
- **刻度**：token 那条有 4 个常用位置（16k / 32k / 128k / 256k）加两端（8k / 512k）。作者拖到刻度附近要不要吸附、吸附范围多大、刻度之间的值怎么读（读数显示「96k」还是「≈ 96k」）——请给方案。
- **非线性**：8k 到 512k 跨 64 倍，线性轨道上 8k–32k 会挤在头 5%。请按对数刻度画，并说明 16k 和 32k 在轨道上离多远。
- **读数**：等宽字，和 18 那屏「最大长边」输入框同一列宽（110px）对齐——它就在那一行的下面。读数可不可以直接编辑（点进去改成一个数）？如果可以，它和滑块怎么互为镜像。
- **比例那条**：50–80% 只有 30 个百分点，步进是 1 还是 5？刻度要不要画？

请给出完整的 anatomy 规格（像 04 给开关的那样：尺寸到像素、颜色到 token）。这个滑块以后会被别的设置复用。

### 2.2 「先到者生效」要看得见

两条独立的线，最后只有一条起作用，而起作用的是哪一条**取决于当前模型**：256k 的模型是比例那条先到，1M 的模型是 token 那条先到。作者拖动一条滑块时，需要知道「我现在拖的这条有没有用」。

设置页知道当前选中的模型和它的窗口大小。请设计一行**「以当前模型为例」的读数**，例如：

> 当前模型 Claude Sonnet 4.5（200k）：到 **100k** 归纳 —— 由「窗口比例 50%」决定

拖 token 滑块时这句话随时更新；当 token 那条变成先到的，句尾的归因换成「由 token 数 96k 决定」。**不起作用的那条滑块要不要变淡？**——请判断。它仍然是有效设置（换个模型就起作用），变淡可能被误读成禁用。

### 2.3 有第三条线，而且它今天赢

> **2026-09-05 起这一节的「去处」已过时**：「窗口占用」搬进了这一页（50–90% 的滑块，见 §D），路标从「去 AI 面板」变成同页滚动。三条线的几何关系没变，下面这段照旧成立。

**这是本任务书最要紧的一条。** 应用里已经有一个作者能调的数：AI 面板工具条上的「窗口占用」（25% / 50% / 75% / 90% 四个 chip，默认 50%）。它决定一次请求**最多**用掉窗口的多少——是硬上限，超过就裁剪。归纳线必须画在它下面，否则历史会先被硬裁再有机会归纳。

今天的归纳线 = 70% × 消息上限，消息上限 ≈ 窗口 × 窗口占用 − 输出预留 − 工具说明。默认窗口占用 50% 时，这条线大约在**窗口的 35%**。

后果：**在默认设置下，「窗口比例」滑块的整个值域（50–80%）都在今天那条线之上，一次都不会先到。** 它只有在作者把「窗口占用」调到 75% 或 90% 之后才有意义。这不是 bug，是三条线的几何关系；但它必须被看见，不能让作者拖着一条永远不生效的滑块。

所以 2.2 那句读数要多一种归因：

> 到 **70k** 归纳 —— 受「窗口占用 50%」限制（AI 面板工具条里调）

请把这三种归因（token 数 / 窗口比例 / 窗口占用）设计成同一句话的三个变体，并给「受窗口占用限制」的那种一条去处（它在 AI 面板里，不在设置页——设计稿 18 里「接着去 … →」的路标语汇可以复用，只是这次指向的不是设置页里的一页）。

### 2.4 开关关掉后，两个页面的条怎么说话

自动归纳关掉后：

- 上下文构成条上那根竖线（「越过此处将折叠最早的对话」）**不再是一个承诺**。它还画不画？画成什么样？我倾向于**还画，但换一种线**（今天的线是实线）。注意应用里的线型已有分工——本轮取材条里断成点线的是「记忆区」、3px 双线归「集合」——请查一下别撞车。请判断。
- 条被点开后的解释句今天是「越过竖线后，下一轮把最早的对话归纳成摘要」。关掉后要改成什么——要告诉作者「自动归纳已关」、「点右边的立即归纳」、以及「在设置里能打开」，一句话说完。
- **扮演页要补一个「立即归纳」按钮**，和 AI 助手那个同款同位置（条的右端）。今天没有它，是因为扮演页的归纳走另一条代码路，不是设计上不要。

条的现状（你们没画过它，简要描述）：6px 高的分段条，段按来源着色（系统+工具 / 摘要 / 近期对话 / 知识库 / 记忆 / 空余），条右端一行 11px 读数「Context 42k / 100k」，可以点开一行图例；「立即归纳」是读数行右端的一个文字按钮，归纳中变成「归纳中…」。

### 2.5 这一节在页里的位置，和 18 的 B2 的关系

18 的屏 1d（B2）演练过「装满以后」：图片 / 知识库注入 / 输出 / 前情提要四节。现在真正来的第二节是「对话归纳」，B2 里没有它。两个问题：

- 它放「图片」**上面**还是下面？归纳影响每一次长对话，图片只影响带图的请求。我倾向归纳在前。
- 页底那行灰字「知识库注入预算和上下文利用率目前在 AI 面板的工具条里调」——2.3 让「窗口占用」和这一节直接相关了。那行字要不要升级成这一节里的一个真正的去处？

## 3. 视觉规范（硬约束，必须遵守）

- **风格**：克制的、现代的、Apple 式的。整体气质是「手稿」——像裁切的纸，不像圆角卡片。
- **圆角：全局为 0。** 滑块柄也是**方的**。唯一允许的圆形是状态圆点、加载指示器、单选标记。
- **强调色：只有一个**——赭石色 sienna（设置页用它自己那档：浅色 `#A9512B`；深色跟随夜间色阶）。滑块已走过的轨道段可以用它；不允许第二种颜色。
- **设置页有自己的一层纸**：浅色页面 `#FBF7EE`，输入框 `#FFFDF6`；标题衬线（Source Serif 4 / Noto Serif SC）。
- **层次靠背景深度 + 1px 细线**。小节 = eyebrow 大写小字 + 1px 细线 + 若干行；行 = 左侧标题与说明、右侧控件，右缘对齐。
- **字体**：正文衬线，UI 标签无衬线，**数字等宽**——滑块读数、刻度标签、「以当前模型为例」里的数字全部等宽。
- **动效**：120–320ms，Apple 缓动。滑块吸附到刻度可以有一下极短的停顿感，不要弹跳。
- **深浅双主题**都要出。
- **文案**：这个功能叫「归纳」，不叫「压缩」（应用词表：对话历史压缩的产物叫「历史摘要」，动作叫「归纳」；「压缩」只在工程文档里用）。面向作者的词一律说「知识库 / 条目 / 文档」。
- **与 18 一致**：沿用 18 屏 1c 的页面版式（标题 / 副标题 / 节距 28px / 行内 110px 数字列）。

## 4. 交付物

一屏 `19 归纳阈值 Compaction`，包含：

1. **滑块 anatomy**（浅 / 深）：尺寸、颜色 token、五个状态、刻度与吸附、键盘操作（←→ 步进、Home/End、PageUp/Down 跳刻度）
2. **「对话归纳」一节**在「上下文与记忆」页里的样子，五个状态：
   - 开关开、当前模型 200k（比例那条先到）
   - 开关开、当前模型 1M（token 那条先到）
   - 开关开、默认窗口占用 50%（第三条线赢，带去处）
   - 开关关（滑块的样子——禁用？淡化？）
   - 没有选中模型 / 模型没声明窗口（读数说什么）
3. **上下文构成条**在自动归纳关掉后的样子（AI 助手 + 扮演页各一），含点开的解释句；扮演页补上「立即归纳」
4. 设计说明侧栏：对数刻度怎么分、吸附规则、不生效的滑块要不要变淡、竖线关掉后画不画、节的顺序

## 5. 数据边界（防止设计出画不出来的东西）

- 设置页能知道：当前选中的模型名、它声明的窗口大小（可能没有）、「窗口占用」的当前值、两条滑块的值、开关状态。**不知道**任何一场对话现在有多长——「以当前模型为例」只能算线在哪，不能画「你离线还有多远」。
- 上下文构成条知道全部（它在对话现场），但它**不知道**滑块——它只拿到最终那一个数（线在哪）和是谁决定的。所以条上不要画两条线。
- 归纳线是**装机级**设置（所有项目、两个页面共用），不是每个会话一份。
- 「立即归纳」在少于 3 轮时不出现（没有可折叠的轮）；关掉自动归纳不会让它在 2 轮时出现。
- 值域硬边界：token 8,192 – 524,288；比例 0.50 – 0.80。开关默认**开**（见 §B.1，待作者拍板）。

# B. 实施计划（实现者读）

## B.0 语义（先定死，再画）

**三条线，取最小：**

```
trigger = min(
  triggerTokens,                      // 滑块 1：8k–512k
  triggerRatio × contextSize,         // 滑块 2：50–80% × 模型窗口
  COMPACT_TRIGGER × messageCeiling,   // 今天的线：0.7 × (窗口×占用 − 输出预留 − 工具 schema)
)
```

- 比例乘的是**模型声明的窗口**（作者原文「256k 的模型到 50% 即 128k」），不是占用后的上限。
- 第三条线保留，原因在任务书 §2.3：它是硬裁剪（`trimHistory`）之前最后的安全距离。两条滑块只能把线**往前挪**，永远不能挪过今天的位置——所以滑块都拉到最大（512k / 80%）时，行为与今天**完全一致**。
- **默认值 = 512k / 80% / 自动归纳开**：装机后行为不变，作者动了滑块才有差别。这是我的建议；作者原文「打开后才会生效」说的是语义不是默认值，若要默认关，等于给所有现存用户关掉自动归纳，需要作者明确拍板。
- 模型没声明窗口时（`contextSize` 缺失）：`messageCeiling` 走 `ASSUMED_INPUT_CEILING_TOKENS`（32k），比例那条无法计算、跳过；trigger = min(tokens, 0.7 × 假定上限)。
- **折叠目标同比缩放**：今天折完停在 `RETAIN_TARGET(0.45) × messageCeiling`。若 trigger 被滑块压到 16k 而上限是 100k，目标 45k 高于触发线 16k，折完立刻再触发——每轮都归纳、缓存每轮全废。所以目标改成 `trigger × (RETAIN_TARGET / COMPACT_TRIGGER)`（≈ 0.64 × trigger），保持今天 0.70 → 0.45 那个比例的空档。`MIN_KEEP_TURNS = 2` 不变。
- **开关关**：`sendChat` / `prepareContinuedHistory` 跳过 `compactChatHistory`；`trimHistory` 照旧兜底（裁的是旧工具结果和图片，不动对话文本——这是它今天的行为，也是关掉自动归纳后唯一的降级路径，条的解释句要提到）。手动归纳（force 档）不看开关、不看阈值。
- **手动归纳补到扮演页**：`roleplayStore.compactNow(agentId)`，镜像 `agentStore.compactChatNow`——但扮演的归纳有两个副作用今天住在 `prepareContinuedHistory` 的 compacted 分支里：摘要落盘（`saveSummary`，旁白的 `read_scene_summary` 读它）和记忆注入块刷新（`refreshMemoryBlock`，「压缩之后刷新」是正确性边界，见 roleplay 05 §2）。手动路径**必须**做同样两件事，所以把它们抽成 `lib/roleplay/run.ts` 里的一个 `afterCompaction()`，两条路共用。

## B.1 作者已拍板（2026-09-02）

1. **默认值 512k / 80% / 自动归纳开**——装机后行为与今天完全一致。
2. **「窗口比例」保持 50–80%**，在默认窗口占用 50% 下整段不生效这件事靠读数说清（§2.3）。被否的两个替代：值域放宽到 20–80%；比例改成相对消息上限。
3. **「窗口占用」先不搬**，留在 AI 面板工具条；这一节的读数给它一条去处。

## C.2 与设计稿的出入

1. **刻线挂在容器上而不是条里**：`.ctxBar` 有 `overflow: hidden`，1×4px 的刻线放进去会被裁掉，所以它是条的兄弟元素、由 `.ctx` 做定位上下文（`top: 7px`）。位置同一个百分比，视觉上和设计稿一致。
2. **路标去处是「关设置 + 开 AI 面板（生成模式）」**：设计稿只说「去 AI 面板 · 工具条」，应用里那排「窗口占用」chip 住在 AiPanel 的工具条上，所以就是这一跳。
3. **「假定上限」读数**：设计稿写 32k；实现读 `ASSUMED_INPUT_CEILING_TOKENS` 的真值格式化，常量改了这里跟着改。
4. **滑块的 aria**：设计稿没提；`role="slider"` + `aria-valuetext`（「92k」而不是 94208），Tab 可达、拖动时把焦点交给柄以便接着用键盘。
5. **深色三色**没有单独调色板：`Slider.module.css` 读 `--stg-*` / `--color-*` 角色，夜色由 tokens.css 的映射得到，与 18 一样。
6. **PR 2 先用原生 `<input type=range>` 的过渡态没有留下**：设计稿在同一轮回来了，最终提交里只有设计的组件。

# D. 后续：「窗口占用」搬进这一页（2026-09-05）

推翻 B.1-3（「先不搬」）和 C.1 末行的第 ③ 条。作者的话是「干脆把这个选项加到设置里，参考归纳阈值的两个滑块方式，让用户可以在 50%～90% 之间调整」。

## D.1 为什么这次搬

§2.3 那条几何关系没变，但它的**代价**在设计稿回来之后才看清：读数句每次以「受「窗口占用 50%」限制」结尾时，作者要做的事是**离开设置页、打开 AI 面板、在工具条上点一个 chip、再回来看这句话变了没有**。一条读数指向另一块屏幕，就等于要求作者在两块屏幕之间对齐一个数——而那个数正是这一页三条线里最先赢的那条。搬进来之后，路标从「关设置 + 开 AI 面板」降级成同页滚动，三条线第一次在同一屏上可比。

## D.2 落点

| 改什么 | 怎么改 |
|---|---|
| 值域 | `CONTEXT_UTILIZATION_MIN` 0.1 → **0.5**，`MAX` 0.95 → **0.9**，默认仍 0.5。两端本来就没人守得住：10% 等于把声明的窗口作废，95% 在小模型上剩不下输出预留 |
| 迁移 | `appStore` 读取时 clamp，所以点过已退休的 25% chip 的装机会回到 50%。**这是唯一一处行为变化**，且方向是「装得更多」，不会让原本发得出去的请求发不出去 |
| 设置页 | 新的第一节「窗口占用」，一根 50–90% 的滑块（刻度 50/60/70/80/90，吸附，步进 1%，Shift ×5）+ 可编辑读数，形制照 C.1 逐条复用。节内多一行 foot：「当前模型 X（200k）：一次请求最多 100k」——和「以当前模型为例」同一种「把算术摊开」的手法，只是这里只有一个数要推 |
| 节的顺序 | 窗口占用 → 对话归纳 → 图片。硬上限在前：它框住后面那两条线，而不是反过来 |
| 路标 | `goCeilingLink` 从「AI 面板 · 工具条 →（不在设置里）」改成「窗口占用 ↑」，点击 `scrollIntoView` 到本页第一节；`goCeilingHint` 整条删掉（它说的「不在设置里」现在是假的） |
| AI 面板 | 那排 chip 退休，原地留一行读数（标签 + 百分比 + 「设置里调 →」，`openSettings("context-memory")`）。位置不动——[reasoning-plan.md](../../api/reasoning-plan.md) 的思考控件锚在「紧接「窗口占用」行下方」，而分配条没有这个数就读不懂：条上每一段争的就是它 |

## D.3 没有变的

- **默认值下比例滑块仍然整段不生效**（§2.3 的几何关系）。搬家改的是「怎么去调」，不是三条线的相对位置；新的 `MIN` 恰好等于默认值，所以装机后的归因照旧是「受「窗口占用 50%」限制」。
- **`compactTriggerFor` 一个字没改**。三处读同一个数的唯一来源还是它。
