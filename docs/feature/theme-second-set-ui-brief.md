4. **事件色那处待盯，实测下来不用改。** 六色**全部**来自推导，最近的一对（物品–事件）oklab ΔE 石 0.069 / 墨 0.047；同一对在纸是 0.073、夜是 **0.025**——推导出来的六色比手调的两套分得更开或持平，所以没有为石 / 墨 开任何手调。
5. **名字。** 一对主题在应用里是**两张各自独立的卡**（浅色带一张、深色带一张），所以「石墨」拆成两个单字，与纸 / 夜同一种取名法：id `stone` / `ink`，名 **石** / **墨**。
6. **落地形态＝内置**（作者定）：`[data-theme="stone"]` / `[data-theme="ink"]` 写在 `tokens.theme` 层，**只写 37 个核心**。它顺带答掉了方案 §4 末尾悬着的那句「注掉手调层看一眼」——见 §13 的 S5 行。

## 第二批：靛（2026-09-07）

稿子的第二选也落成一对内置卡：id `frost` / `indigo`，名 **霜** / **靛**。取名同纸 / 夜、石 / 墨 的单字法——深色那张是主角，直接叫**靛**；浅色那张是「它的白天」，稿子标的是「浅 · 白日」，取**霜**：一层冷白，同色系、同为一个字，而「昼」会和已经在用的「夜」撞成一对不相干的时段词。

与稿子的出入，只有一处新的：

- **四个类型色的芯片底不能直接掺**。石 / 墨 那次是把锚色按比例掺进底色；靛的底是蓝的，按同样比例掺出来的 `type-text-bg` 变成 `#DFDFDF` ——中性灰，橄榄色相被互补的蓝抵掉了，四个芯片就没法靠色相扫读。改成在 oklab 的 **LCh** 上构造：**L 与彩度照石的四片，色相各自保住**（106.7° / 46.5° / 333.8° / 217.6°），再把 fg 压到 ≥ 4.5。
- 稿子给的 `type-video-fg` `#3F7A8A` 在自己的芯片底上只有 4.1，压到 **`#2F6A7A`**（4.61）；这个令牌同时是知识库的**概念**色，所以下面的六色是按压过之后的值量的。
- 其余 22 个照 S5 的补法（`bg-tinted` 跟基底、影子取正文色的冷近黑、`amber-soft` 是金褐的淡洗、`border-strong` 取 amber（浅）/ text-faint（深）、玻璃取 surface 的 .85/.72 与 .80/.62）。

**稿子自留的那处待盯，实测下来同样不用改**：它担心 事件（靛青×金褐）与 势力（灰蓝）只能靠色相分开，可六色里最近的一对，霜是 势力–概念 ΔE **0.081**、靛是 势力–概念 **0.057**——都高于各自最近的一对：纸 0.068（地点–概念）/ 夜 0.025 / 石 0.069 / 墨 0.047；它点名的 事件–势力 在深色侧 0.068、浅色侧连前三都进不去。所以靛这一对也**没有开任何手调**。

# 设计任务：在本项目里新建 `05j 第二套主题 Second Theme.dc.html`

（屏号从 `05j` 起，因为 `05i 主题 Themes.dc.html` 已被主题系统的界面稿占用；如果 `05j` 也被占了，往后取第一个空位并在回稿里说明。）

## 0. 这次不是画界面，是配一套色

应用已经有了主题系统：`05i` 那一屏能让作者把一份 CSS 丢进文件夹，它就和内置主题并排出现。缺的是**证据**——今天全应用只有一套主题：浅色的「纸」和深色的「夜」，一对暖赭石手稿色。系统能不能承住第二套，没人验过。

这一稿就是第二套，同时也是那次验证。**一个像素的结构都不许动**：`01a` 的三栏工作区、`05a` 的设置页、`03a` 的知识库墙全部原样，间距、字号、圆角、字体一律不碰——主题文件里根本写不了这些（校验器会丢弃）。这一稿唯一的变量是**颜色**。

## 1. 交付物

**一对**外观主题：浅色一张 + 深色一张。因为模式有「跟随系统」，一张浅的没有配对的深色就只能白天用；第二套要能整套换掉纸/夜。

交付的不是 CSS 文件（那个我照稿写），是：

1. **37 个核心令牌的两组最终值**（浅一列、深一列，十六进制或 rgba，可直接抄进代码）；
2. **把这两组值画在真实界面上的稿**，用来证明它们成立——尤其是那些颜色**不是**你直接给的、而是从这 37 个推导出来的界面（见 §4）。

## 2. 你需要知道的背景（不用读代码）

应用是一个中文写作工具：左边文件树、中间 Markdown 编辑器 + 预览、右边 AI 面板，另有知识库（条目卡片墙）、设置页、同步等界面。三根独立的切换轴：

- **外观主题**（本次）＝ 应用外壳的**颜色**，一份只声明设计令牌的 CSS，有明暗极性；
- **字体方案**（宋 / 黑 / 楷 / 手稿）＝ 另一根轴，主题管不着；
- **Markdown 排版主题**（文档正文的排版）＝ 第三根轴，本次不做。

三条应用级规矩不随主题变，第二套照旧遵守：**全局零圆角**（稿面读作裁下来的纸，不是圆角卡片；只有状态圆点、加载圈、单选点是圆的，开关旋钮是方的）、**单一克制强调色**（一个强调色贯穿全应用，交互元素上不用多色渐变）、**分层阴影**（层次靠阴影不靠加边框）。

## 4. 最要紧的一条：其余 176 个令牌是**推导**出来的

应用里还有 176 个令牌（AI 面板的角色色、设置页的 `--stg-*`、知识库的 `--lore-*`、同步的 `--sync-*`、扮演的 `--rp-*`…）。内置的纸/夜为它们保留了一份**手调值**——但那份手调只对纸/夜生效。**第二套主题拿不到它，全部 176 个从这 37 个推导出来。**

所以这 37 个不是「够用就行」，它们是整张应用的种子。几条真实推导式，好让你知道后果：

- **设置页整张纸**：`--stg-bg = bg-base 掺 45% 白`、输入框 `= bg-surface 掺 60% 白`（深色侧是相应地掺黑）。也就是说设置页永远比工作区亮一档——**你的 `bg-base` 如果本身就很亮或饱和度很高，那一档会掺成惨白或脏色。**
- **知识库的六色分类**：角色 `= sienna`、地点 `= success`、物品 `= amber`、事件 `= sienna 与 amber 的 oklab 混合`、势力 `= text-secondary`、概念 `= type-video-fg`。**你选 `--color-success` 和 `--color-type-video-fg` 的时候，实际上是在选「地点」和「概念」两个分类的颜色**；这六个推完必须仍是**六个分得开的色**，这是这次配色最硬的一处约束。
- **选中与悬停**：`accent-tint = sienna 12% 透明`、`accent-tint-strong = 23%`，选中态用它们，**悬停**用中性的 `bg-hover`。tint 太淡则选中看不见，太浓则悬停像选中。
- **警告文字**：`warning-text = warning 与 text-primary 的 oklab 混合 40%`；标签文字 `= sienna 与 text-primary 混合 45%`。**warning 选得太浅，混完就是一摊泥。**
- **焦点环**：`= sienna 32% 透明`的 2px 环，落在任何底上都要看得见。

**这条直接决定这一稿要画什么**（§6）：只画 `01a` 主界面是不够的，必须画那些颜色是**推出来的**界面——设置页的开关、知识库的分类点、同步的风险条。哪一处推垮了，就回来调那 37 个里的某一个，**不允许**「这个界面单独给个值」：那正是第二套主题证明不了的事。

## 5. 性格：第二套该是什么

这是这一稿唯一开放的决定，也是它的价值所在。

纸/夜是**手稿**：暖米纸、赭石强调、褐墨字。第二套必须与它**拉得开距离**——作者在 `05i` 的网格里一眼就要看出这是另一套东西，而不是「纸的另一种米色」。同时它不能背叛应用：零圆角、单强调色、克制的分层，这些不是纸的性格，是应用的。

**TURN 1 先不要铺开**：给 3 个方向，每个方向一块调色板（那 37 个里的关键 12 个左右）+ 一张 `01a` 主界面缩略图 + 一句「为什么这个方向对写作工具成立」，并**推荐一个**。我选定之后你再铺开画全部屏。

可以从这些里挑，也可以不用：冷灰石墨（现代编辑器的中性）、低饱和青绿（长时间写作的护眼）、高对比近黑白 + 单一强调（极简）、靛蓝夜色（以深色为主角，浅色那张是它的白天）。

**不要**做的：多色渐变、彩虹强调、把强调色换成纯饱和红或纯饱和蓝（它要同时当 1px 线、填色底、焦点环三种用途）。

## 6. 要画哪些屏

按 `01a` / `05a` / `03a` 已有的结构照画，只换色。

- **1a 主界面 · 浅** —— 三栏（文件树 / 编辑器 + 预览 / AI 面板）、标题栏、底部状态条。这一屏中英各一份，其余屏中文即可。
- **1b 主界面 · 深** —— 同上。
- **1c 设置页**（照 `05a`）—— 必须含：开关 ON 与 OFF、输入框、分节卡片、chip、一行危险操作。**这一整屏的颜色是推导出来的**（`--stg-*` 掺白/掺黑），最容易垮，所以它是验收面而不是装饰。
- **1d 知识库墙**（照 `03a`）—— 六色分类点 + 条目卡片 + 集合的装订线，浅 / 深两半并排。判据只有一条：六个分类色分得开吗。
- **1e 令牌对照表** —— 37 个核心令牌的两列色卡（浅 / 深），每个带令牌名、最终值、一句角色说明。**我会直接照这一屏写 CSS**，所以这里的值必须是最终值，不能是示意。
- **1f AI 面板** —— 一条流式输出 + 一张审批卡 + 一个模型选择行：强调色、选中 tint、警告色、八个类型色里的两三个同屏出现。
- **1g 极端情况一屏** —— ①一整屏正文的编辑区（久读的对比度）；②模型列表（八个类型色同屏）；③同步的风险条（error 与 warning 同屏，必须一眼分得出哪个是错误）。
- **1z 决策注记** —— 每个色为什么是这个值、放弃了什么、以及下面这张对比度实测表。

## 7. 硬约束（不满足会被打回来）

- **一张主题只有一个极性**，浅那张必须真的浅、深那张必须真的深——「跟随系统」白天会切到浅那张，一张偏暗的「浅色」主题会在正午刺眼。主题里不能带 `prefers-color-scheme` 分支。
- **对比度（在自己的底上实测并在 1z 列出数字）**：`text-primary` ≥ **7:1**（正文是久读的）、`text-secondary` ≥ 4.5:1、`text-muted` ≥ 3:1；`faint` / `ghost` 是装饰级，不承载信息，但必须看得见。
- **`sienna` 在 `bg-base` 与 `bg-surface` 上都 ≥ 3:1**——它不只填色，还要画 1px 边和细线。`sienna-hover` 要读得出「按下去了」：浅色主题里通常更深，深色主题里更亮（夜的做法就是更亮）。
- **三个语义色不能被主题的性格吃掉**：错误必须一眼是错误。但它们同时参与推导（`success` ＝地点分类色、`warning` ＝要混进文字色），所以也不能是刺眼的纯红纯绿。
- **八个类型色**：每个 `-fg` 在自己的 `-bg` 上 ≥ 4.5:1，四个色相在同一行列表里要分得开。
- **五档阴影**要在真实卡片上看出四层差别；说明它们带什么色（纸带暖褐、夜是纯黑加深）。
- **不要发明令牌**：这 37 个之外的名字装不上（校验器会丢弃并计数，卡片上会显示「已忽略 N 条规则」）。
- **不要画主题选择界面**——那是 `05i`，已经有了；这一稿只在 1e 里以色卡形式出现。
