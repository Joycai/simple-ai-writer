## 需求梳理

### A · ⌘K 升级成全局搜索

1. **搜文档**（项目目录内所有非隐藏文件，按文件名 + 路径段匹配，VS Code ⌘P 式子序列匹配）→ ↵ 在编辑器打开，**文件树自动定位到它**（展开 + 滚动 + 选中）。
2. **搜条目**（名字 / 别名，跨全部分类）→ ↵ **切到知识库墙并打开那张条目**（`setMainView("lore-wall")` + `openDetail(dirPath)`，和导航历史回放走同一条路），不再在编辑器里打开 index.md。阅读/管理模式沿作者偏好。
3. **当前文档正文**保留为第三组，↵ 要真的跳到那一行（需要编辑器暴露一个 goToLine；实现时核对 `editorStore` / CodeMirror 包装有没有现成的）。
4. **AI 操作组**保留，位置和显隐由设计定（有查询词时才有意义）。
5. **前缀 / 作用域**要么真做要么删掉：`/` 条目、`?` AI 已画在界面上；文档需要一个新前缀（`@` 已被对话里的引用占用）。也可以用 Tab 在「全部 / 条目 / 文档 / 正文」之间切。
6. **空查询**改成「最近去过的地方」：`navStore.past` 本会话记录了每次落点（视图 + 文档 + 条目），不跨会话；比「知识库前 6 条」有用得多。
7. **没打开项目**时的空态（现在 ⌘K 照样弹出一个空面板）。
8. 结果上限与「更多」；匹配高亮沿用现有 `itemHl`。

### B · 文件树「定位当前文档」常驻按钮

1. 工具栏**视图组**（「全部折叠」旁）加一枚常驻 `Crosshair` 按钮，IDEA / VS Code 的肌肉记忆。
2. 三态：无打开文档 → 禁用；当前文档已在视野 → 点了也选中 + 滚到中间（不是 no-op）；看不见 → 展开 + 滚动 + 选中。
3. 工具栏在最窄档（<220px）只有 116px 给 7 枚图标，第 8 枚放哪、谁退回 ⋯ —— 设计定。
4. 脚线的「定位」条**去留由设计定**：它说的是「当前文档现在不在视野」这个**状态**，按钮说不了；但两处同一动作是重复。
5. **打开即定位**：树外面打开的文档（搜索、导航后退、引用跳转）默认自动定位——行为改动，不需要设计，本文记一笔。

## 数据边界（设计不能画出不存在的东西）

- **文档**：树节点只有 `{名字, 路径, 是否目录, 子节点}`（`FileNode`，`lib/project`）。没有修改时间、大小、字数；没有内容预览（要读文件）。隐藏文件与 `.ai-writer/` 不在树里。种类只按后缀判（`lib/fs/images` 的分类：可写可读 `.md/.txt/.html`、导入原件、图片、`assets/`）。
- **跨文档全文搜索本期不做**：要把整个项目的文件读一遍；作为后续一片（带索引）单独立项。当前文档正文行可搜（已在内存里）。
- **条目**：`LoreEntity` 有 `name / aliases / summary / category / collections / avatarPath / dict`；分类有名字和颜色（**分类用颜色，集合用装订**——`docs/reference/design-system.md`）。没有修改时间。搜索匹配 `name` + `aliases`，`summary` 只显示不参与匹配（实现时可放开）。
- **最近去过**：`navStore.past`（≤100 条，`{kind: editor|lore|library, filePath|entityDir}`），**只在本会话**。要跨会话的「最近打开文档」需要新增一行偏好 —— 如果设计需要，单独列出来。
- **打开条目**只能到知识库墙的详情（阅读 / 管理随偏好）；打开文档只能到编辑器；两者都会**切换主视图**。
- 快捷键：⌘K 已占（开关面板）；⌘P **未占**，可作「直达文档」别名；⌘F 是编辑器内查找；⌥⌘L 是定位当前文档；`@` 在对话里是引用前缀。
- 命名一律用应用词表：**文档 / 分组 / 知识库 / 条目**（`useTerms()`），不写「设定 / 词条 / 章」。

#### 第一片实现记录（2026-09-03）

照上表落地，两处与计划有出入：

- **树外打开的判定用的是 ref，不是「谁调了 store」**：树自己的两条打开路径（行点击、右键
  「打开」）先把路径写进 `treeOpenedRef` 再 `setActiveFilePath`；effect 看到的 `activeFilePath`
  不等于 ref 记的那一个，就是外面开的。ref 以挂载时的值初始化，所以切侧栏标签不触发。
- **面板打开文档时也显式调一次 `revealPath`**：树挂着时和 effect 重复，代价是同一行再居中
  一次；树不挂着（侧栏在别的标签）时这是唯一一次——展开先落进 store，滚动等树挂回来按
  `seq` 兑现（`consumedRevealSeq` 是模块级的，卸载再挂回不会把旧请求再跑一遍）。

vite 预览里灌假数据实测过：文档按名字 / 分组路径命中并排序（名字命中在前，短路径在前）·
条目按名字与别名命中、点击切到知识库墙并打开详情 · 正文行命中带行号与片段 · 打开一个
三层深的文档后树自动展开到它、选中并居中 · 空查询列出上一处「最近去过」且不含当前位置。
**没在浏览器里验到的**：正文 ↵ 跳行（要一个真挂着的 CodeMirror，浏览器里文件读不出来）
和 `pendingJump` 那条（从知识库墙按 ⌘K 跳正文）——留给真机。

# ⌘K 全局搜索 + 文件树「定位当前文档」—— 设计任务书

请**新开一屏** `21 全局搜索 Global Search`（20 是滑块）。第 1 组画板是命令面板，第 2 组画板是文件面板工具栏的改动——后者请在 `17 文件面板` 的语言之上改，不要另起一套。

## 0. 这是什么应用

桌面写作应用（Tauri + React），面向小说 / 跑团 / 文案 / 周报作者。视觉语言是
**「手稿」**：深色墨底或浅色纸面，衬线正文，**单一赭石色**（`--color-accent`
浅 #A0522D / 深 #D9925B）是唯一强调色，**全局零圆角**（圆形只留给状态点、头像、
spinner），层级靠背景深度 + 1px 细线，不靠描边和阴影堆叠。悬停用**中性底**
`--color-bg-elevated`，**选中**才用赭石 tint。

界面词表固定：**文档**（一个文件）· **分组**（文件夹）· **知识库**（这个项目的
设定 / 资料库）· **条目**（知识库里的一条，如一个人物、一个地点）。不要写
「设定」「词条」「章节」。

行：`9px 18px` 内距，hover / 当前项 `--color-bg-elevated`；标题 13px 衬线 500；
命中片段高亮 `--color-mention-bg` 底 + 赭石字。

**它的问题**（这也是这一期的全部理由）：

- **搜不到文档**。占位文案说「搜索文稿与条目」，实际只搜条目名/别名，和**当前打开的那一篇**的正文行。
- **打开条目去错了地方**：它把条目的源文件在编辑器里打开，而不是去知识库墙上打开那张条目。
- **正文命中按 ↵ 没反应**。
- 右上那两枚 `/ 条目` `? AI` chip 和脚线那句「前缀限定范围」**是假的**，代码里没有前缀。
- 空查询时列出「知识库前 6 条条目」，没有任何理由。

## 2. 这一期要做成什么

一个**全局搜索**：一个输入框，三类结果，↵ 直达。

| 类 | 搜什么 | ↵ 去哪 |
|---|---|---|
| **文档** | 项目目录里所有文件，按**文件名 + 所在分组路径**匹配（VS Code ⌘P 那种：`ch3 ren` 能命中 `第三章/人物小传.md`） | 编辑器打开它，**同时文件树展开到它、滚到它、选中它** |
| **条目** | 知识库全部分类的条目，按名字 + 别名 | **切到知识库墙，打开这张条目**（阅读或管理模式随作者偏好） |
| **正文** | **当前打开的那一篇**的正文行（跨文档全文搜索本期不做，见 §5） | 编辑器光标跳到那一行 |

另加一组 **AI 操作**（问 AI / 打开对话 / 核对一致性），只有输入了词才有意义——
放哪、是否折叠，你定。

### 1a · 有查询词，三类都有命中

## 4. 文件面板：「定位当前文档」常驻按钮

### 现状

「定位当前文档」这个动作**已经存在**，三个入口：

1. 面板底部 22px 脚线——**只在当前文档看不见时**（被折叠掉，或滚出视野）变成一条
   赭石字的「⌖ 文档名」，点它展开 + 滚到中间 + 选中。这是 17 稿的决定：脚线三件事共用
   （计数 / 剪贴板 / 定位），永不叠加；
2. 工具栏 ⋯ 菜单第一项；
3. 快捷键 ⌥⌘L。

### 2a · 按钮放哪

### 2b · 三态

## 5. 数据边界（请不要设计出画不出来的东西）

- **文档**：树节点只有 `{名字, 路径, 是否目录, 子节点}`。**没有**修改时间、大小、
  字数、内容预览；隐藏文件和 `.ai-writer/` 不在树里。种类只按后缀判。
- **跨文档全文搜索本期不做**（要读整个项目的每个文件）。只有**当前打开那一篇**的正文行可搜。
- **条目**有：名字、别名、一句摘要、分类（有名字有颜色）、所属集合、头像（可能没有）。
  **没有**修改时间。
- **最近去过**只在本会话；要跨会话的「最近打开文档」需要新加一行持久化——如果你的
  设计需要它，**单独列出来**，我会评估代价而不是默默砍掉。
- 打开条目只能去知识库墙的详情；打开文档只能去编辑器；两者都会切换主视图。
- 从搜索打开文档后，**树自动定位到它**——这是行为，不需要画；但 2b 的「已在视野」态
  因此会更常见。

如果设计需要上面某样不存在的东西，请单独列出来并说明它值不值得。

## 6. 必须遵守的约束

- **零圆角**；唯一强调色赭石；hover 中性、选中赭石 tint。
- 颜色一律标 **token 名**（`--color-text-faint`、`--color-border-soft`、
  `--color-bg-elevated`、`--color-accent-tint`…），不要给裸十六进制；确实需要新颜色时
  说明它映射到既有的哪个角色，并**同时给浅/深两套**。
- 命令面板**保持零动画**（只有 80ms 遮罩淡入）；工具栏按钮的悬停/按压是纯 CSS，
  `prefers-reduced-motion` 下退化。
- 三种字体角色：Spectral 衬线（`--font-serif`）给条目名、文档名、正文片段；
  Inter Tight（`--font-sans`）给 UI 标签 11–13px；JetBrains Mono（`--font-mono`）给
  **每一个**数字、行号、快捷键提示、路径。
- 图标全部来自 lucide。
- 不弹模态。
