# Mac App Store 上架审查与分阶段改造计划

> Status: `partial` — P0 已实现；P1 的项目书签、重新授权与渠道身份隔离已实现，见 §8。P2 告知 / 同意 / 撤回与联网边界已实现，见 §9；P3 功能边界、固定架构构建与静态审计已实现，见 §10；P1 / P2 / P3 原生验收、政策发布及正式签名仍待完成；P4 本地准备已实现，见 §11；P5 本地测试 / 提审准备已实现，见 §12，正式上传、TestFlight、提审与发布待完成。
> 范围：macOS 的 Mac App Store；不包含 iOS 移植。保留现有站外分发渠道。

## 1. 已确认的产品决策

- **双渠道共用代码库**：现有站外版继续维护，新增独立商店构建配置。不要把商店的功能限制全局施加到站外版。
- **商店版禁用终端，降级到 tools**：保留应用原生、结构化的读写与导出工具及其审批机制，移除通用 shell 执行能力。这里的 tools 是功能边界，不假定现有代码已有同名模式枚举；也不表示取消写入审批、缩减为只读工具，或调整能力包的工具等级。
- **优先级**：先建立可测试的沙盒构建和渠道边界，再完成持久文件授权与隐私流程；这些通过后才进入商店材料、TestFlight 与提交。
- **终端禁用是构建能力约束**：不能只隐藏开关或依赖默认关闭。旧偏好、导入备份、历史会话和恢复任务均不能重新打开终端能力。
- 首次上架不自动引入自营 AI 额度、订阅、应用账号或 IAP；商业模式另行决定。

理由：应用的主体价值是本地编辑与受控 AI 工具，不依赖通用终端。将终端留在站外版能缩小商店版的沙盒适配与审核范围，同时保留已有用户的能力。双渠道只分离发行策略，不复制整套业务实现。

补充判断：

- `src/lib/mcp/client.ts` 是 Streamable HTTP 客户端，不能将 MCP 等同于本机终端；保留与否按数据流、工具权限和实际行为评估。

## 3. 分阶段实施

依赖顺序：**P0 → P1 → P2 → P3 → P4 → P5**。隐私政策和数据清单可以在 P1 期间准备，但不能因此跳过 P1 的文件授权验收。每阶段完成后更新本文状态与验收记录；没有真机证据时保留 `unverified`，不写成已完成上架准备。

### P0：建立渠道边界与最小沙盒包

交付：

1. 新增商店专用 Tauri 配置、entitlements 和独立构建命令；默认站外构建保持原有功能。商店包记录明确渠道，前后端读取同一构建来源，用户偏好不能覆盖它。
2. 接入开发测试所需的签名身份和描述文件，构建能启动的沙盒 `.app`；发行证书、签名 `.pkg` 与上传自动化在 P4 完成。证书和私钥不入仓库。
3. 逐项记录 entitlement 的功能依据：App Sandbox、出站网络、用户选择文件读写，以及后续书签和打印所需权限；不以全盘权限或临时例外替代文件授权设计。
4. 商店版终端能力设为不可用：设置入口、schema、提示词、工作流指引、工具路由、审批执行、任务恢复均不得承诺或执行 shell。Rust 通用命令执行入口不注册或在商店构建中编译排除；纯只读 shell 快路径也在禁用范围内。
5. 对旧会话 / 待审批命令给出明确不可执行状态，取消或阻断对应步骤；不得将 shell 文本自动转译为已批准的 tools 操作。后续重新规划仍须遵守原生工具的授权规则。
6. 审查模式选择 / 能力回退点，商店版有效能力收敛到 tools。保留站外偏好原值，不因在商店版加载备份就破坏站外终端配置。

验收门槛：两个渠道均可构建；商店包签名中可查到沙盒 entitlement；篡改偏好、导入旧备份、恢复终端任务和直接 IPC 调用均不能启动 shell；站外版终端原有测试继续通过；工具在场性与预算守卫通过。

### P1：持久文件授权、容器及迁移

交付：

1. 建立 macOS 文件授权模块：系统选取 → 创建 security-scoped bookmark → 持久存储 → 重开解析 / 开始访问 → 完成后释放；处理过期、移动、删除、撤销及失效书签。序列化书签不写入可跨机器同步的项目配置。
2. 先恢复系统授权，再检查项目标记、注册内部 `FsScope`，最后打开文件和数据库。书签不替代内部路径围栏；内部白名单也不能扩大 OS 授权。
3. 授权失败时请求重新选取原目录并保留历史记录，不把权限错误误报为项目损坏，也不自动创建空项目替代旧项目。
4. 覆盖最近 / 固定项目、启动恢复、多实例、项目内 `.ai-writer`、图片协议、外部附件、另存为、导出、备份和目录监听；对符号链接目标单独检查访问边界。
5. 实测原生打开 / 保存对话框对插件、自定义 Rust I/O 和 SQLite 的授权传播，不假定依赖会自动持久化权限。
6. 决定双渠道 Bundle ID、appData 和 keychain 身份关系，记录并存 / 替换行为及理由；不可盲目更改现有站外 Bundle ID。旧数据迁移经用户选择与授权，只复制 / 导入并可重试，不破坏原数据。

验收门槛：首次选择 → 编辑保存 → 完全退出 → 最近项目重开成功；重启系统与多实例重复通过。覆盖中文 / 空格路径、外置磁盘、iCloud 目录、目录移动与授权失效。拒绝授权不丢数据；资源访问有配对释放；新安装、站外迁入和升级均有明确结果。

### P2：隐私政策、数据流与发送前授权

交付：

1. 建立数据流清单：对话、正文 / 检索片段、知识库、附件、图片、音频、embedding / rerank、翻译、模型探测、MCP、同步 / 配置备份、字体下载。逐项记录触发点、接收方、内容、凭据、保留 / 删除方式及是否后台发送。
2. 发布可访问的隐私政策，应用内提供固定入口；说明本地数据、第三方处理、删除与撤回、联系渠道。实际行为、文案与商店标签保持一致。
3. 在发送前明确告知提供商及实际端点、数据类别和自动上下文范围，记录版本化同意。原生工具审批、费用确认和隐私同意是不同维度，不能互相替代。
4. 明确授权粒度及失效规则：服务端点 / 接收方、数据用途或告知内容实质变化时重新确认；仅模型名变化是否重询取决于接收方和用途是否变化，避免无意义重复弹框。
5. 拒绝不阻断本地编辑；撤回后阻止后续发送，处理中请求尽力取消，并说明已经发出的数据无法由本地撤回。自动重试、子代理、嵌入、探测和后台同步不能绕过授权。
6. 本机 / 局域网服务也明确显示实际接收地址，不能仅凭 localhost 标签声称内容永不外传。MCP 按服务器 / 数据范围处理授权，服务端动作审批继续独立保留。
7. 同意记录按本机保存并遵守 `PREF_KEYS` 及配置备份边界；导入备份或迁移配置不能自动授予新机器的数据分享许可。

验收门槛：拒绝 / 未授权时对应网络发送为零；授权后只向所披露的目标发送；撤回、换端点、重试、恢复任务、多实例和子代理路径均有测试。中文与英文文案通过术语检查。政策 URL 可访问且覆盖实际数据流。

### P3：完整沙盒回归与首发范围冻结

交付：

- 在正式打包的沙盒应用中验证编辑、项目数据库、图片、导入导出、打印、字体、通知、网络与钥匙串；不要以 `pnpm dev` 或非沙盒开发进程替代验收。
- 确认最低 macOS / WebKit 版本、Apple Silicon 与 Intel 的支持范围；只有实际承诺的架构需要发布，并与产物、系统声明和测试矩阵一致。
- 测试首次安装、升级、离线、IPv6 网络、拒绝权限、流式中断、磁盘不可写和应用退出。确认没有未经同意继续运行的后台进程。
- 逐项冻结实验室功能范围，未达到正式质量的功能从商店构建排除；不通过仅改掉 Beta 标签掩盖缺陷。
- 检查最终 bundle 的签名、entitlements、资源、描述文件、依赖及 Privacy Manifest 适用要求；运行仓库对应的前后端合并门禁。

验收门槛：P0–P2 的关键失败路径有记录；没有数据丢失、授权绕过或核心操作失败；每个保留功能都有可复现的审核操作路径；站外版通过回归。

### P4：商店签名流水线与提交材料

交付：

- 注册 / 确认 App ID 与 App Store Connect 记录，匹配最终 Bundle ID；接入商店分发签名、描述文件、安装包证书与 `.pkg` 验证 / 上传。站外产物继续走独立发布路径，商店包的更新由 App Store 分发。
- 明确 marketing version 与递增 build number，避免同版本重传冲突；应用版本变更继续使用 `bump-version` skill，不手改四份清单。渠道差异不复制版本来源。
- 设置应用分类、支持系统、截图、描述、支持 / 隐私地址、联系方式、年龄分级、发行地区及价格；AI 需要用户配置服务及可能产生第三方费用应准确说明。
- 根据数据清单填写 App Privacy；核对加密出口问卷及必要材料，记录判定依据，不预设 AES-GCM 必然需要或必然不需要额外申报。
- 完成字体、图标、依赖、示例内容授权核查；按发行地区检查额外材料要求。若引入销售额度或订阅，先另行评审 IAP 与当地规则。
- 准备样例项目、非显而易见功能的审核说明，以及可用、限额、可撤销的审核专用服务凭据或经认可的演示安排；不将真实作者数据或生产密钥放进样例 / 包内。

验收门槛：签名包通过上传处理，App Store Connect 必填项完整，审核环境可以实际体验声明的功能，所有密钥在受控环境管理。

### P5：TestFlight、正式提审及后续维护

交付：通过 TestFlight 在干净用户环境执行完整验收，再提交正式审核。记录构建号、测试环境、问题、修复和审核反馈。审核反馈先定位具体规则与行为，不扩张权限或隐瞒功能绕过检查。

验收门槛：作者确认首发范围与商店资料；阻断问题关闭；审核通过并按作者选择的时间发布。项目协作仍做到 PR 已开、CI 已绿为止，由作者合并；本文不授权自动发布或操作开发者账户。

## 7. P0 实施记录（2026-11-04）

### 渠道与启动

## 8. P1 实施记录（2026-11-04，2.0.11）

### 身份与迁入决策

作者选择双渠道独立身份、支持并存。商店配置覆盖 Bundle ID 为 `com.simple-ai-writer.app.appstore`，应用名称为 **Simple AI Writer Store**，避免安装到 Applications 时覆盖站外 `.app`。站外身份、名称和构建入口不变。Tauri 的 appData / appLocalData 与实例注册目录随身份分开；macOS 钥匙串 service 同样分开，商店的读取、旧条目归并和清空都只处理商店 service，不枚举或删除站外密钥。

迁入采用已有的显式流程，不自动扫描站外容器或复制数据库：

1. 在站外版导出配置备份，需要迁入密钥时由作者显式勾选；在商店版通过原生文件选择器导入。沿用已有按 ID 合并、可重试的配置导入逻辑，不修改来源备份或站外数据库。
2. 在商店版选择原项目目录，创建本机授权。项目文件仍在原位置；打开项目会沿用现有的结构补齐和数据库升级逻辑，因此它是继续使用项目，不是创建独立副本。需要两份独立数据时先导出项目备份并恢复到另一个空目录。
3. 最近 / 固定路径与书签不跨机器同步；旧版本留在本机的路径会进入重新授权流程。两个渠道共用项目文件时仍受项目内窗口锁保护，不取消原有的重复打开提示。

### 授权与恢复链路

`bookmarks.rs` 只在 macOS + `app-store` 编译。增加 `com.apple.security.files.bookmarks.app-scope`，不增加临时例外或广泛文件权限。

- **首次选取**：Rust 原生文件夹选择器 → 用 NSURL 创建 security-scoped bookmark → 解析并 `startAccessingSecurityScopedResource` → 持久保存 → 内部 FsScope / plugin-fs 注册。保存失败会拒绝继续，不宣称已获得重启后的访问能力。
- **最近 / 固定 / 启动参数**：本机书签读取 → 无 UI、无自动挂载解析 → 开始 OS 访问 → 检查真实路径和 `.ai-writer` → 内部 scope → 锁、项目文件、SQLite。启动参数和“新窗口”入口在商店版不再提前探测尚未授权的目录；子进程恢复自己的授权。
- **过期与移动**：过期书签在访问有效时刷新；使用解析后的路径打开项目，保留旧路径的书签别名。成功打开后迁移最近记录及固定状态；失败或取消不删除旧记录。活动进程中若移动后旧 URL 无法访问，或书签已损坏 / 撤销 / 丢失，走重新授权；不会以旧路径创建空项目。
- **重新授权**：解释访问需要恢复，确认后选取原目录。Rust 比较选择结果与原目录、确认项目标记，选错目录不保存书签、不注册根、不创建文件。取消保持当前项目和历史。若目录已移动且旧书签不可恢复，提示通过“打开文件夹”选择新位置。
- **符号链接**：从已授权父目录恢复子项目时，canonicalize 后必须仍位于该授权目录内；原有 FsScope 对每次自定义文件操作的 symlink / `..` 围栏保持。商店版的 `.ai-writer`、SQLite 文件及 sidecar、窗口锁和初始化目录另行拒绝符号链接（包括悬空链接），避免元数据写入借用另一个已授权根或应用配置目录；选取的项目根本身可以是可解析的符号链接。

书签存放在商店 `appLocalDataDir/security-scoped-bookmarks/`，每个路径用 SHA-256 命名一个二进制文件。每项通过同目录临时文件 + rename 原子替换；不同进程更新不同路径不会覆盖整张授权表。同一项最后一次完整写入生效。它是原生本机安全凭据，不是用户偏好，不进入 PREF_KEYS、配置备份或项目 `.ai-writer`，不把书签字节传给 WebView。

### 授权生命周期与文件入口

显式 security-scope lease 在 Rust 持有，重复恢复同一路径复用 lease，替换时释放旧 lease；错误分支由 RAII 释放刚开始的访问。进程退出先清理项目窗口锁，再清空 lease，`stopAccessingSecurityScopedResource` 与成功 start 配对。刻意不在 UI 切换 / 关闭项目瞬间 stop：现有 SQL 插件连接池、异步保存、图片请求和主题监听可能仍在使用该路径，`resetDb()` 也只是清缓存，不是关闭连接池。当前授权单位是进程会话；若未来改为关闭项目即撤销，必须先建立后台任务排空和数据库池关闭屏障，再同时回收两份内部 scope，不能只提前 stop OS 授权。

| 入口 | 本次处理 / 边界 |
|---|---|
| 最近、固定、启动参数、多实例 | 统一走项目授权恢复；任意路径参数自身不授予权限 |
| `.ai-writer`、SQLite、项目图片与旧 asset 协议 | 项目授权成功后才打开；保留自定义 FsScope 与 plugin-fs 的隐藏目录授权 |
| 项目备份恢复 | 复用原生目录选择器保存目的目录授权，解包后可重开；父目录授权可恢复其真实子项目 |
| 外部导入、图片 / 音频附件 | 现有原生选取后读取或复制入项目的流程保留；不为一次性来源额外建立持久权限 |
| 另存为、导出、配置 / 项目备份 | 原生保存 / 打开对话框的会话授权继续用于本次 I/O；不扩大为父目录永久权限 |
| 目录监听 | 现有项目主题监听依赖项目会话授权；没有新加全项目监听 |

以上是代码路径覆盖，不等于所有原生插件已完成沙盒交互验收。最终的 SQLite、插件 I/O、导入导出、打印、监听权限传播必须在实际包内验证。

### 同意与撤回的实现决策

- `lib/privacy/consent.ts` 是 HTTP 下层门禁，只依赖编译渠道；UI / 存储适配器在启动时注入，避免 `http → prefs → project → AI → http` 的循环。商店 / 未识别渠道在初始化缺失、DB 读取失败、无许可、拒绝或暂停时均不发送。站外版跳过这一流程，保留原有发送与重定向行为。
- 原生确认框显示实际接收地址、用途、数据类别、自动上下文、后续 / 后台请求范围、第三方保留及本地服务可能转发的事实。设置 → 关于提供离线可读的中英文隐私说明、撤回并暂停、允许再次询问。公开政策发布前，此入口是应用内说明，不能代替 App Store Connect 的公共 URL。
- 同意键包含告知版本、用途、scheme / host / port 和路径范围。一般请求使用精确路径；Gemini 模型名和任务轮询 ID 使用显示出的模板；知识库 / 配置操作按同一 API 根覆盖其资源；固定字体按站点授权，备用站点重新询问。不同 base 路径、主机、端口、用途或告知版本重新确认；模型名本身不改变常见对话端点的许可。查询参数、认证头和正文不落入同意记录，也不显示在原生提示框；同一路由的请求参数属于已告知数据范围。
- `privacy:consent:` 在 `PREF_KEY_PREFIXES` 注册，每项独立存放，避免不同接收方并发更新整表；`app:privacyControl` 在 `PREF_KEYS` / machine-local 列表注册。保存含版本、时间、允许 / 拒绝及控制代次。导入与导出均排除这些本机记录，项目配置不携带许可。保存确认失败不发送，不回退到 localStorage。每次发送用 `readPrefConfirmed` 读取共享 DB，不依赖焦点刷新或内存许可。
- 拒绝也持久记录，自动重试不会反复弹相同确认框。“允许再次询问”轮换代次，下一次请求重新确认；它不直接许可或启动请求。“撤回并暂停”持久暂停全部用途，即使重启也保持暂停，本地编辑不受影响；同进程立即中止活动请求，写盘失败时该窗口仍保持暂停并显示失败。
- 同一窗口并发请求共用同一目标的待确认结果，原生弹框串行展示；迟到确认须再次核对代次。另一进程在每次发送前读共享记录，活动请求每 500ms 检查并尽力 abort，DB 失败同样取消。请求发出与另一进程撤回之间不存在跨网络事务，已发送数据无法收回；500ms 轮询和 OS 调度是取消的实质边界，不宣称远端任务一定停止。
- lease 持续到响应体 EOF / cancel，包括 SSE；原请求的取消信号保留。商店 HTTP 禁止自动重定向（原生 `maxRedirections: 0`），3xx 给出可读错误，需核实最终地址并重新配置 / 授权。可能依赖重定向的第三方服务需用最终端点，不能为了兼容自动转发敏感请求。
- 商店主 WebView 的 `connect-src` 仅允许应用 / IPC；HTTP 插件是联网入口。独立 HTML 预览与打印自定义协议增加无公网资源的 CSP，并限制导航到自己的协议，避免生成页面绕过授权联网。站外配置与窗口规则不变；依赖远程 CDN 的预览在商店版不会加载那些资源。用户主动在系统浏览器打开外部网页的行为仍交由浏览器处理。
