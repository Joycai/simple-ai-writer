## 实现与设计稿的三处出入

1. **文档名在窄档没有做「中段省」**，沿用今天的尾部省略号。设计稿写的「中段省（今天已有的做法）」是记混了——`middleEllipsis` 是 `@` 引用芯片的做法（它要把扩展名钉在右端），而面包屑里的文档名**本来就不显示扩展名**，中段省在这里换不来任何信息。项目名照做了尾省（窄档 `max-width: 10em`）。
2. **落盘失败那一格设计稿没画，实现里补了**：写盘失败时**文档不关**——缓冲区是那几行字唯一的副本，关掉等于替作者丢稿——痕迹改成琥珀色的「保存失败，未关闭 · 名字」。没有这一格的话，作者按下 × 之后什么都不会发生。
3. **「用默认应用打开」在窄档也不收成图标**（照表 A 的「永不动」一行）：它只出现在没有视图切换的那几类文件上，那一档右侧本来就空着。

## 实现落到哪里

- **新分类器** `lib/fs/docKind.ts`：`DocKind` 的五个值就是表 B 的五行，`isTextKind()` 决定字数 / 保存点 / 「已修改」在不在。刻意与 `isChapterFile`（大纲、书脊用的那个）分开：为大纲的理由放宽它，不该顺手给一个文件发一枚导出按钮。
- **文档段拆成 `DocActions.tsx`**：视图切换（宽/中三格连体 + 窄档一格下拉）、导出 / 打印 · PDF、图片尺寸、转换文档、用默认应用打开、字数 + 保存点。窄档的成色与宽档的成色**都渲染出来**、由容器查询藏掉一种——查询能换布局，换不了词（`design-system.md`）。
- **`TitleBar.tsx`**：`.flow` 那一格是让位的量程（平台让位留在它外面）；面包屑末尾的 ×、两秒痕迹、窄档的 ⋯ 菜单（主题 · 语言）。
- **`closeDocument()`（`editorStore`）**：三个入口共用；`⌘W` 进了 `useGlobalShortcuts` + `SHORTCUTS` 注册表（与 `⌘⇧W` 关闭项目成对），文件树右键的「关闭」只长在当前打开的那一行上。**mac 上 `⌘W` 起初到不了 webview**——菜单挂的 `PredefinedMenuItem::close_window` 固定带着它，而一个窗口就是一个工作区，于是「关文档」按下去关掉的是整个项目窗口。先补过一条 `⌃⌘W` 后备（2026-09-10），随后按 VS Code 的分层整理成三层并撤掉了它：**文档 ⌘W · 项目 ⇧⌘W · 窗口 ⌥⌘W**（窗口那一项在 `windowmenu.rs` 换成自定义菜单项，把 ⌘W 让回页面）。表在 `CLOSE_DOC_COMBOS` 的注释里。
- **`printHtmlDocument()`（`lib/fs/export`）**：`.html` 的唯一导出。整份文档解析、图片就地内联（打印稿没有 base URL）、**先摘掉 `<script>`**——打印稿没什么要跑的，而两个打印面（应用内同源 iframe 受 CSP 管、macOS 是自己的一个 webview）对「脚本会不会跑」的答案不一致；摘掉它，两边印出来的是同一页，也不碰「独立预览窗口是页面脚本真正跑起来的唯一地方」那条规矩。
- **图片尺寸**：`ImagePreview` 在 `img.onload` 时把 `naturalWidth × naturalHeight` 连同**路径**一起报进 `projectStore.imageSize`，顶栏比对路径后才显示——和 `WritingFocus` 防的是同一件事：一张图的尺寸绝不能挂在另一张图的名字下面。
- **单位词**：顶栏原来读的是「3,124 字数」/「3,124 Words」（`statusBar.words` 是个**栏目名**）。新增 `titleBar.words` / `titleBar.chars`，读成「3,124 字」/「12,480 字符」。
- **测试**：`docKind` 的五行 + 与导出口径不漂移（`exportScope.test.ts`）；`closeDocument` 的四条——干净直接关 · 脏的先落盘再关并留两秒痕迹 · 写盘失败不关 · 关图片时不碰缓冲区里那篇待写的文档（`editorStoreCloseDocument.test.ts`）。
- **浏览器里核过的**（vite dev，store 直接喂状态）：三档在 1440 / 1100 / 900 上各让掉哪几件、四类文件各自的名单、空态、英文窄档不折行不溢出、⌘W 与 × 的两条路径、窄档两个菜单。**没核到的**：Tauri 里才有的那两件——mac 菜单让位后 `⌘W` 是不是真的落到页面上了（本机是 Windows，`windowmenu.rs` 连编译都轮不到：应用的 CI 只跑 ubuntu，那个模块是 `cfg(target_os = "macos")`），以及 `.html` 的「打印 · PDF」真去调打印对话框那一步。Windows 侧核过：`Ctrl+W` 关文档、`Ctrl+Shift+W` 仍然是关项目、`Ctrl+Alt+W` 什么都不做。

## 发出去之前先核对过的事实

顶栏的实现在 [`TitleBar.tsx`](../../src/components/layout/TitleBar.tsx) + [`TitleBar.module.css`](../../src/components/layout/TitleBar.module.css)，动作的另一半在 [`ExportMenu.tsx`](../../src/components/layout/ExportMenu.tsx)、分发在 [`EditorArea.tsx`](../../src/components/layout/EditorArea.tsx)。

- **顶栏是整窗宽的**（`App.tsx`：`TitleBar` 在 flex 列的第一格，侧栏和 AI 栏都在它下面）。所以挤压跟面板宽度无关，只跟**窗口宽度**、面包屑的长短、以及无边框 Windows 右端那三个 46px 的 caption 按钮有关。窗口 `minWidth: 900`。
- **一次只有一个当前文档**，没有标签页：`projectStore.activeFilePath` 一个字段。文件树、命令面板（⌘P 的「文档」档）、一致性检查、批处理都往它上面写。**没有任何调用点把它置空**（只有关项目和删掉当前文件时会）。
- **`⌘W` / `Ctrl+W` 目前空着**（`useGlobalShortcuts.ts` 里没有它），`Esc` 已被「关命令面板 / 关 AI 抽屉」占用。
- **视图切换与导出原先对任何打开的文件都在场**——`activeFilePath` 非空就渲染，不看类型。由此来的三个真 bug **已在本分支修掉**（发任务书前就修了，下面的类型表是修完之后的现状）：
  - 打开**图片**时，编辑器缓冲区还停在上一篇文档（`EditorArea` 对图片不调 `loadFile`，这是有意的——AI 那一侧靠 `WritingFocus` 判断"还没就绪"）。此时点「导出」，导出的是**上一篇的正文**，文件名却取自图片名。→ 导出改成认 `WritingFocus`，不认 `activeFilePath`。
  - 同一原因，顶栏的**字数**（以及底栏的「累计 N 字」、保存点、面包屑的「已修改」）在图片打开时说的是上一篇的话。→ 改成只在打开的是文本文件时出现（当时叫 `isTextPath`，设计稿回来后并入 `docKind.ts` 的 `isTextKind`）。
  - 打开 `.html` 时导出也是错的：`lib/fs/export` 三条路径都先 `renderMarkdown(source)`，等于把 HTML 源码当 markdown 再渲染一遍。→ 新增 `isExportableDocument`（`md / markdown / txt`），`.html` 的导出**暂时撤下**，等本稿判它该有一套什么样的导出。
- **视图切换对图片完全无效**：`EditorArea` 走图片分支时根本不看 `viewMode`，三个按钮点了什么都不会变。**这一个没动**——撤下还是灰掉是本稿要判的事。
- 四类文件的现状见任务书里的表。可转换的 `docx / xlsx / pdf / pptx` 目前只有文件树右键里的「转换文档」，「用默认应用打开」只出现在「读不出来」那张说明页上。
- 关闭一个脏文档必须先落盘：自动保存是 2s 防抖（`editorStore.setContent`），`saveNow()` 是现成的同步出口。

# 设计任务：在本项目里新建 `01e 顶栏 · 文档动作 Doc Actions.dc.html`

## 这一屏是什么

`01a 工作区 · 编辑器 · 最近项目 Workspace` 顶上那条 48px 的横条，这次只画它，重点在**右半段**。今天从左到右是：

品牌菱形 → 面包屑（`项目 / 分组 / 文档` + 「已修改」）→ 弹簧 → 视图切换（`编辑 | 分栏 | 预览` 三格连体）→ `导出 ▾` → 细分隔 → `深色` → `中文` → 细分隔 → 字数 → 保存点 + `已保存` → 细分隔 → `AI · Ctrl+K` →（无边框 Windows 上还有）最小化 / 最大化 / 关闭。

这一串里有两种东西混在一起，而它们的命运不一样：**跟着当前文档走的**（视图切换、导出、字数、保存点、面包屑的文档段）和**全应用的**（主题、语言、AI）。本轮要动的只是前者，后者请原样沿用。

其余背景直接看 `01a`（工作区的纸色方言、空稿页）、`01b 文件面板（一）`（文档是从那棵树点开的）、`01d 全局搜索`（⌘P 的「文档」档是另一个打开入口）。不用重新解释产品。屏号从 `01e` 起是因为工作区组已经用到 `01d`。

## 这次要解决的四个张力

**1. 打开了就关不掉。**
应用没有标签页——一次一个当前文档，点树上另一个就换过去。作者的原话是「点击文件打开，但是没有地方关闭」。今天**没有任何地方**能回到 `01a` 画过的那张空稿页。要决定的是：关闭这个动作住在哪（面包屑末尾一个 ×？和视图切换、导出站成一组？只给快捷键 + 文件树右键？），它是常驻还是悬停才现身，以及**关掉之后顶栏右半段变成什么**——那一整组文档动作是整组消失（弹簧变长、主题/语言/AI 靠右），还是留在原地灰掉。前者会让顶栏在开关文档时"呼吸"，后者会留一排点不动的字，两种都请在 1z 里判一次。

约束：`⌘W` 空着可以用；脏文档关闭时**先落盘再关**，所以**不要**画「保存 / 丢弃 / 取消」三选一的模态——这个应用里没有「丢弃」这个概念（一直在自动保存）。如果你觉得作者需要知道"关的时候替我存了"，那是一行痕迹的事，不是一个模态的事。

**2. 动作应该按文件类型出现。**
原先只要有文件打开，`编辑 | 分栏 | 预览` 和 `导出 ▾` 就都在，不管打开的是什么——由此来的三处"替别的文件说话"刚刚在代码里堵掉了，但**堵法是临时的，这张表的最终形态归本稿判**：

| 打开的是 | 编辑区是什么 | 视图切换 | 导出 | 字数 / 保存点 |
|---|---|---|---|---|
| `.md` `.markdown` | 编辑器 + Markdown 预览 | 三档都成立 | 三条都成立（复制 Markdown / 存自包含 HTML / 系统打印出 PDF） | 在 |
| `.txt` | 同上，预览按 markdown 渲染 | 成立 | 成立，语义上是"当 markdown 处理" | 在 |
| `.html` `.htm` | 编辑器 + **沙箱 iframe** 预览（不是 markdown 渲染） | 三档都成立 | **暂时撤下**（原先会把源码当 markdown 再渲染一遍）。它该有自己的一套吗——复制源码 / 原样存盘 / 打印这个页面？ | 在 |
| 图片 `png/jpg/jpeg/webp/gif` | 整块只有一张图（可缩放） | **仍在，但全无效**，点了不变 ← 要判 | 已撤下 | 已撤下 |
| 读不出来的（`.docx` `.pdf` `.zip` 非 UTF-8…） | 一张说明页：重试 / 用默认应用打开 | 仍在，无效 ← 要判 | 已撤下 | 已撤下 |
| 什么都没打开 | `01a` 的空稿页 | 不在 | 不在 | **也不在了**（原先显示 `0 字 · 已保存`）← 请在 1d 里确认这一档 |

要一张明确的"谁在场"对照表：每一类文件，顶栏那一组里**留下哪几个**、留下的是撤走还是灰掉。空出来的位置补不补东西也请判一次——手上有两个现成的、今天藏在别处的动作：可转换的 `docx / xlsx / pdf / pptx` 有「转换文档」（现在只在文件树右键里），任何文件都有「用默认应用打开」（现在只在那张说明页上）。

**3. 窄窗口下右半段会挤变形。**
窗口最窄 900，顶栏是整窗宽，右边这一串在 900 上会被面包屑（项目名 + 分组名 + 文档名都可能很长）挤到变形；无边框 Windows 还要在最右端再让出 3×46=138px，mac 左端要让 56px 给红绿灯。**中文标签一旦被压到字宽以下会逐字折行**成「编 辑 / 分 栏」——这条 strip 唯一不能出的错，和 `05f` / 设定集模态 footer 是同一条纪律。

要一个明确的**让位顺序**：谁先收成图标、谁并进溢出菜单、谁改写文案（`已保存` → 一个点）、谁永远不动。面包屑那一侧也在这场竞争里：它今天靠中段省略活着，但项目名和文档名谁先省、`分组` 那一段什么时候整段消失，也请一起定。请至少给出宽 / 中 / 窄三档的分界宽度（真实数字，不是"小屏"），并说明这是靠窗口宽度判还是靠容器查询判。

**4. 英文更长。**
`编辑 | 分栏 | 预览` → `Editor | Split | Preview`，`导出` → `Export`，`已修改` → `Modified`。同一档宽度下英文这一串明显更长，最窄档必须两种语言都成立——**不要**用"英文时另设一档"来回避。

## 数据边界（应用真正知道的东西，别画它没有的）

- 文件类型**只能按扩展名判断**，没有嗅探。可渲染图片就是那五个扩展名；可转换的就是 `docx / xlsx / pdf / pptx`。
- 导出只有三条：复制 Markdown（走剪贴板）、存成自包含 HTML（选保存位置）、走系统打印对话框出 PDF。**应用里没有 toast**——导出的回执是按钮自己变成 `✓ 已复制` 停 2 秒，这是全应用唯一的成功回执，请沿用它，也别再发明第二种。
- 关闭 = 当前文档置空，**不是关标签**：没有"最近关闭"、没有"重新打开上一个"（返回历史里倒是有，⌘←）。
- 字数、保存点只有在文本文档打开时才是真的。
- 顶栏 48px；这条 strip 的字号是 12px（文字控件）/ 11px（视图切换、AI 按钮）；窗口 `minWidth 900 / minHeight 600`。
- 三种窗口边框形态都要照顾：mac（左端 56px 空出来）、无边框 Windows（右端 138px 的 caption 按钮）、浏览器里的开发形态（左端三个装饰圆点）。

## 不要做

- **不要画标签页。** 哪怕它是"正确"答案——多文档是另一个方案，本轮的问题是"关不掉"，不是"要开好几个"。
- 不要给关闭画保存/丢弃模态（见张力 1）。
- 不要重画主题 / 语言 / `AI · Ctrl+K` 这三个全应用控件的形态，它们在 `01a` 里已经定了；只在窄档里判它们让不让位。
- 不要引入第二种强调色，不要圆角（全应用零圆角），不要 toast。
- 宽档里视图切换请保持三格连体：作者要一眼看见现在在哪一档。收成下拉只可能是窄档的手段。

## 沿用的方言

`01a` 的纸色与线：零圆角、1px 细线分隔（`sepThin` 14px 高）、赭石（sienna）是唯一强调色且一屏里别撒太多、数字用 mono、视图切换的选中态是实底赭石 + 纸色字。深浅两套都要，深色不是把浅色反相——照 `01a` 的深色页取色。
