# 取材事实：这一轮模型眼前有什么

> 状态：**数据管道已实现**（`lib/roleplay/trace.ts` + `run.ts` 的两个出口 +
> `roleplayStore.contextTrace` / `preflight`）。**界面尚未实现**——取材条和上下文
> 构成条的预估态还没有落地，设计稿在做。

## 1. 起因

作者反复问同一个问题：**「我改的那段设定，它到底读到没有？」**

这个问题应用其实答得上来。`selectLore` 每次调用都产出完整的
`LoreActivationReport`——哪个条目、命中哪一层（摘要 / 正文 / 特征 / 配图清单）、
特征被**哪几个关键字**激活、注入了多少字符、以及**命中了却没进去的**加上原因
（关键字没中 / 同组被挤掉 / 超预算 / 仅手动 / 已常驻）。`loreSelect.ts` 的文件头
写得很直白：这份报告存在就是为了让界面回答「为什么它没进来」，是作者调特征
关键字的唯一反馈回路。

写作面板早就接了（`AiPanel` 的 `LoreReportSection`）。**扮演这条路一个都没接**：

| 来源 | 进上下文的位置 | 改之前 |
|---|---|---|
| 主角条目正文 | system 层「## 你是谁」 | ✗ 只有一个字符串 |
| 绑定条目 / 特征 | prelude 的绑定块 | △ 有层清单，**没有每层多大** |
| 知识库自动检索 | 播种的【场景】块 / 续跑的逐轮注入 | △ 播种轮的报告只被取走一个 `.length`；**续跑轮的报告在 `prepareContinuedHistory` 内部就被丢掉** |
| 记忆区检索 | 独立的【记忆】块 | △ 只留下几个名字，报告丢弃 |
| `@` 引用内联 | 问句里 | ✗ 只有 dirPath |

续跑轮那一条是真正的缺口：**第 2 轮往后的取材事实永远算不回来**。这类故障不
报错、不崩，只是让一个功能什么都答不上来。

顺带还有一个已经在骗人的界面：信息带那个 popover 写着「本次对话注入的设定 · N」，
读的却是 `agent.boundPaths` **配置**——失效的绑定、超预算只写了占位行的绑定、
以及自动命中的那一堆，它一个都不知道。（UI 那一轮一起改。）

## 2. 三条决定形状的判断

### 2.1 这是**按轮**的事实，不是按会话的事实

作者往回翻到第 12 轮问「它当时为什么这么答」，答案必须长在第 12 轮旁边。所以
`contextTrace` 按轮号存，和 `log` / 原先的 `recalled` 完全同构，`rewind` 时一起
按轮号截断——留着的话，被撤销轮号上的痕迹会错挂到重写后同轮号的新对话上，那是
一条看起来完全正常、内容却属于另一段对话的记录。

**只在内存**，和 `log` 一样（"它是调试信息，不是作品"）。代价明确：重启后历史
轮次没有痕迹。界面因此必须把两句话分开说——

- 「这一轮什么都没命中」→ 显示 **0**，它是有价值的信息；
- 「本次运行之前的轮次没有记录」→ 另一句话。

而分得清它们的唯一办法是**空的取材事实也要记**（`noteTrace` 无条件写），让「这个
键在不在」成为那个区别。原先的 `recalled` 是「没想起就不记」，那条路走不通。

### 2.2 常驻的和这一轮新来的必须分开

`coreDone` 机制会让主角条目和绑定条目在报告里显示成「匹配了、贡献 0 字」。不分
栏，作者会看到「沈砚 · 0 tk」并以为角色的人设根本没进上下文——**而它永久驻在
system 层**。这是所有误读里最坏的一种，因为它会让作者去改一个没坏的东西。

`LoreEntityReport.coreResident` 这个字段就是为这件事存在的，注释里写着：没有它，
报告读起来像「匹配了、什么都没注入」——唯一错误的那种读法。

### 2.3 记忆区绝不并进知识库那一栏

06 §4.2 反复钉的一条：【知识库】是世界的事实，【记忆】是这个角色**以为**的事，
两者可以互相矛盾。上下文里分块的理由在界面上一模一样——合成一栏，作者会把角色
的猜测读成公认设定。

所以 `TurnContextTrace.lore` 和 `.area` 是两个字段，不是一个数组加一个标记。

## 3. 已实现：数据管道

### 3.1 `lib/roleplay/trace.ts`

纯类型 + 纯装配，不碰盘、不碰 store，**不 import `./context`**——方向只有
`context → trace` 一条，反过来会绕成循环。

- `ResidentPiece` —— 常驻层的一项（`primary` / `bound-core` / `bound-facet`）。
- `TurnContextTrace` —— 一轮的取材事实。
- `PreflightEstimate` —— 首次发送之前的预估（见 §4）。

### 3.2 `BoundContent` 为什么长出第二个字段

`resident`（给账本）和 `pieces`（给作者看）**成员不同**，所以必须是两个字段：

超预算而只写了一行标题的绑定项，正文并不在上下文里，所以它**不能**进
`resident`——进了，注入账本就当它已经在，自动检索不会再去补它（这是
`BoundContent.resident` 注释里已经写死的一条）。可作者恰恰需要在清单里看见它，
并且看见它是「没展开」的那一种。合成一个字段只能二选一：**要么账本出错，要么
界面漏报。**

### 3.3 报告的两个出口

- `SeedOutcome` 加 `resident`（在 lib 里装配，不把 `primaryText` 抛给 store 自己
  拼——主角正文住在 system 层是**那个函数刚刚做的决定**，让调用方再推导一遍就是
  把一条不变量复制成两份）。
- `ContinueOutcome` 加 `loreReport`，**无条件带出去**，`inj.text` 为空时也带：
  「跑了检索但一条都没命中」和「这一轮根本没跑过检索」是两句话，只有 `null` 与
  非 `null` 分得清。
- `injectAreaRecall` 直接返回 `LoreActivationReport | null`，不再返回名字数组。
  `recalledNames(report)` 负责把它变成稿面那道「想起了…」要的几个名字——一次
  检索一份真相，两份迟早对不上。

### 3.4 `recalled` 退休

`LiveSession.recalled` 并进了 `contextTrace[n].area`。它们本来就是同一次检索的
产物。

### 3.5 续跑轮的常驻层从哪来

常驻层只在播种和「刷新绑定」时变，所以续跑轮沿用上一轮的那一份。

**上一轮也没有的情形是重启**：`session.json` 把 wire 历史接了回来，而取材事实只
在内存里，于是一段活得好好的会话会从此每一轮都报「零常驻」。这时退回
`preflight[agentId].resident`——它是**推断而不是实测**（作者如果在两次运行之间
改了绑定却没刷新，配置和块里的内容会不一致），但那种不一致正是 `stale` 那条提示
在管的事，而「什么都不显示」在任何情况下都更糟。

## 4. 已实现：首轮预估

### 4.1 为什么需要它

`history` 为 `null` 时（新会话、或 `rewind` 之后），上下文构成条只画得出工具
schema——首次请求真正会带上的 system 层、绑定块、记忆块、首轮检索块一样都还没
装配。旁白（无主角、通常无绑定）看着还合理；绑了满额条目的角色是条上 4.9k、
发出去 20k+。1M 窗口下只是难看，接一个 8k 窗口的本地模型就是「条还是绿的，请求
已经炸了」。

### 4.2 `blockSizes` 和 `contextSignature` 是同一个道理

三块的字符数由 `context.ts` 的 `blockSizes` 算，而它调的就是
`buildSystemPrompt` / `boundBlockContent` / `memoryBlockContent` **本身**。

**估的那一份和真的那一份必须由同一段代码算出来。** 在别处照着拼一遍块的形状，
就是让一个「预估」在下次有人改动块头文案时安静地失准——而它恰恰无法被任何测试
发现，因为估值本来就不精确。

### 4.3 不猜检索

`PreflightEstimate` 没有「检索会带来多少」这一项。那取决于作者还没打出来的那句
话。**少一段已知的未知，好过多一段编出来的确定**——界面上要显示成「未知」，不是
0，也不是一个平均值。

### 4.4 `checkBindings` 的跳过要拆开

`checkBindings` 原先第一行就是 `if (agent.contextHash === null) return null`——
没有基线的 agent（还没开过口）不参与「设定已更新」的比对，这是对的（05 §2.6：
标成「已更新」是在报一件没发生的事）。

**但它恰恰是最需要预估的那一个**，因为构成条这时只画得出工具 schema。所以那句
跳过必须只跳过 `stale` 那半边。`inspectAgent` 因此一次读完（同一组文件）、返回
两样东西，而**是否采用签名由调用方判断**——那就是这个函数签名的全部意思。

`preflight` 放在 store 级而不是 `LiveSession` 上，理由和 `stale` 一样：
`checkBindings` 跑遍整个花名册，而没打开过的 agent 根本没有会话。

改人设卡 / 改身份 / 手改 `memory.md` 都不会触发知识库重扫，所以「刷新绑定」和
「刷新记忆」各自补一次 `refreshPreflight`。

## 5. 明确没做

- **记忆块在构成条里的归类。** 绑定块因为是注入载体落进 `injected` 段，而记忆块
  不是载体，于是落进「对话」段。它是永不折叠的 prelude，画成「对话」在图例上是
  错的。**不影响总数**，只影响分段颜色，所以留着——要做的话给
  `computeContextBreakdown` 加一个可选的 `permanentBlocks: Set<StreamMessage>`
  参数（chat 传空），别为它改 `ChatSessionMeta` 的形状。
- **trace 落盘。** 见 §2.1 的取舍。
- **界面。** 取材条 + 构成条的预估态 + 信息带 popover 改读真实注入，都在下一轮，
  等设计稿。

## 7. 界面（设计稿 13「本轮取材条」TURN 1，**已被 §8 的 TURN 2 修正**）

数据管道（§3–§4）落地之后，作者拿到的还是零——这一节是把它摆到稿面上的那一半。

### 7.1 这一稿的一句话：四种来源用四种装订分开，不用四种颜色

| 来源 | 装订 | 为什么是这个 |
|---|---|---|
| 常驻 | 骑缝双线，**上下出血** | 线不在段内起笔也不在段内收笔，它从上一场穿进来、往下一轮穿出去——「不随轮次变」的字面画法 |
| 本轮命中 | 单线，**两端有止笔** | 止笔把这一段封成闭合区间：这些是这一轮才来的，下一轮很可能换一批 |
| 记忆区 | 点线 + 斜体 + 下沉一格底色 | 三件事一起做才够重：线断开＝不是实证，斜体＝这是他的口径（和稿面旁白同一个字形），底色沉一格＝另一张纸上抄来的 |
| 你 @ 的 | 作者轮那道 **2px 赭石线** | 稿面上标作者自己回合用的就是这道线。四段里唯一带强调色的装订，因为它唯一由作者负责 |

**仓库既有规则是「分类用颜色，集合用装订」**，而四种来源是四个*集合*（同一个
条目可以既常驻又被 @），所以只能用装订区分。颜色继续只承担两件事：赭石＝你能
点的与你负责的，褪色＝没进去。第三套彩色编码会立刻和知识库墙、上下文构成条打架。

**「没进去」不装订**：它不是第五种来源，是一种*状态*——只用一条通栏细线隔开，
整组降到最淡一档。装订线在这一稿里只表示「进了上下文」。

### 7.2 三句不能混的话

§2.1 里那个「空的也要记」的决定，在界面上兑现成三句字面不同的话：

- **本轮 +0 tk** —— 常驻早就在里面了，不必重复计。
- **本轮 0** —— 查过了，这一句话没碰到任何触发词。
- **无记录** —— 重启前的轮次，无从查证。

第三句是整个组件里**唯一不可交互的形态**，所以它在版式上就要看起来点不动：没有
三角、没有任何数字（包括没有 0）、起笔是破折号、上方一道虚线——页被撕掉的样子。

### 7.3 事件用箭头，账目用三角

稿面上原有的「← 想起了」「→ 记下了」是**事件**，方向就是它们和这一轮的关系。
取材条和执行日志都不是一次性事件，是可以查的**账**——所以它们并排在回复末尾，
都用 `▸`，中间一道 1px 竖线。`TurnLedger` 就是这一行。

取材条**恒在**（哪怕零命中、哪怕无记录），执行日志只在有步骤时出现：「这一轮
什么都没命中」是一句有价值的话，「这一轮没调工具」不是。

### 7.4 为它补的四样数据

设计稿收尾自己列了「需要的数据 · 落地时确认」。四样补上了，都在 `loreSelect`：

- **`LoreEntityReport.matchedTerms`** —— 条目级的命中词，`some` 改 `filter` 就有了。
  它撑起的是整个组件里最重要的一行「由「铁鳞」命中」：一个条目同时应答自己的名字
  和每一个别名，只说「它匹配了」等于让作者去猜是哪个写法命中的——**而那个猜正是
  他来调的东西**。
- **`LoreLayerReport.sourceChars`** —— 截断前的原字数。「正文 · 截断」是个耸肩，
  「2,840 → 1,200 字」是个能动手的数。
- **`FacetDrop.winner`** —— 同组挤掉时赢的那一条。不点名等于没解释。
- **`FacetDrop.neededChars`** —— 超预算差多少，即提高预算能换回什么。

「随条目进入 · 不看关键词」不需要新数据：没有 `matchedKeys` 又不是 pin 的特征
就是 `mode: "always"`。这一行**必须存在**——留空会被读成「不知道为什么进来的」，
而它恰恰是设定里最确定的一类。

`LORE_BUDGET_OPTIONS` 从 `AiPanel` 的私有常量搬进了 `appStore`：写作面板的注入
报告和这里各有一个「提高预算」，同一句话跨不同的步长是最容易让作者对不上账的
一种不一致。

### 7.5 降级：设计稿要了、这一轮没给的

- **常驻的「第 N 场起」**。需要为每一条绑定记下加入时的场次，而绑定现在只是一个
  路径字符串，没有任何来历。整列省掉，不猜。
- **记忆区条目的「第 N 场」**。`scene` 确实写在区条目的 frontmatter 里，但
  `scanEntityFolder` 产出的是 `LoreEntity`，不带它。要它就要动扫描层的形状。
- **你 @ 的那一段没有 tk**。字数没有从 `chatRefs` 的内联路径上带出来。
- **预算浮层**（「改成 8.0k 并重发这一轮」）。「重发这一轮」是另一套交互——要撤销
  已经落盘的一轮再重跑。这一版只给设计稿的默认态：预算条 + 一个跨一档的「提高
  预算」。

### 7.6 窄栏

断点按**容器**写（`container-type: inline-size` 挂在 `.logLine` 上），而容器查询
量的是**内容盒**——那一层自带 20px 稿面缩进，所以容器尺寸 = 面板内宽 − 20。设计
稿说的面板 400 / 340 因此写成 **380 / 320**。

照抄稿面那两个数是第一版的错：实测 420px 面板下容器正好 400，`max-width: 400`
当场命中，于是一个宽面板一上来就把 tk 单位藏掉了。**这类错只有量才看得出来**，
截图上「少两个字母」不会引起任何怀疑。容器落点也修过一次——原先挂在展开的
`.body` 上，而收起行在它外面，于是窄栏下收起行会固执地留着单位。

## 8. TURN 2：按真实字段重画（现行）

设计稿在 §7 落地之后出了 TURN 2，标题就是「按真实数据结构重画」——它拿着已经
实现出来的字段又画了一遍，**推翻了 §7 的六处**。TURN 1 保留在稿子下半部分作
对照，但**以这一节为准**。

这件事本身值得记一笔：**先做界面再拿设计稿，代价是真实的。** §7 那一轮里我按
TURN 1 做对的每一处，都是因为 TURN 1 恰好猜对了字段；猜错的地方（单位、常驻的
kind、coreResident）一处都没躲过。

### 8.1 同一根线，出血还是止笔

TURN 1 给常驻的是 **3px 骑缝双线**，TURN 2 拿掉了：

> 分类用颜色、集合用装订，而 **3px 双线已经归集合所有**。取材条这四段是上下文的
> 四个块，不是分类也不是集合，所以它们只借「同一根线的不同终止方式」。

于是常驻和知识库变成**同粗同色的 1px 线**，只有终止方式不同——出血 vs 止笔。
实测确认两者的 `background` 是同一个 `--color-border-input`，只有 `top/bottom`
一正一负。这比双线更难画对，但它说的是更准确的一句话：**它们是同一种东西，
区别只在有没有边界**。

### 8.2 单位：取材条一律读「字」

TURN 1 全篇 tk，TURN 2 全篇「字」。理由是数据层给的本来就是 `chars`：

> chars → tk 的换算只在计量条发生一次，取材条不做二次估算——**两处各说各的真实
> 数据，比对齐成一个假数好**。

同一个面板里两种单位，靠位置分：条上是 tk，条下的账目是字。`TurnContextTrace`
上那个 `charsPerToken` 因此在取材条里不再被读（留着给 §9 的计量条）。

### 8.3 常驻的三种 kind 用「位置」说，不用「身份」说

`人设 / 正文 / 特征` → **`系统提示 / 绑定块 / 绑定块 · 特征`**。TURN 2 写着
「这是位置，不是又一种色标」——它同时回答了「为什么它一直在」，而「人设」不回答
任何问题。

### 8.4 五句不能互相代替的话（TURN 1 只有三句）

| | 意思 | 版式 |
|---|---|---|
| 本轮 +0 | 常驻，一直在 | 段头右端 |
| **0 字** | 命中了，正文已在常驻段，去重后不重复装 | 条目行，比别的数字淡一档，**不是**警示色 |
| 本轮 0 | 跑过了，一条都没命中 | 段头通栏细线 + 数字 |
| **本轮未检索** | 这条路没跑（`null`，重试轮） | 段头换**虚线** + 「未检索」 |
| 无记录 | 重启前的轮次 | 破折号，不可交互 |

加粗的两句是 TURN 2 新增的，而它们各自推翻了一处实现：

- **「0 字」逼着 `hitRows` 不能再用 `contributingEntities`。** 那个过滤器把
  零层条目滤掉，于是 `coreResident` 的条目在界面上直接消失——作者会以为这一句话
  没能唤起它，然后去给一个工作正常的条目加关键字。（`contributingEntities` 本身
  没错：它是给日志里「注入了 N 条」用的，报一个不存在的注入是另一种错。同一份
  数据，两个问题，两种过滤。）
- **「本轮未检索」要在收起行就分得出来。** 原实现只在展开的段落里区分 `null`，
  收起行一律写 0。

### 8.5 `resident` 落选没有芯片

> 它不是失败，画成芯片就成了第五种失败。

改成一句带点线下划的话「已在绑定块 · 见上」，颜色比上面四行**亮**一档，单独排在
组内一道细线之下。

### 8.6 引用算一条，但不带字数

`refs` 只有 `name` 和 `dirPath`，所以它计入 `turnCount`（它确实在上下文里）而不
计入 `turnChars`。**将来 refs 带上字数，它应当计入而不是继续留白**——这句写进
`traceView` 的头注了，免得下一个人把留白当成有意的设计。

### 8.7 还是没给的

「第 N 场起」TURN 2 自己撤掉了（「它没有这个字段」），右端改读它在上下文里占多少
字——这一处是设计稿向实现让步，不是实现欠着设计稿。

预算浮层（「改成 2,600 并重发这一轮」）仍然没做：重发要撤销一轮已落盘的对话再
重跑，是另一套交互。这一版只给默认态。

## 9. 计量条的预估态（设计稿 2h，已实现）

TURN 2 还带来了新的一屏：上下文构成条的预估态。一句话是「**≥**」——发送之前算不出
检索会拿到什么，所以预估画的是**下界**：读数从「Context」换成「预估 ≥」，右侧
轨道换成未定纹，**折叠竖线撤掉**（发送前一条对话都没有，没有东西可折叠，画它就是
画一个不存在的风险；更糟的是位置会骗人——预估是下界，条只会往右长）。

### 9.1 同一个组件，只换三样

高度、分段顺序、点击行为、图例结构完全一致，作者不需要学第二套东西。变的只有
**动词**（Context → 预估 ≥）、**纹样**（空余 → 未定纹）、**竖线语义**——而这三处
恰好就是「估」和「量」的全部差别。

### 9.2 撤掉折叠竖线不是省事，是那道线在这里会说谎

它的意思是「越过这里，下一轮开始把最早的对话折叠成摘要」。发送之前**一条对话都
没有**，画它就是画一个不存在的风险。更糟的是位置会骗人：预估是下界，条只会往右
长，作者看到「离竖线还很远」，发送之后可能已经越过去了。

所以 `PreflightBreakdown` **根本没有** `compactMarkerPct` / `willCompact` 这两个
字段——让它画不出来，比让它算出来再嘱咐别画可靠。同一根 1px 线改用相反的含义：
`lowerBoundPct` 说「至少到这里」，不说「到这里就要归纳」。

### 9.3 token 在哪里数

`blockSizes` 同时返回字数和 **token 数**，因为只有它握着那三段**真正的文本**。

不这么做的话，显示层只能拿一个常数去换算，而字→token 的比值随语种差四倍
（中文 ~1、拉丁 ~4）。在一条写着「≥」的读数上报一个可能高四倍的数，就把一个
下界声明变成了假话。用权威估算器（`estimateTextTokens`，预检门用的同一个）当场
数——**换算只发生一次，且发生在有文本的地方**。

### 9.4 未定纹的两档色不能照抄暗色稿

设计稿的暗色值是 `--color-border` 叠在轨道上。**浅色下这两个 token 是同一个
`#E5DCC9`**，斜纹当场消失，整段读成「空余」——正好是这一段要表达的反面。

改用 `--color-text-ghost`（最淡的一档墨）在轨道上拉斜纹，两个主题下都分得开。
这类塌陷**只有量出来才看得见**：截图上它只是一条平淡的米色带子，四个色标全等
这件事要 `getComputedStyle` 才说得出来。这是这一轮第二次被「照抄暗色稿的具体
值」咬到（第一次是 §7.6 的窄档断点）——**教训是同一条：设计稿给的是意图，
主题令牌才是实现。**

### 9.5 没做

设计稿 2h ④ 的**过渡残影**（发送后旧的下界刻线留成一道灰残影 + 「刚才预估
≥ 15.4k」，400ms 一起淡出）没做。它要跨「预估→实测」这次切换记住上一版的下界，
是一次真实的状态编排，而它买到的是一次跳变的解释——留给下一轮。
