## 1. 起因

作者报的一句话：

> 我和旁白说「和 xxx 之前发生的某个事件」（在之前的某个 scene 里），它完全无法找到。

盘点下来这不是一个缺工具的问题。作者对这套系统的预期与实现之间有**七处**差异，
其中两处是语义装反了——不补齐它们，只给旁白加一个读归档的工具会让情况更糟：
旁白会把作者明确想丢弃的试验场当成正史读出来，并写进正文。

### 1.1 作者的预期（原话整理，已确认）

| # | 预期 |
|---|---|
| A | 扮演 agent 与知识库里一条角色条目绑定，扮演它 |
| B | 旁白可读取多个扮演 agent 的对话，总结 / 盘点 / 提取 / 转写到文件 |
| C | 作者可选一条角色条目作为扮演对象；**不选时作者是「导演」**——用陈述和剧情指令驱动，而不是以某个人的身份说话 |
| D | 另有一档「陌生人」：作者临时扮演一个身份未知的角色 |
| E | 转场 = 这段剧情**有效**，需要保留，后续以它为历史记忆 |
| F | 「另起一场」= 这一场是试验性 / 测试性的，**本场信息全部丢弃** |
| G | 旁白能找到扮演对话里的**特定场次**并阅读其内容 |
| H | 约定、重大事件（初吻、初拥、告白…）被记下并能记起 |
| I | 记忆以**少量摘要 + 展开细节**两级存储，而不是整体塞进上下文 |
| J | 能找到记忆对应的 scene 记录；必要时**扮演 agent 或旁白**可获取完整记忆 |

### 1.2 现状差异

| # | 差异 | 性质 |
|---|---|---|
| J | `MemoryRecord` 只有 `turn`，**没有场次坐标**。而转场把 `turnCount` 归零，所以旧记录的 `turn: 14` 指向「某个已归档场次的第 14 轮」，没有任何字段说是哪一场 | **缺失，且是其余几条的地基** |
| F | 「另起一场」**没有丢弃任何东西**：`takeSinkable` 分拣在 `if (continuing)` **之前**无条件执行，试验场里记下的事件已经沉进记忆区、带着关键字，未来会被命中 | **与作者意图相反** |
| — | 记忆区默认不绑（`createAgent` 里 `areaId` 默认 `null`）。没绑区的角色转场时旧前情直接标 `void`，**两场之后永久失忆** | **缺陷，默认配置下 E/H 不成立** |
| G | 旁白的 `SceneReader` 只解析 `transcriptPath`（当前场），`archive/` 与记忆区都够不到 | 缺失 |
| I | `renderMemoryBlock` 把 `title` **和 `body` 全文**一起塞进注入块，只有一个 4000 字符总上限，超出的**整条不列**。所以现状的两级是「列出 / 完全不列」，不是「摘要 / 展开」 | 设计不同 |
| C/D | `AuthorPersona.mode` 只有三档，`none` 的措辞是**「把他当成故事里一个你还不认识的人」**——那是陌生人，不是导演。作者写「天开始下雨，她推门进来」，角色会把它当成一个陌生人在对它说话 | **语义装反** |
| J | 扮演 agent 连**自己的** `archive/` 都读不到（`read_conversation` 作用域是当前场次） | 缺失 |

## 2. 定义（本方案据此实现，不再解释）

- **场号**：每个 agent **自己的**归档序号，`peekNextArchiveNo` 的口径（已有文件名解析出的最大值 + 1，**不是文件个数**）。不存在全局场编号。
- **场次地址**：`<agentId>#<N>`。`N ≤ 归档数` → `archive/transcript-NN.md`；`N == 归档数 + 1` → 当前这一场；裸 `<agentId>` 等价于当前这一场。地址空间**是全的**，没有洞。
- **接续**：这一场是正史。产出前情，进常驻记忆，写成新一场的 `summary.md`。
- **另起一场**：这一场**作废**。不产出前情、不沉记忆区、移除本场记下的常驻记录、归档打废弃标记。
- **废弃场次**：磁盘上保留，对模型默认不可见。作者显式点名时仍可读，且读到的内容必须带「已废弃」标注。

## 3. 不能碰的

前四条是既有不变量（01-overview §3），后三条是本方案新增：

1. **`transcript.md` 是资产，wire history 是缓存。** 只追加、永不改写；封存靠 rename。
2. **绑定块与记忆块进 prelude 的独立消息，永不进 seed 块。**
3. **隔离是结构性的。** 扮演 agent 的工具集里没有 scene 工具，而 scene 工具够不到别人的 wire history。本方案**不往扮演 preset 加任何跨 agent 的东西**。
4. **记忆是记录，不是摘要。** 只增改不删（对模型而言），恒在 prelude。
5. **记忆区绝不并进任何 `loreIndex`。** 并进去，隔离就从「它不在那里」降级成一个要在六处同时正确的过滤器（逐轮注入、知识库读工具、一致性检查、知识库墙、同步导出、旁白上下文）。本方案只加**显式的只读工具路径**。
6. **废弃场次默认不可见。** 任何新增的读路径（旁白的、角色的、记忆区检索的）都必须先问「这一场废弃了吗」，默认答案是不给。
7. **不真删作者写的字。** 「丢弃」是语义上的；物理上一律 `backupFile` 或留在 `archive/`。

## 4. 依赖关系

```
PR1 场次坐标 ──┬─→ PR2 「另起一场」＝丢弃 ──→ PR4 旁白打开到归档
               └─────────────────────────────→ PR4
PR3 记忆注入两级    （独立）
PR5 身份四档        （独立）
PR6 角色读自己的归档（依赖 PR1、PR4 的地址解析）
```

PR3 与 PR5 与主线无依赖，可以任意插队；**PR4 不能早于 PR2**——没有废弃标记就打开归档，等于让旁白把试验场当正史。

## PR1 — 场次坐标（地基）

作者可见的变化为零。这一片存在的唯一理由是后面三片都要用它。

**做什么**

- `MemoryRecord` 加 `scene: number`（`0` = 不详，旧记录读成 0）。
- `memory.md` 的记录行加一个字段：
  `### [m3] 标题 · 主语 · open · scene 2 · turn 14 · keys=雪原,塔`
  - **`scene N` 必须先于 subject 排除掉**，和 `keys=` 一个坑——`parseMemory` 里 subject 是「剩下那个字段」，漏掉排除它就会把 `scene 2` 当成主语。
  - 旧文件没有这个字段 → `scene: 0`，不迁移、不重写。
- `addRecord` 的入参加 `scene`；`mutateMemory` 写入时取 `peekNextArchiveNo(projectPath, agentId)`。多一次 `readDir`，目录很小，可接受。
- `lib/roleplay/scene.ts`（新，纯函数）：
  - `parseSceneAddress(raw)` → `{ agentId, scene: number | null }`。`agent` 旧拼法的兼容仍留在 `sceneTools.ts` 那一层。
  - `resolveSceneNo(archives, currentNo, n)` —— 判定是当前场还是第几号归档，**按解析出的编号匹配，绝不按排序下标取**。
- `listArchives` 的正则放宽到 `^transcript-(\d+)(\.discarded)?\.md$`，返回值带 `discarded: boolean`。PR1 里没有任何东西会写出 `.discarded`，先把读侧准备好。
- 记事本面板（`MemoryPanel`）显示「第 N 场」，`scene: 0` 不显示。

**验收**

1. 记一条约定 → `memory.md` 里出现 `scene 1`；转场后再记一条 → `scene 2`。
2. 手删 `archive/transcript-02.md` 之后再记 → 场号跟着 `peekNextArchiveNo` 走，和转场时用的是同一个数。
3. 打开一个改动前的项目，记忆面板不报错，旧记录显示为无场次。
4. 手改 `memory.md` 把 `scene 2` 删掉 → 读回来是 0，不崩。

**测试**：`memory.test.ts` 加 round-trip（含 `scene` 与 subject 的字段歧义）；`scene.test.ts` 全新，覆盖地址解析、编号有洞、越界、`N == 归档数+1`。

**规模**：约 250 行。

## PR2 — 「另起一场」＝ 丢弃

**做什么**

`newSession` 里按分支切开（现在分拣是无条件的）：

| 步骤 | 接续 | 另起一场 |
|---|---|---|
| 分拣 `takeSinkable` → 记忆区 | ✅ | ❌ **不跑** |
| 移除本场记录（`r.scene === sceneNo`） | ❌ | ✅ **先 `backupFile` 再写** |
| 加一条 `kind: "scene"` 前情 | ✅ | ❌ |
| 归档文件名 | `transcript-NN.md` | `transcript-NN.discarded.md` |
| 写新一场 `summary.md` | ✅ | ❌ |

- **移除是允许的**，理由和 `truncateTurns` 完全一样：「只增改不删」防的是模型跑飞悄悄丢字，而这是作者自己按下去、指名道姓要撤销的动作。纪律照旧——**写前必 `backupFile`**。
- 顺序纪律不变，且现在更紧：**场号先算 → 记忆先落 → 再封存 → 最后写新 summary**。
- 「同时清空记忆」勾选项改语义为 **「连更早的记忆一起清空」**（推倒重来），文案跟着改。它现在和「丢弃本场」是两件事：本场无条件丢，更早的才需要勾。
- `SceneTransition` 两支的说明文案跟着改：另起一场要说清「这一场会被作废，角色不会记得，旁白也不会读到」。
- **不产出前情**这一点不变——作者已确认现状是对的。

**实现时发现的两处，都不在原计划里：**

1. **预览态的「不要前情」原本落到 `mode: "fresh"`**（设计稿 2b 的注解：「它按另起一场落地」）。那在从前是对的——两支的差别只是留不留前情。新语义下它会**静默作废整整一场**：作者点进预览时已经选了「这一场算数」，只是嫌这份摘要写得不好。改成走接续里不带 recap 的那一支（照常分拣、照常算正史，常驻层不多一条前情），`discarding` 因此判 `mode === "fresh"` 而不是 `!continuing`。
2. **两处稿面的场号用的是「归档数 + 1」**（`AgentComposer` 的 `archiveCount + 1`、`RoleplayChat` 的 `archives.length + 1`），而记忆里写的场号走 `peekNextArchiveNo`（max + 1）。作者手删过一场归档之后两者错开，「另起一场」就会照着一个错的场号去丢弃记录。两处都改成 `currentSceneNo`。这正是 06 §12 记过一次的那个坑，在另外两个文件里又长了一遍。

**验收**

1. 试验场里让角色 `remember` 一个事件 → 选「另起一场」→ 记忆区**没有**新条目，`memory.md` 里那条**不在了**，`.ai-writer/backups/` 里有备份。
2. 同样的场景选「接续」→ 记忆区有条目、带 `scene: N` 和关键字。
3. 另起一场之后 `archive/` 里是 `transcript-03.discarded.md`；接续之后是 `transcript-03.md`。
4. 另起一场且勾了「连更早的一起清空」→ `memory.md` 整份进 archive。
5. 已有的未了结约定（更早场次记的）在「另起一场」后**仍然在常驻层**——丢的是本场，不是全部。
6. `scene: 0` 的旧记录**永不被当作本场**丢掉。

**测试**：`store.test.ts` 加两支的分拣差异；一条专门钉「`scene: 0` 不被误删」。

**规模**：约 300 行。

## PR3 — 记忆注入两级（独立，可插队）

**做什么**

- `renderMemoryBlock` 只渲染 `title`（+ subject），**不再渲染 `body`**：
  `- (m3) 对沈砚：雪停就去塔下…`
  - 尾部 `…` 表示「这条有细节」——不给标记的话模型不知道哪条值得展开。
- 块尾固定加一句：需要细节时用 `recall` 展开某条 id。
- `recall` 支持按 id 取单条全文（现在只能列全部）。
- `MEMORY_BLOCK_CHAR_CAP` 保持 4000：同样的预算现在能装下多得多的条数，「还有 N 条」的情形大幅减少。

**验收**

1. 二十条记忆时，注入块列全部条目，`body` 一条都不在里面。
2. 角色被问到细节时**会自己去 `recall`**——这条是这一片唯一的真实风险，必须真聊，不能只看单测。
3. 一条记忆的 `body` 很长时，它不再挤掉别的记录。

**风险（写在这里免得后面争论）**：少了 `body`，角色的即时表现可能变差——它必须多一轮工具调用才能拿到细节，而扮演的 `maxRounds` 只有 5。如果实测下来角色明显变笨，退路是**分级**：`pact` / `todo` 保留 `body`（未了结的事必须一眼看见），`event` / `note` / `bond` 只给标题。**先做纯两级，实测之后再决定要不要退。**

**规模**：约 150 行。

## PR4 — 旁白打开到归档

本方案最大的一片。

**做什么**

- `SceneReader` 接口扩到 `(agentId, sceneNo)`：`read` / `summary` / `memory` 都要能落到 `archive/*-NN.md`。
- `list()` 每个角色仍是**一行主行**，归档压成**一条附行**：

```
- rp-shen — 沈砚 · 沈砚/index.md · 当前第 4 场 18 轮 · 2 条未了结
    已封存 3 场：#3「雪停之后」40轮 08-14~08-16 · #2「塔下」12轮 08-09 · #1 6轮 08-02
```

  - 绝不一场一行——旁白一开口就吃几十行清单。多于 6 场截断成「另有 N 场更早的」。
  - 标题取 `summary-NN.md` 首行。**日期范围无条件给**（从 turn 的 `at` 推）：只有走过「接续」的场次才有摘要，一直点「另起一场」的项目归档里根本没有摘要，那时日期是唯一的抓手，而「上周和沈砚那次」正是作者最自然的说法。
  - **废弃场次不出现在这一行里**，另起一行「另有 N 场已废弃（作者标记为试验，不计入故事）」。
- `read_scene` / `read_scene_summary` / `read_scene_memory` 认 `#N`。读废弃场次要显式给地址，且返回内容**必须**以「这一场已被作者废弃，不属于故事」开头。
- `search_scenes` 改成**两层合一**，输出分栏：

```
逐字命中（对话原文）
- 沈砚 #2 第 14 轮：「雪停了我就去塔下等你」

索引命中（场次前情 / 记忆区）
- 沈砚 #2「塔下」· 关键字 雪原·约定 · 我答应她雪停就去塔下

用 read_scene 加上面的场次地址读原文。
```

  - 默认搜进归档（不含废弃）。总命中 30 条封顶不变。
  - 索引层的来源：各场 `summary-NN.md` + 记忆区条目（`name` / `aliases` / `summary`）。
  - **不新开工具**——两层产出的是同一种可操作的东西（场次地址 + 理由），而每加一个工具就是每轮固定头部多一份 schema 开销，`agentToolBudget.test.ts` 的棘轮拦的就是这个。
- **缓存规则**（写进 `sceneTools.ts` 的文件头）：
  - 归档文件**内容**按路径 memo，一次运行内有效——它 rename 进去之后永不再改。
  - **目录列表每次重读**，运行中途新封存的一场要立刻可见。
  - 当前 transcript 维持「每次读盘、不缓存」。
- 记忆区接进旁白的读路径。输出**必须**标注「记忆区 · 这是角色**以为**的事，未必与正文一致」——旁白是会往正文里写字的，把一个角色的错误认知当事实写进第三章是这个口子唯一真实的风险。
- `ai.instructions.narrator` 改：现在那句「你能读到作者与每一个角色的对话记录」在归档面前是假的。要说清记录**有历史**，以及找旧事的顺序：`list_scenes` 看有几场和标题 → `search_scenes` 定位 → `read_scene_summary` 确认 → `read_scene` 取原话。
- 四个工具的 description 同步改（`registry.ts`）。

**验收**

1. 转场三次之后问旁白「和沈砚之前在雪原上那件事」→ 它能定位到场次并引用原话。
2. 作者用**转述**的说法（transcript 里没有的词）→ 索引层命中，仍然找得到。
3. 一直用「另起一场」的项目（没有任何 summary）→ 旁白靠日期仍能找到那一场。
4. 废弃场次**不出现**在 `list_scenes` 和 `search_scenes` 里；显式点名能读到，且开头有废弃提示。
5. 旁白讨论到一半，作者切去和某角色聊三轮再回来 → 旁白读得到那三轮（当前场不缓存）。
6. 转场发生在旁白运行中途 → 下一次 `list_scenes` 看得见新归档的那一场。
7. 扮演 agent 的工具集**没有任何变化**（`presets.test.ts` 守着）。

**测试**：`sceneTools.test.ts` 扩（`#N` 寻址、废弃过滤、两层输出、缓存边界）；`presets.test.ts` 钉住扮演 preset 不变。

**规模**：约 700 行。

**实现时的三处决定：**

1. **`list()` 分两级读盘。** 场次标题从 `summary-NN.md` 取——文件很小，每一场都读得起，而它是「转述也能找到」的主力；轮数和日期要解析整份 transcript，所以**只给最近 `ARCHIVE_DETAIL_LIMIT` 场算**。更早的只报个数，旁白按场号点名去读。
2. **`search_scenes` 的逐字层封顶到最近 `SEARCH_ARCHIVE_LIMIT` 场，索引层不封顶。** 逐字要读整份 transcript，索引几乎不要钱。超出的部分**必须在输出里说出来**——不说的话，「搜过了没有」和「压根没搜到那么早」在旁白眼里是同一句话。
3. **`read_scene_memory` 返回两层**：常驻记忆（`memory.md`）+ 记忆区条目清单。只读第一层的旁白会以为这个角色什么都不记得，而它记得，只是转场时被移出了常驻层。记忆区那一层**只给标题 + 一句话 + 场次地址，不给正文**——正文本身就是某一场的复述，而旁白现在读得到那一场的**原文**，那是严格更好的来源。

## PR5 — 身份四档（独立，可插队）

**做什么**

| mode | 含义 | system 那一行 |
|---|---|---|
| `lore` | 知识库里的一个人物 | 不变 |
| `prompt` | 作者自己写一段身份 | 不变 |
| **`stranger`**（新） | 临时角色，身份未知 | **原样搬用现在 `none` 的措辞**：「与你对话的人没有给出身份，把他当成故事里一个你还不认识的人。」 |
| **`none`**（改语义） | **导演视角**（默认） | 新写 |

导演那一段必须说清三件事，少一件模型就退回去把作者当角色：

1. 对方**不是故事里的人**，是这部作品的作者；
2. 他写的是**场面描述和剧情指令**，不是有人在对你说话；
3. 你据此**演下去**，不要回应他本人。

连带（**不改就是静默失效**）：

- **`personaKey`（`context.ts:411`）必须区分四档。** 它现在对 `none` 和任何未知 mode 一律返回字符串 `"none"`——不改的话，作者在导演和陌生人之间切换，「设定已更新」**永远不会亮**。这就是「往 system 层加一样作者能改的东西，就要同时加进 `contextSignature`」那条。
- `ai.instructions.roleplaySyntax` 按 mode 分岔：`裸文本＝场景` 在导演模式下是**导演在下指令**，不是作者以某个身份描述场景。两种模式共用一套语法说明会互相打架。
- 身份选择器 UI 加一档（全局 + per-agent 覆盖两处入口）。
- **不写迁移代码。** 现有 `mode: "none"` 的角色语义从「陌生人」变成「导演」，作者要旧行为就在选择器里点「陌生人」。这会静默改变已有角色的行为，UI 上要有一句说明。

**验收**

1. 不选身份 → 写「天开始下雨，她推门进来」→ 角色**演下去**，不把它当成有人在对它说话。
2. 选「陌生人」→ 行为与改动前的 `none` 一致。
3. 在导演 / 陌生人之间切换 → 「设定已更新」亮起，点「刷新设定」后生效。
4. `lore` / `prompt` 两档行为完全没变。
5. 新建角色默认是导演视角。

**测试**：`context.test.ts` 加 `personaKey` 四档互不相等；`buildSystemPrompt` 四档快照。

**规模**：约 250 行。

## PR6 — 角色读自己的归档

作者预期 J 的后半句：「扮演 agent **或**旁白可获取完整记忆」。

**做什么**

- `ConversationReader` 扩到自己的 `archive/`：`search_conversation` / `read_conversation` 接受场号，**但仍然没有 agent id 参数**——作用域的结构性由此保持不变。
- 废弃场次对角色**一律不可见**，连显式点名也不行（作者说那一场没发生过，就是没发生过）。
- 一条记忆的 `scene` 字段成为角色回看原文的入口：`recall` 的输出带上「第 N 场」，角色可以据此 `read_conversation`。

**验收**

1. 角色被问到三场以前的约定 → 能从 `recall` 拿到场号，再读到当时的原话。
2. 角色**读不到**废弃场次。
3. 角色仍然读不到任何别人的东西（`presets.test.ts`）。

**规模**：约 200 行。

**实现时的两处：**

1. **`search_conversation` 省略 `scene` 时搜自己的每一场**，不是只搜当前场。「你还记得我们在雪原上说的话吗」问的多半就是旧场次——默认只搜当前场，等于让这个工具在它最该起作用的时候答不出来。
2. **作废的场次走的是「不存在」而不是「不能读」。** 过滤在 `ConversationReader.scenes()` 那一层，工具够不到它们；点名得到的回答是「你没有第 2 场」。多说一句「你不能读它」反而是在告诉角色有一段它不该知道的历史。

## 5. 记忆区默认绑定（并入 PR1）

> **实现时的修正**：盘点时说的「记忆区默认不绑」**说重了**。`AgentComposer` 的
> `AreaPicker` 在新建角色时默认就选中「新建一个」，随后 `bindArea(id, "new")` 会
> 建出区来——**走 UI 建的角色一直是有区的**。真正没有区的只有两种：这个功能出现
> 之前建的角色，以及作者在「绑定已存在的」下没有可选项时落到的 `null`。而后者
> 在界面上**没有任何提示**说这意味着什么。

- `createAgent` 在调用方**没表态**时（`draft.areaId === undefined`）自动建区并绑上。判据是 `undefined` 而不是 `null`：`AgentComposer` 走的是「先 `areaId: null` 建出来、再 `bindArea` 建区并写两份 meta」那条路，把 `null` 也当成没表态，就会在那条路上多建一个区，它随即被 `bindArea` 摘掉，变成一个谁也不认识的孤儿目录。
- `AreaPicker` 在 `value === null` 时**说出后果**：「没有记忆区：转场时这个角色会忘掉上一场，而且找不回来。」说后果，不替作者选。
- 已有的、没绑区的 agent：**不写迁移**，编辑抽屉里的「新建一个」就是修复入口。

## 6. 不做什么

写在这里是为了 review 时能直接指过来：

- **不做全局场编号。** 场号永远是每个 agent 自己的归档序号。
- **不做 AI 整理记忆区**（合并重复、补关键字）。06 §9 列为下一期，本方案不碰。
- **不改扮演 preset 的隔离。** 角色读不到别的角色，一行都不放开。
- **不把记忆区并进 `loreIndex`。** 只加显式读路径。
- **不做跨角色的共享事实层。** 两个角色都在场的一件事仍然各记各的。
- **不改 transcript 格式**，不给它加 frontmatter，不改「只追加」。
- **不写任何数据迁移。** 旧字段读成默认值，作者手上有修复入口。
- **不动 `lib/agent/*`。**

## 7. 已知的坑

| 坑 | 说明 |
|---|---|
| `parseMemory` 的 subject 是「剩下那个字段」 | 加 `scene N` 必须同时加进排除列表，否则它被当成主语。`keys=` 踩过一次 |
| `personaKey` 对未知 mode 返回 `"none"` | 加 mode 不改它 = 「设定已更新」永不亮 |
| 分拣在 `if (continuing)` 之前 | 这就是 F 装反的根因；切分支时别只在 `continuing` 里加东西 |
| 场号两处算 | `peekNextArchiveNo` 是唯一口径。按 `listArchives().length + 1` 数在作者手删过归档后会错开——06 §12 已经踩过一次 |
| 归档缓存 | 内容可 memo，**目录列表不可**。反了就是「转场后旁白说那一场不存在」 |
| 记忆区可继承 | 一条条目的 `scene: N` 可能来自**上一个绑定者**的第 N 场。解析不到就只显示条目、**不给场次地址**，别给一个指错场的链接 |
| 工具 schema 预算 | `agentToolBudget.test.ts` 是棘轮。PR4 刻意不新增工具名，只改已有四个的 description |
| PR3 的表现回归 | 去掉 `body` 之后角色可能变笨。退路（按 kind 分级）写在 PR3 里，别临场发明 |
