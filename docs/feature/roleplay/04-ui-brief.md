# 设计任务：为一款桌面写作应用设计「互动式角色扮演」面板

## 产品背景

这是一款给小说 / 剧本 / 跑团模组作者用的桌面写作应用（Tauri + React，Mac 和 Windows）。它的核心是三件事：左边是文件树，中间是 Markdown 编辑器，右边呼出一个很宽的 AI 抽屉。作者在应用里维护一个「知识库」——人物、世界观、势力、道具这些条目，每个条目是一个带头像和多段特征的卡片。

现在要加一个新功能，代号「扮演」。它让作者能**以第一人称走进自己写的条目里，和笔下的角色直接对话**。

- **扮演 agent**：绑定知识库里的一个人物条目，AI 就演这个人。作者用第一人称和它互动——说台词、描述动作、描述环境。每个角色的记忆完全独立，角色之间互相不知道对方存在。
- **旁白 agent**：不演任何人。它能读到作者和所有角色的全部对话记录，像画外音一样和作者讨论故事该怎么发展，并且能把某段精彩的互动整理成正文写进稿子里。
- **每个 agent 有一本自己的「记事本」**：角色会主动记下和作者定下的**约定**、自己打算做的**待办**、发生过的**重要事件**、以及对某个人的**关系**变化。这本记事本不会随着聊天变长而遗忘——它是这个功能和普通聊天机器人的根本区别，**在界面上必须被看见、被信任、可编辑**。

一个项目里可以有很多个 agent，最多 3 个同时在生成回复，其余排队。

## 这个界面要解决的核心张力

**它同时是"聊天"和"创作工具"。** 纯聊天 UI（气泡、头像、无限滚动）会让它显得像个玩具，作者不会认真对待；但塞满工具栏和面板又会破坏"走进故事里"的沉浸感。**设计的成败就在这个平衡上。**

倾向：**沉浸为主，工具克制**。对话区应该安静、可读、有质感——接近读一段剧本或小说，而不是刷微信。所有的编排能力（绑定了哪些条目、用哪个模型、执行日志）都存在，但默认收起，需要时才展开。

**唯一的例外是记事本**：它不是配置，是作品的一部分，值得一个能常驻在视野里的位置。作者应该能一眼看到「这个角色现在还欠着三个承诺」。

## 视觉规范（硬约束，必须遵守）

这个应用有严格的既定视觉语言，新面板必须无缝融入：

- **风格**：克制的、现代的、Apple 式的。整体气质是"手稿"——像裁切的纸，不像圆角卡片。
- **圆角：全局为 0。** 所有容器、按钮、输入框都是直角。唯一允许的圆形是状态圆点、加载指示器、单选标记、以及**头像**。开关是方形的。
- **强调色：只有一个** —— 赭石色 sienna（浅色模式 `#A0522D`，深色模式 `#D9925B`）。禁止在交互元素上用多色渐变。需要区分状态时用中性灰阶 + 这一个强调色的深浅。
- **层次靠阴影，不靠边框。** 有一套四级阴影（sm/md/lg/xl），取能读出来的最小那一级。
- **字体**：正文用衬线（手稿感），UI 标签用无衬线，数字/代码用等宽。中文正文默认宋体系。
- **动效**：120–320ms，Apple 缓动曲线，"几乎察觉不到但很顺"。不要弹跳、不要大位移。
- **深浅双主题**：两套都要出，不是深色改个背景色了事。
- **选中 vs 悬停要分开**：选中用强调色淡染，悬停用中性灰。把悬停也染成强调色会让人以为选中了。

## 画布尺寸

面板是一个从右侧滑出的抽屉，**宽 1180px（最大 94vw），高度占满窗口**。顶部已经有一行 tab（生成 / 对话 / 一致性检查 / **扮演**），扮演是新增的第四个。请注意四个 tab 在窄窗口下的排布，给出应对方案。

## 需要设计的界面

### 1. 主界面：花名册 + 对话区（最重要）

两栏。左边是 agent 花名册（建议 240–300px），右边是当前选中 agent 的对话。

**花名册的每一行要传达**：
- 头像（取自绑定的人物条目；旁白 agent 没有人物，需要一个不同的视觉符号）
- 名字
- 是扮演还是旁白（两类要一眼可分，但不要用两种颜色——只有一个强调色）
- 状态：空闲 / 正在生成 / 排队中 / 有未读回复
- **未兑现的约定 / 待办条数**（比如一个小小的计数）——这是花名册上最有信息量的一个数字，它告诉作者「这条线还欠着东西」
- 可选：最后一句话的摘要、轮数

**对话区要传达**：
- 作者和角色的往复。**注意**：作者的输入不只是台词，还包括动作和场景描述，混在一条消息里，像这样：

  ```
  *推开门，屋里没有点灯。*
  「你还在等？」
  ```

  `*…*` 是动作、`「…」` 是台词、裸文本是环境描述、`[…]` 是出戏的元指令（"[让他更冷一点]"）。**这四种在气泡里需要不同的排版处理**——这是这个界面最有设计价值的一个点：让一段混合了动作和台词的文字读起来像剧本，而不是像聊天记录。
- 角色的回复同理。
- 流式生成时的状态。
- 每条回复背后可能有"AI 查了哪些条目"的执行日志，默认折叠成一行小字。

**顶部需要一条克制的信息带**：当前角色的名字、绑定了哪些条目（可点开）、用的哪个模型（可切换）。

### 2. 输入区

比普通聊天框重要得多，因为作者要在这里写混合内容。需要：
- 多行输入，支持换行不发送
- 一条常驻的语法提示（四种标记的说明），第一次用时展开，之后折成一行
- `@` 引用按钮（引用某个条目或某个文档）
- 发送 / 停止
- 一个"我现在扮演谁"的指示（作者可以选一个知识库角色，或者自己写一段描述，或者不指定）

### 3. 记事本面板（本次设计的第二个重点）

每个 agent 一本，展示它记下的东西。可以是对话区右侧的第三栏（可收起）、也可以是从对话区顶部拉下来的一层——**请给出你认为更好的方案并说明理由**，这正是这个界面需要设计判断的地方。

数据长这样，四类 + 一个兜底类：

| 类别 | 例子 | 有状态吗 |
|---|---|---|
| **约定** | 「雪停了一起去塔下」 | 进行中 / 已兑现 / 已作废 |
| **待办** | 「去问铁匠要那把刀」 | 进行中 / 已完成 / 已放弃 |
| **事件** | 「她说出了自己的名字」 | 无 |
| **关系** | 「对 林：从戒备转为勉强的信任」 | 无（内容会被改写） |
| **其他** | 兜底 | 进行中 / 已作废 |

每条记录有：一行标题、一段正文、状态、**记下时的轮次编号**（点它能跳回对话里的那一刻）、可选的关联对象（某个人物或条目）。

需要考虑的：
- 四类怎么分组或分区，让作者一眼看出「还欠着什么」（进行中的约定和待办是最重要的，事件和关系是背景）
- 状态怎么表达——**只有一个强调色**，所以「进行中 / 已兑现 / 已作废」不能靠三种颜色
- 已作废的记录不删除、但也不该抢视线
- 作者能手动增、改、改状态（这本记事本是作者和角色共同维护的）
- 条目很多时（几十条）怎么办
- **空态**：还没记下任何东西时，要能让作者明白这里将来会有什么

### 4. 对话区里的记忆提示

角色在回复的过程中记下一条东西时，对话流里要有一个**很轻**的痕迹——一行小字之类的，"记下了：雪停了一起去塔下"，可点击跳到记事本。

分寸很重要：它不能像系统通知那样打断阅读，但也不能轻到作者看不见——作者需要知道角色**真的**记住了，这是建立信任的地方。

### 5. 新建 / 编辑 agent 的抽屉

从右侧再滑出一层，或者一个居中的面板。需要：
- 选类型：扮演 / 旁白（两个大选项，选了之后下面的表单不同）
- 扮演：选一个主角条目（从知识库里挑，要能搜、要显示头像和一句话摘要）
- 绑定相关条目（多选，可以是整个条目也可以是条目里的某一段特征）——**这个选择器要好用**，作者可能有几十个条目
- 选模型（可留空 = 跟随全局）
- 写"扮演指令"（自由文本，比如"说话短，从不解释动机"）
- 旁白：没有主角，只有绑定条目 + 模型 + 指令

### 6. 各种状态

请把这些都画出来，不要只画理想态：
- **空态**：还没有任何 agent（这是作者第一次看到这个 tab 的样子，很重要，要能让人立刻明白这功能是干什么的并且想试）
- **对话空态**：agent 建好了但还没说过话
- **排队中**：并发满了，这个 agent 在等
- **绑定的绑定内容已更新**：需要一条提示 + 一个"刷新"动作
- **绑定的条目被删了**：绑定项标灰 + 可移除
- **模型没配好 / 出错**：行内错误
- **旁白提出要改稿子**：一张确认卡片（作者要能看清改动内容，然后批准或拒绝）
- **记事本为空**
- **记事本被手动改过、但角色还不知道**：需要一条提示 + 一个"让它读一遍"的动作
- **记事本条目很多**：滚动、分区、或者折叠已完成的

## 交付

- 主界面深色 + 浅色两版
- **记事本面板**（含你选择的呈现方案的理由）
- 新建 agent 抽屉
- 空态和其他关键状态
- 混合文本（动作 / 台词 / 场景 / 元指令）的排版规范细节图——这个单独放大画
- 记事本单条记录的细节图（标题 / 正文 / 状态 / 轮次 / 关联对象怎么排）
- 花名册行的各种状态细节图

## 不要做的事

- 不要引入第二个强调色
- 不要加圆角
- 不要把它设计成微信 / iMessage 那种气泡（尤其不要一左一右加小尾巴）
- 不要在角色之间加"群聊"的暗示——它们互相看不见，界面不能暗示它们能互相看见
- 不要在扮演对话区放任何"改稿子"的按钮（那是旁白独有的能力，混在一起会打断作者的心流）
- 不要把记事本设计成待办清单 app（不要复选框方阵、不要进度条、不要优先级星标）——它是**故事的账本**，不是效率工具
