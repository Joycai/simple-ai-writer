# 计费组与两本用量账

> 状态：`shipped` · 设计稿 `05l 计费组与用量 Fee Groups × Usage`（TURN 1 屏 1a–1g + 1n + 1r；TURN 2 屏 2a–2g + 2n）

## 改之前是什么样

价格是模型行上的五个列：`price_in` / `price_cached_in` / `price_out` /
`price_per_image` / `price_per_second`。三个后果：

1. **抄十几遍。** 同一家的十几个对话模型价格相同，每一行各填一次；改价要改十几处。
2. **一次请求该读哪一列没有答案。** 出图模型既可能按张计价、也可能把出图计进
   token，于是旧的 `imageCostFor` 把两种价**相加**——一个两边都填了的模型会被
   收两次。这是一笔糊涂账，而它不报错。
3. **改价会改历史。** 算钱时回头查模型行上的当前价，于是今天把 Sonnet 的价从
   3 改成 4，上个月的账单跟着变。

## 现在是什么样

```
计费组 FeeGroup           一组价格，三种模式之一（fee_groups，在全局 config.db）
   ├─ token   输入价 · 缓存价（可空 = 同输入价）· 输出价     每百万 token
   ├─ request 每次请求价
   └─ spec    单位（张 / 秒 / 条）× 档位表[尺寸? · 质量? · 时长? → 单价]
              + 输入图（每张单价 · 每次免费张数）
模型 models.fee_group_id ──▶ 组      渠道 providers.default_fee_group_id 只给新模型预填
用量行 token_usage        一次计费请求：计数 + **当时价格的快照** + 规格快照 + 上游报价(可空)
```

## 不变量

1. **行自带价格。** 每一行抄下计费时的模式、单价、数量与规格快照。改组、删组、
   把模型换到另一个组，历史一分不动。删组只把引用置空（`feeGroupDeleteStatements`），
   用量行不碰。
2. **算钱只有一份代码，且只读行上的数。** `feeGroup.costOf(billed)`。金额在记账
   那一刻算好写进 `cost_usd`，读那一侧 `SUM` 它——不是第二套口径，是同一个函数
   的结果落了盘。因此**不需要检查点**：几万行的汇总在 SQL 里做完。
3. **「没有」与「零」分得开。** `cache_input_price` 可空（空 = 同输入价，0 = 真
   免费）；`reported_cost` 可空（空 = 没报，0 = 上游说免费）；档位条件可空（空 =
   匹配一切）。界面从不拿 0 冒充「没配」。
4. **规格两边都归一化后再比。** 请求值、上游回显值、表里手填的条件走同一个
   `normalizeSpec`；匹配是纯相等。**空条件匹配一切，填得最多的行赢，同样多先写
   的赢，同样多时精确尺寸压过靠面积落进来的档位。**
5. **上游报价压过整张表。** 有它就不再算（它含输入侧，是替换不是叠加）；档位
   估算照样快照在同一行上。
6. **一次请求记两处。** 项目库（`.ai-writer/project.db`，跟着项目文件夹走）和
   总账（`appDataDir/config.db` 的 `token_usage`，多一列 `project`，比任何一个
   项目活得久）。两处各自 try，永不抛错。
7. **记账只有一个写入口。** `lib/ai/usageRow.recordUsage`；纯函数 `buildUsageRow`
   把「这次请求的事实 + 模型绑的价」变成要写下去的那一行。
8. **「按计费组」统计按当前归属，不按快照。** 行上快照的是**价**，不是归属；
   重新分组之后历史跟着走，这是故意的。
9. **分项的钱也是落盘的结果，不是第二套口径**（2026-09）。`costOf()` 的七项经
   `segmentsOf(parts, outputUnit)` **分流**（不重算）成六段，和 `cost_usd` 一起
   写在行上（`cost_input` / `cost_cache` / `cost_output` / `cost_count` /
   `cost_duration` / `cost_other`）；读那一侧只 `SUM` 它们。拆分放在**写入时**
   是因为 `spec` 那笔钱数的是张还是秒只有 `output_unit` 知道，而 `GROUP BY`
   之后一个桶里可能混着两种单位——写的那一刻单位是确定的单值。
   **守恒律：六段 + `cost_unsplit` ≡ `cost_usd`**（`cost_unsplit` 是分项列还是
   NULL 的老行贡献的那部分）。这条一破，用量页的条就会比行尾那个金额短一截或
   长一截，而那种不一致不报错。老行由 `usageBackfill` 补，**对得上账才补，
   对不上就留白**——回填的不是价，是同一笔钱的分法。

## 迁移

`models.fee_migrated` 记「这行搬过了」，每行一次、幂等，跑在 `ensureAiSchema`
里（凡是读这个库的路径都先过它）。归并按「同一份价」去重——这正是这次改动的
理由：十几个同价的模型搬完之后指向同一个组。

两处值得记住的判断：

- **老的 `price_cached_in` 是 `NOT NULL DEFAULT 0`**，所以「没填」和「真免费」
  在库里长得一样。迁移把 0 读成 **null**（= 同输入价）。照搬成 0 会让所有老配置
  一夜之间缓存不要钱，而那是一笔看不出来的错账。
- **旧的价格列不清零**：迁移要读它们，一台机器上的旧版本也还在读它们。新代码
  一律走 `Model.fee`（`configDb.feeOf`），旧列没有任何算钱的路径在读。

用 `models.fee_migrated` 而不是「表里已经有组了」或「把旧列清零」：前者会让
用户删光组之后下次启动又长回来，后者会让同一台机器上的旧版本读到一堆零价。

### 写模型行必须自己盖章（1.76.1）

这个标记只有在**不会被悄悄清掉**时才成立，而 1.76.1 之前它每写一次就被清掉：
`modelUpsert` 是 `INSERT OR REPLACE`，REPLACE 先删旧行再插新行，列清单里没有的
列回到默认值——`fee_migrated` 没有默认值，也不在那张列清单里，于是抽屉保存、
渠道合并、配置还原，每写一次模型行，这行就又成了「老版本留下的」。下次启动迁移
按从不清零的旧价列重来：

- 组价后来改过 → 旧价对不上任何组 → 按模型名插一个**旧价的重复组**（绑定被
  `COALESCE` 保住了，组却已经插进去了）；
- 删过组或主动解绑的模型（`fee_group_id` 为 NULL）→ `COALESCE` 把它**绑回**旧价组。

还原把每个模型行都写一遍，所以换机几乎必中。它没被拦住，是因为这个标记不在
`Model` 上（往返测试看不见），迁移函数本身此前零测试，而仓库里的测试不跑真
SQLite——REPLACE 的列默认值只在真库上显形。

现在是两道：

1. **`modelUpsert(m, pricing)` 显式写标记**，三种：
   - `local`（抽屉保存、探测回写、渠道合并）：绑了组就盖章；**没绑组时沿用这一行
     原来的标记**（`VALUES` 里一个子查询——REPLACE 删旧行之前它已经求值，sqlite3
     实测）。启动时的迁移失败只 warn、不挡启动，库里可能还有没搬的行；这时保存
     一次（在 AI 面板改个思考档位就算）不能替它盖章，否则旧价再也归不了组。新建
     的模型没有原来那一行，读成 NULL，而它的旧价列全是 0，迁移只盖章。
   - `restored`（v3 备份还原）：一律盖章。新机器上没有原来那一行，「沿用」会读成
     NULL，源机器上主动不绑的模型就会被迁移按旧价绑回去。
   - `legacy`（v2 及更早的备份还原）：强制 NULL，让迁移按旧价归组。

   参数**必填**是故意的：`.map(modelUpsert)` 会把下标塞进第二个参数，必填加
   字面量联合让编译器点名每个调用方。
2. **迁移只替没绑组的行建组。** `fee_group_id` 有值的行一定是新代码写的——这一列
   和 `fee_migrated` 是同一次加的，老版本不认识它，它的 REPLACE 只会写成 NULL——
   绑定是决定过的，这种行只盖章。空串和 NULL 同算「没绑」（写回用
   `COALESCE(NULLIF(fee_group_id, ''), ?)`，和过滤、`rowToModel` 同一个定义）。
   这一道也是**已经受害的库**的止血：升级后第一次启动，被清掉标记的已绑定行只盖章。

两件有意没做的事：

- **不清理已经长出来的重复组。** 分不清哪个是作者自己建的，删错是静默丢价。
  （另一个来源与本节无关、也没修：两个进程同时迁移同一批行——多开时同时升级
  启动，或一个窗口还原时另一个正在启动——会各自按同价建一个组。迁移不是跨进程
  互斥的；根治要把「读待迁移行 + 插组 + 盖章」放进一个 `BEGIN IMMEDIATE`。）
- **指向已删除组的 `fee_group_id`（死 id）当「已绑」，只盖章。** 按旧价把它绑回
  去，和「删组 = 引用置空、从此不按这份价计」冲突；1.76.1 之前它同样不会被绑回
  （只是多插一个没人用的组）。

剩一种分不清的：1.76.1 之前被清掉标记、**又**主动解绑的行，升级后第一次启动仍会
被绑回旧价组一次——它和「老版本加的无组行」在库里长得一模一样。之后本版本自己
不会再这样写；但同一个 `config.db` 上如果还跑着 1.76.1 之前的任何构建（更老的
不认识这一列，1.74.0–1.76.0 的漏写了它），它保存模型时照旧会清掉标记，下次这里
启动时照旧会发生——这和「老版本加的行下次启动被迁移」本来就是同一条路。

## 配置备份

`CONFIG_BACKUP_VERSION` 升到 **3**：包里多一项 `feeGroups`，模型多一个
`feeGroupId`，渠道多一个 `defaultFeeGroupId`。只带模型不带组，导到新机器上
每个模型都会变成「未绑定」，而那种缺失不报错，只是从此一分钱记不出来。

v2 的包读得进来：它的模型行还带着旧价格列，落库之后同一步迁移会把它们归并成
组——和一台机器从老版本升上来走的是同一条路，不是第二条。只认 v2 的构建会
**整体拒绝** v3 的包，而不是导到一半。

「落库之后同一步迁移」要真的发生在落库**之后**：`applyConfigImport` 在事务前
调 `configDb()` 只是为了建表，那次迁移扫不到这批还没写进去的行；`aiStore` 的
schema 检查一个进程只跑一次。所以事务提交之后再跑一次迁移，否则还原 v2 包到
下次重启之间模型全是「未绑定」，这期间的请求一分钱都记不下来。它在事务外、失败
只 warn：配置已经在库里，迁移是派生计算，下次启动的 `ensureAiSchema` 会再试。
代价要说清：迁移失败时界面照样报「导入完成」，旧版备份的模型到重启前按 0 计。
这时保存它们，`local` 沿用那一行的 NULL 标记，下次启动照样迁移——**除非**在
模型抽屉里保存、而渠道设了默认计费组：抽屉编辑一个未绑定的模型时会预填渠道
默认组（这是另一个问题，不在本节修），保存就绑上了那个组，迁移只盖章，旧价
不再归组。

包记住自己是不是旧价（`ParsedConfigBundle.legacyPrices` = 版本 < 3），落库时据此
选 `modelUpsert` 的 `pricing`（`legacy` / `restored`）。v3 包里没绑组的模型照样
盖章：那是源机器上决定过的，不该被旧价绑回去。

还原确认（文件 / 服务端）和服务端的版本列表都数出计费组（`EnvelopeCounts.feeGroups`，
可选——老 header 没有就不说，不说成 0）：价格从 v3 起跟着备份走，作者应当看得出
这份备份带没带价。

## 界面上的几个判断（设计稿 05l · 1n）

- **份额用长度，种类用词。** ~~用量页的分组条只有一个强调色、长度表示占比。不把
  成本拆成五段上色：这个仓库只有一个强调色，五段要么互相认不出，要么逼出一套
  新色板。~~ 几何比颜色能表达更多状态。

  > **「不拆五段上色」这一条已于 2026-09 推翻**（见下方「计量条为什么改成分段」）。
  > 「份额用长度」那半句仍然成立——条的长度至今表示的还是调用次数的占比，
  > 这次改的只是条**内部**。
- **计量条为什么改成分段**（2026-09 推翻上面那一条）。作者要的是「一眼看出钱
  花在输入还是输出上」，而一个单色条回答不了这个问题——它只回答「谁最大」。

  推翻的是**理由的前提**，不是口味：当初说「这个仓库只有一个强调色，五段要么
  互相认不出，要么逼出一套新色板」。实际做下来，**五个具名段各借一个已经存在的
  语义色相就够了**，一套新色板都没逼出来——

  | 段 | 借谁 | 为什么是它 |
  | --- | --- | --- |
  | 输入 | `--color-type-text-fg` | token 输入就是文本 |
  | 缓存 | `--color-success` | 缓存是省下来的那部分输入，绿色读作省 |
  | 输出 | `--color-sienna` | 钱主要花在这一段，给它唯一的强调色 |
  | 张数 | `--color-type-image-fg` | 这一段的钱就是出图与输入图的钱 |
  | 时长 | `--color-type-video-fg` | 按秒的钱：转写、视频 |
  | 其它 | `color-mix(--color-text-dim, --color-border 25%)` | 中性灰：这一段**没内容**，它表示「说不出花在哪儿」 |

  六个都是 `tokens.derive` 层的 `--usage-seg-*`，**不进 41 个核心契约**：外观
  主题不写就跟着公式走，想定制可以直接声明同名 token 覆盖。「认不出」那一半也
  量过了：六色两两 15 对，paper 最小 ΔEok 0.100、night 0.099，是大色块可分辨阈的
  五倍；六套内置主题里最弱的是 `ink` 的「张数/时长」0.067，仍是该阈值的三倍多。

  **几何比颜色能表达更多状态这句话没被推翻**——所以长度的语义一个字没动，
  段的名字仍然由文字（tooltip）说，颜色只负责把「这是几段、各占多少」说清楚。

  钱怎么分成六段：`costOf()` 的七项经 `segmentsOf()` 分流（**不重算**），
  记账那一刻就抄在用量行的 `cost_*` 六列上，读的那一侧只 `SUM`——和 `cost_usd`
  是同一条规矩。升级前的老行没有这六列，用量页把它们单独数成「未分项」而不是
  摊进六段；`lib/ai/usageBackfill` 会用行上的快照重算一遍，**对得上账才补，
  对不上就留白**。

- **7px 方块沿用 05c。** 组列表每行头上：实心 = 配了价，虚线 = 全是 0。和模型
  抽屉的节目录同一个记号，作者不用学第二套。
- **未覆盖要说出来，并且能一键去补。** 没命中任何档位的请求按 0 计，条下面一行
  「N 次请求没匹配到档位」+「去补档位 →」。不报警色：没配档位不是错误，是还没
  配完。明细行照常把规格写全——那正是作者该抄进表里的一行。
- **切到「全部」多出「按项目」那一层**，它同时是「为什么有两本账」的自我解释。
- **清除是两个动作。** 范围切在哪就清哪一份，按钮文字跟着换。清掉一个项目的
  记录不是在说「这半年我没花过钱」，所以本项目那次清除不碰总账。
- **切计价方式不清空别的方式的值**（`FeeGroupDrawer` 的表单是一个完整的
  `FeeGroup`）——切回来价还在。
- **渠道默认组只预填新模型**（2026-09-23 修正）。模型抽屉的计费组下拉，新建时
  初值是渠道的 `default_fee_group_id`，**编辑已有模型时是它自己的绑定，空就是空**
  （`ModelDrawer.initialFeeGroupId`）。b753f6d9 起到这次之前，编辑时也拿渠道默认
  兜底：一个未绑定的模型——作者故意不绑的，或组被删、引用被置空的——一打开抽屉
  下拉就是渠道默认组，而未绑定行的价格段默认收起，作者看不见；改个名字、调个
  思考档位一保存，它就被绑上、开始计费。这也架空了「删组 = 从此不按这份价计」
  （不变量 1 的删组置空）：删掉的组的模型只要再被编辑一次，就会被渠道默认接走。
  未绑定是一个状态，不是「还没填」，所以预填只发生在还没有状态的时候。

  别处没有「编辑时预填」：渠道合并（`channelMerge.planMerge`）搬过来的模型原样
  带着自己的绑定，折叠进同名模型时留的是保留方那一行的绑定，两边的默认组都不看；
  `updateModel` 的其它调用方（AI 面板的思考档位、换主线路时钉 `activeRoute`）都是
  在原行上展开改一个字段。反方向倒有一处**没预填**、这次没动：新建渠道时一起加的
  入门模型不带 `feeGroupId`，哪怕同一张表单里已经选了默认组——它们是新模型，
  按上面的规矩本该预填；要补就在 `ProviderDrawer` 的 `starterModels` 循环里带上
  `form.defaultFeeGroupId`。

## 厂商与搜索（2026-09-22）

价格搬进组之后组开始变多，一屏十几行只能靠自己起的名字认。加了两样整理手段：
一个**厂商**标签把列表分段，一个搜索框。两样都**不参与算钱**——`vendor` 不进
`FeeConfig`、不进 `costOf()`、不写进用量行，所以上面九条不变量一条没动。

### 厂商为什么是自由文本

不绑 `PLATFORM_IDS`，也不绑 `Provider` 的外键：**一份价常被好几个渠道共用**
（直连一个、中转一个，同一个厂商），把组绑到渠道会把两件事绑死。枚举还会挡住
中转站、自建端点，以及「按张计价」这类作者自己想出来的整理维度。
`docs/reference/terminology.md` 里「厂商」本来就是那个跟接入方式脱钩的词——它
在那份表里是用来反衬 Platform（协议方言）与渠道（一把 key + 一个平台）的。
写法的一致交给补全（`<datalist>`，候选是已经用过的值），不交给校验。

### 段序为什么不按名字排

段的顺序是**这一段第一个组在原列表里的位置**，未填厂商的一段恒排最后
（`organizeFeeGroups` 末尾那次 `sort` 只把空厂商挪到末尾，`Array#sort` 是稳定的，
别的段保持首现顺序）。不按名字排的理由：中英混排下「按名字」到底是拼音还是
笔画取决于运行时的 ICU 数据，同一份配置在两台机器上会排成两样；而原列表的顺序
（`sort_order` → `created_at`）是迁移和作者自己留下的，分段不该把它推翻。

**这条和将来的拖拽排序有关**：段序现在是从组的顺序派生的，真要做重排时得先决定
重排的是段内还是段间——别从代码里反推。

### 大小写合并，但只合并大小写

归段的键是 `vendor.trim().toLowerCase()`，显示用**第一次出现的那个写法**：手打
一次 `openai` 不该和 `OpenAI` 各占一段。挡得住大小写，挡不住「Open AI」——那种
只有补全能防，没做改名/合并工具。

### 搜索为什么连模型一起搜

三个维度：组名、厂商、**这个组绑着的每个模型的 `name` 与 `modelId`**。作者记得住
`qwen3.8-flash`，不一定记得住自己给那组价起的中文名。两个字段**分别**比，不拼成
一个字符串——拼接会在接缝上造出一个原文里不存在的词（`name:"foo" modelId:"bar"`
会被 `oo b` 命中）。

代价是结果里会出现「组名里根本没有这个词」的行，所以那一行的副标题从「N 个模型」
换成「命中模型 …」：它是这一行凭什么出现的理由。**组名或厂商自己命中时不写**
——那只是噪音。

### 备份版本号为什么不涨

`CONFIG_BACKUP_VERSION` 保持 3。版本号该涨的条件是「老版本读到新格式会出错或
读错」，而这里两个方向都是合法状态：老版本读新包，没人读 `vendor` 那一键，厂商
丢掉而价格一个字段不差；新版本读老包，厂商读成空。为一个可空的整理标签涨版本号，
只会让老版本整体拒掉一份价格完整的备份。

### 顺带修掉的两处「不是这个应用画的」

设计稿 2g 画的就是这两处，都是上一轮（PR #663）留下的：

1. **抽屉里每个输入框都退回了浏览器原生样式。** 它们写的 `hub.input` / `hub.unset`
   在 `ProvidersModels.module.css` 里**不存在**——输入框样式一直在
   `settingsCommon.module.css`。CSS Module 对不存在的类返回 `undefined`，模板串把它
   拼成字面量 `"undefined"`：没有报错、没有警告。顺带一条从没生效过的规则也补上了：
   「空着的格画虚线、填了 0 的画实线」原本挂的正是那个不存在的类。
   `.unset` / `.badPrice` 都把类名写两遍（`.unset.unset`）才稳定压过 `.input`
   ——单写一次都是 0-1-0，谁赢取决于 bundle 里两个模块的先后。
2. **两个选组的下拉是原生 `<select>`**（模型抽屉的「计费组」、渠道抽屉的「渠道
   默认计费组」），而**同一个抽屉里别的下拉早就用了 `components/common/Select`**。
   换过去之后这一轮要的两件事正好都是它现成的：`option.group` 就是 `<optgroup>`
   的平铺写法（厂商直接当段用），`searchable` 让组多起来之后能搜。「未绑定」保持为
   `value: ""` 的第一项而不是 placeholder——它是一个真的选择，不是「还没选」。
   （排版格式 Beta 那边还有四个原生 `<select>`，另一个功能，不在这次范围里。）

### 这一轮没做

拖拽排序（见上面段序那一条）、厂商改名 / 合并工具、按厂商批量改价、
分段折叠、模型行上单独存一份厂商（模型的厂商由它绑的组间接给出，存两份会各说各的）。

## 已知没做

- **币种一律 `$`。** 人民币标价的组（千问转写按 ¥/秒）要作者自己换算后填；
  金额那一列仍叫 `cost_usd`，记进去的是 ¥ 数。这是 ASR 那一轮就有的账目不一致
  （`docs/feature/asr/02-ui-brief.md`），这次没有解决，只是把它从模型行搬到了组上。
- **视频「提交即计费 + 结算」没做**：这个应用还没有视频生成端点。
- **上游报价没有任何协议在发**：`reported_cost` 那一列留着、算式也留着（有它就
  压过整张表），但今天没有一处写它。加一个会报价的协议时，翻译成中性键
  `reported_cost_usd` 的换算只写一处，并且要在铺上游 `usage` 的地方剔掉这个
  保留键——否则中转起个同名字段就能定账。
- **组级「信任上游报价」开关**没做。
- **档位表的下拉菜单**没做：三个条件都是自由输入框。各模型家族的参数并集可以
  自动收集，但那是菜单不是校验，值不值得再说。
- **拖拽排序**没做：`fee_groups.sort_order` 列留着，写入口以后再加。
