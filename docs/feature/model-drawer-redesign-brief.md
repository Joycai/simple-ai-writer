## 与设计稿的出入（都是有理由的）

- **结构化输出「自动」在未识别的模型上是 JSON 模式，不是设计稿写的「关闭」。** 设计稿 1n 与 19b 的 note 写着「自动 → 关闭 · 未识别到支持，不发 response_format」，而 `lib/ai/jsonMode.ts` 的解析是族默认 `json_object`（这正是今天所有模型的行为）。note 与「将发送」都按真实解析显示——于是 **19b（GPT-5 官方）的「将发送」不是空的**：`response_format json_schema · 结构化任务时`（GPT-5 在 id 表里）。Anthropic 族则恒显示 `thinking.type adaptive`，因为那个适配器每次请求都发它。一行说真话的摘要比一行好看的空摘要值钱。
- **上下文档位取现有 `CONTEXT_SIZE_STOPS`**（16k / 32k / 128k / 256k / 512k / 1M），不是设计稿的 32k / 64k / 128k / 200k / 256k / 1M——那张表另有消费者。设计稿没给「清空」路径，实现里**再点一次已选中的 chip 即清空**。
- **探测面板整块沿用**（快速探测按钮 + 深度检测勾选 → 确认 → 进度 → 报告 → 应用），没有重画成两按钮条；它落在限额节里、带自己的一句话 hint。实测标记只有日期，没有「快速 / 深度」种类——面板的回执里没有这一项，加一列去存它不值。
- **思考强度的开 / 关类目也放了一枚「跟随默认」虚线 chip。** 设计稿只画了开 / 关两枚，但「跟随默认 ＝ 不发」是这一屏自己的规则，两枚都不亮的状态需要一个名字。
- **温度改成单个数字框**（照设计稿），原来的 0 / 0.3 / 0.7 / 1 chips 去掉了；「确定性」标签只在 0 时出现。
- **19g 的联动演示台**（切类目的按钮条）不实现，它是设计稿的说明装置；联动本身在抽屉里可点。
- **英文的一句话 hint** 与中文一起进了 `en.json`；「为什么」的英文仍是今天英文 hint 的原文。

## 明确没做的

- 抽屉宽度、进出动画、Esc、底部按钮条：全部沿用供应商抽屉，没动。
- 结构化输出不上左侧列表（设计稿 19h 也这么定）：它不改变模型出现在哪些候选里。
- 模型行的启用 / 禁用开关仍不暴露。
- 设计稿 1n 提到的「协议族在供应商那边改回来时能力声明的行按同样方式增减」——今天抽屉是按供应商打开的，改协议族要关掉抽屉去改供应商，回来时是一次全新挂载，没有过渡可做。

# 设计任务：重做一款桌面写作应用的「模型」编辑抽屉

## 产品背景

这是一款给小说 / 剧本 / 标书 / 公众号文案作者用的桌面写作应用（Tauri + React，Mac 和 Windows）。作者自己接大模型：官方端点、第三方中继、或本机跑的 Ollama / LM Studio。**设置 → 供应商与模型** 是一个合并的面板：左边是按供应商分组的模型列表，右边滑出一个抽屉编辑其中一条。供应商（地址、密钥、协议标准）的抽屉已经定稿，本次**只做「模型」那一个抽屏**。

一个「模型」在这个应用里的含义是：**某个端点下的一行，作者对它买到了什么的声明。** 同一个中继下面 `gpt-5` 与 `qwen-turbo` 的能力毫无关系，所以能力、限额、价格、思考参数全挂在模型上，不挂在供应商上。这是不会变的数据模型，请不要把任何字段上移到供应商。

## 它今天长什么样，以及为什么必须重做

**为什么塌了：**

1. **三种作者用同一个抽屉，而它只为第二种服务。**
   - 接官方端点、用主流模型的作者：填 id 和名字就该结束。今天他们要滚过十二个和自己无关的组。
   - 接中继 / 本地模型的作者：**这个抽屉存在的理由就是他们**——协议方言、能力、限额，端点不会告诉应用，只有作者知道自己买了什么。他们需要全部字段，还需要每个字段旁边那段「为什么」。
   - 配图片模型的作者：一套完全不同的表单（出图那一组），今天和文本模型的字段混在同一条滚动流里，靠类型 chip 切换整块显隐。
2. **提示文字是这个应用唯一的文档，但它们永远摊开。** 上下文大小的 hint 有三段话，服务端工具的 hint 解释了「本机无法逐次批准」这条安全含义，翻译格式的 hint 是一条会让模型消失的警告。**一个字都不能删**——中继作者读的就是它们——但它们让抽屉长到三屏。
3. **字段之间联动，切一个 chip 别的字段就出现或消失。** 类目决定强度的档位、决定预算字段有没有、决定温度字段有没有；类型决定整块表单；协议族决定四个能力声明各自有没有。今天这些出现 / 消失没有任何过渡，像 bug。
4. **两种来源看不出区别。** 上下文与输出上限可能是探测面板量出来的（带时间戳），也可能是作者敲的；前者会过期（中继明天可能把同名模型路由到别的上游）。今天只有一行小字「于 × 测得」挂在探测面板底下，离那两个字段很远。
5. **「未设置」是这个表单最重要的状态，而它长得和「填了 0」一样。** 不变量：**未设置 = 什么都不发，让端点用自己的默认**。这是对所有中继都安全的唯一选择，任何应用主动发出去的字段都是某个网关可能拒绝的字段。所以每个空输入框都是一个有意义的决定，而不是「还没填」。温度尤其：0 是作者故意要的确定性输出，空是「别管它」，两者今天视觉上一样。
6. **左边列表一行只露 名字 · id · ctx · 类型**。一个作者有 20 个模型时，分不出哪个开了思考、哪个声明了 PDF、哪个是翻译专用——得逐个点开。

## 这个界面要解决的核心张力

**同一个抽屉，要让官方模型的作者 5 秒关掉，让中继作者读完每一段「为什么」。**

偏向：**按「有没有值」而不是按「重要不重要」决定展开。** 一个全空的节折成一行摘要（「未设置 · 跟随端点默认」），有值的节展开。这样官方模型的抽屉自然只剩身份和计费，中继作者填过的节自然全开，而且**折起来的那一行本身就在说「没发任何东西」**——这正是第 5 条要的诚实。

第二条偏向：**提示文字两级——一句话常驻，「为什么」按需展开。** 常驻的一句话回答「填什么」，展开的回答「为什么这么设计、填错会怎样」。展开态要能一次全开（中继作者第一次配的时候会想全读）。

## 要你设计的

1. **抽屉的信息架构。** 给一个提案，不要三个泛泛的方向。建议的分节：身份 / 计费 / 限额与实测 / 思考 / 能力声明 / 采样与前置提示词 / 出图（仅图片）。请决定：节的顺序；哪些节能折；折起来的那一行写什么；「添加模型」（全空）时是什么样。
2. **「未设置」的视觉语言。** 空输入框、「跟随默认」chip、关着的 toggle、折起来的节——它们表达的是同一件事（不发），请给它们一个统一的、和「填了值」有区别的样子。特别处理**温度 0 vs 温度空**。
3. **实测值 vs 手填值。** 探测面板量出来的上下文 / 输出，要在**字段本身**上看得出来源和日期，而不是在面板底下。探测面板本身的内部流程（确认 → 进度 → 报告 → 应用）不重做，只决定它落在哪、默认收成什么。
4. **联动的出现与消失。** 切类目→强度档位换一套、预算字段出现、温度字段消失；切类型→整块表单换掉；切协议族（在供应商那边改，回来时）→能力声明增减。请给这些一套过渡口径（时长、方向、什么该动什么不该动）。应用的动效规则在设计稿 04 / 17 的说明里已有一段「例外 · 转场与浮层」，遵守它。
5. **能力声明这一节的形态。** 四项（服务端工具、PDF、翻译格式、结构化输出）今天是三种控件（toggle、下拉、chip 行）。统一成一列，还是保留各自形态？翻译格式那条「声明后会从候选里消失」的警告怎么放。**结构化输出**在 Anthropic 族只有两个选项、hint 要解释「该协议族没有 JSON 模式参数」——这行不能隐藏，作者需要看到这个解释。
6. **左侧列表的一行要不要多露信息。** 目前 名字 · id · ctx · 类型。请决定要不要加思考 / 能力的小标记，加什么、加几个、什么时候不显示。列表的分组、排序、搜索不动（设计稿 09 / 18 已定）。
7. **思考类目 chip 的换行。** Anthropic 族是 自动 + 3 预设 + 关闭，OpenAI 族是 自动 + 5 预设 + 关闭，抽屉宽度里放不下一行。
8. **双主题、中英。** 设置页用 04 定的暖纸色系（`--stg-*`，页 `#FBF7EE`、输入 `#FFFDF6`、赭石 `#A9512B`）与设置页的衬线标题字；深色沿用 04 的映射。英文标签普遍比中文长 1.5–2 倍（"Structured output" / "Thinking parameter category"），chip 行请按英文校一次。

- ComfyUI 导入的文案、摘要、五种错误：不动。
- 「从 API 拉取可用模型」只在新建时出现：不动。

## 明确不在范围

- 供应商抽屉、列表的排序 / 搜索 / 分组、用量页。
- 不新增任何参数——**只有「结构化输出」一项是新的**，它的四个选项和按协议族的裁剪已经定案。
- 不做「按模型预填能力」的智能推断（那是探测维的事，另一个功能）。

## 给设计师的开放问题（请回答，不必都采纳）

1. 抽屉顶部要不要一行**「这个模型现在会发出去什么」的摘要**（如 `enable_thinking · thinking_budget 8000 · enable_search · response_format json_schema`），随表单实时变化？它是给中继作者排错的利器，也可能是给官方作者的噪音。
2. 计费放第二节（今天的位置）还是放最后？它是最少改、也最常填错的一组，而用量页依赖它。
3. 「探测真实上限」是限额节里的一个按钮，还是限额节本身就是探测的结果视图（手填只是覆盖）？
4. 结构化输出的「自动」档在 19c 里会实际解析成 JSON Schema——这个解析结果要不要显示在 chip 旁边（「自动 → JSON Schema」）？思考类目的「自动」今天不显示解析结果，两者要一致。
5. 折起来的节，「有值」的判定要不要把「自动」算成有值？（自动 = 未设置，但作者可能想看到它。）
