# 设计任务：为一款桌面写作应用的设置页，在「AI 配置」分组下新增两个页面

## 0. 这是什么应用

一个桌面写作应用（Tauri + React，Mac 和 Windows），面向小说 / 公文 / 标书 / 周报作者。左边文件树，中间 Markdown 编辑器，右边一个很宽的 AI 抽屉，里面住着一个能读文件、提修改、每次写盘都要作者点批准的 AI 助手。

它的**设置是一个整窗页面**：左侧固定 246px 的导航，右侧内容区。你们之前为它画过一屏（`04 系统设置 Settings`），这次是那一屏的续篇：**导航结构要动，两个页面要新画**。请沿用 04 的全部语汇（暖纸底、直角、方形开关、eyebrow 小节标题 + 1px 细线、左标题右控件的行），不要另起一套。

## 1. 现状，以及为什么要动

左侧导航现在是这样：

```
通用
工作台
排版格式            ← 只在「Word 排版导出」Beta 开着时出现
── AI 配置 ──
供应商与模型
子代理
Prompt
用量
── 数据 ──
同步与备份
──────
快捷键
关于
```

「通用」这一页塞了八个小节：外观 · 语言 · 图片 · 系统通知 · **实验功能** · 调试 · 数据维护 · 重置应用。问题出在中间两节：

- **「实验功能」是七个 Beta 开关**，每一个开的都是 AI 助手的能力（PPTX 导出 / Word 排版导出 / Excel 导出 / 互动式角色扮演 / 日中翻译 / 本地 ComfyUI 生图 / 助手工具包模式）。作者找它们的时候心里想的是「AI 能不能干这个」，却要去「通用」里翻，翻到的还是一页外观和语言之间。而且其中三个开关**开了以后要去别的页接着配**（翻译要去「子代理」绑模型，ComfyUI 要去「供应商与模型」登记图像模型，Word 导出会让「排版格式」这一项在导航里出现）——它们的邻居本来就该是 AI 配置分组里的那几页。
- **「图片」只有一行**：「发送给模型的最大长边」——超过这个尺寸的图片在发给模型前等比缩小，原文件不动。这不是外观设置，它决定的是**一张图进入模型上下文时占多大**。它和「通用」里的任何一节都不是一家的。

顺序是我的建议，你可以改，但请说明理由。我的理由：「上下文与记忆」是每次对话都在用的东西，挨着模型与 Prompt；「实验室」放在分组末尾，因为 Beta 本来就是这一组的边缘——而且把它压在「用量」之后，「排版格式」在导航上半区出现 / 消失的动静离它的开关远一点，作者不容易误以为自己点错了地方。

两项各需要一个 15px 的 lucide 图标，请从 lucide 现有图标里选，并说明选了哪个（现有几项用的是 SlidersHorizontal / BookOpen / Layers / Users / MessageSquare / BarChart3 / RefreshCw / Keyboard / Info / FileType）。「实验室」我倾向 `FlaskConical`，「上下文与记忆」我没有明显的候选——`Brain` 太具象，`Layers` 已被占用，请给一个。

### 2.2 屏 A ——「实验室」页

装现在「实验功能」那一节的七行，**一行一个开关**，每行：标题 + 一到三句说明 + 右侧方形 toggle。七行的现有文案如下（可以精简措辞，但信息不能丢——每一句都是有人踩过坑之后加上去的）：

| 标题 | 说明（现文案） | 开了以后要去哪 |
|---|---|---|
| PPTX 导出（Beta） | 让 AI 助手把自己写的 .html 转成 .pptx，HTML 预览里也会多一个导出按钮。版式取自浏览器实测的布局，文字仍是可编辑文字；渐变、滤镜这类 CSS 会降级，每次导出都会列出降级了什么。 | — |
| Word 排版导出（Beta） | AI 助手可以把文档导出成 .docx，并按「排版格式」页里的预设排版。结构来自 markdown，字体字号行距页边距全部来自预设。**关着时另有一句：**关掉后左侧导航里没有「排版格式」这一项，AI 助手的工具清单里也没有导出 Word——它不会提出一次自己无法执行的导出。已建的预设留在盘上，重新打开就回到原样。 | 排版格式（导航里会**新出现**一项） |
| Excel 导出（Beta） | AI 助手可以把文档里的 markdown 表格导出成 .xlsx：一张表格一个工作表，名字取自它上面的标题。数字、百分数、日期和 = 开头的公式会写成真的数字、日期和公式，其余留成文本——批准前的卡片上逐张写着判成了什么。 | — |
| 互动式角色扮演创作 | 在 AI 助手里多出「扮演」一栏：绑定知识库人物，以第一人称和他们对话；旁白 agent 能读到全部对话并把互动整理进正文。对话记录存在项目的 .ai-writer/roleplay/ 下。 | — |
| 日中翻译（Sakura） | 接入本地部署的专用日中翻译模型（Sakura，经 LM Studio / Ollama 等 OpenAI 兼容端点）。开启后需在 子代理 里绑定一个已声明翻译格式的模型，助手才会获得 translate 工具。 | 子代理 |
| 本地 ComfyUI 生图 | 把本地 ComfyUI 实例接成一条出图路由：在 ComfyUI 里搭好工作流、导出 API 格式 JSON，在 供应商与模型 里登记成一个图像模型（出图接口选「ComfyUI（本地）」）。应用只填提示词 / seed / 尺寸，checkpoint、LoRA 等全按你调好的样子照发。关闭只是收起配置入口，已配好的模型不受影响。 | 供应商与模型 |
| 助手工具包模式 | 对话助手改为「主控编排」：常驻一套轻工具（查、读、笔记、记忆），文档 / 知识库 / 导出的改动一律派给带专职工具的执行代理完成——审批卡照常出现。每轮工具开销从约 10k 降到约 4k token，对小上下文的本地模型最有感。实验中：模型需要能可靠派单（实测 Gemma 级可以；有的模型会陷在反复读文件里）。下一条消息起生效；系统提示在新会话时刷新。 | — |

这一页要解决的四件事：

1. **「开了以后要去哪」要变成可点的东西。** 现在它埋在说明文字里（「需在 子代理 里绑定」）。三行有下一步，四行没有；请设计一个只在有下一步的行上出现、且在**开关打开之后**才出现（关着的时候没有下一步）的去处——是行尾一个小链接、说明下方一行、还是开关旁边？由你定。它不是按钮，是「接着去哪」的路标。
2. **「Word 排版导出」开关会让导航多出一项。** 作者点下这个开关，左边导航上半区**立刻**多出「排版格式」。这个跨区的因果要能被看见——但不要弹窗、不要 toast。想一想那一项该怎么出现（滑入？先高亮一拍？）以及开关这一行要不要指一下它。
3. **七个开关的分量不一样。** 三个是导出格式（互相是兄弟），一个是整个新的工作方式（扮演），两个要接本地服务（翻译、ComfyUI），一个改的是助手的内部运行方式（工具包模式）。要不要分小节（eyebrow + 细线）、按什么分、还是一列到底靠间距分组——请给方案并说明理由。**不要**给每行加不同颜色的图标或标签来区分类型：强调色只有一个，且 Beta 本身不该做成一个「新功能！」的橱窗。
4. **页面标题下那句副标题**（每一页都有一行灰字副题，例如「通用」是「外观、语言与本地数据」）：请拟一句。它要说清「这里的东西默认关着、开了会给助手加能力、关掉不删数据」这三件事里最重要的那一件。

**不要**搬进这一页的：「调试 → API 调用日志」（那是排查问题用的，不是功能开关，留在通用）；「配置备份」和「重置应用」（不动）。

### 2.3 屏 B ——「上下文与记忆」页

这一页**这次只装一节**：

| 小节 | 行 | 控件 |
|---|---|---|
| 图片 | **发送给模型的最大长边** · 说明：超过这个尺寸的图片会在发送前等比缩小，原文件不受影响。留空 / 0 = 原样发送。 | 数字输入框，范围 256–16384，步进 256，空值占位文字「不缩」 |

它叫「上下文与记忆」而不是「图片」，是因为这个名字是给**将来**起的：应用里已经有好几样「一次对话往模型里装多少东西」的设置，今天散在别处（知识库注入预算和上下文利用率住在 AI 面板的工具条里；「默认最大输出」住在「供应商与模型」页顶部；前情提要用哪个模型住在文库视图）。它们**这次都不搬**——搬不搬是另一个决定——但这一页是它们将来的家。

所以这一页的设计难点只有一个：**一节一行的页面，怎么不像一间空屋子。** 请给两个状态：

- **B1 · 今天的样子**：一节一行。不要用占位卡片、虚线框、「更多设置即将到来」这类东西填空——那是承诺，不是设计。可以考虑的是副标题怎么写、这一节的位置（顶部贴着标题？还是自然落下？）、以及一行的说明文字是否可以稍微多说一句「为什么图片是上下文的一部分」。
- **B2 · 装满以后的样子**（仅用于检验版式，不实现）：假设加进三节——「知识库注入」（预算 token 数 + 上下文利用率两行）、「输出」（默认最大输出一行）、「前情提要」（用哪个模型一行）——B1 的版式是否还站得住，节与节之间的节奏是否一致。**如果 B1 和 B2 不能是同一套版式，请以 B1 为准并说明取舍。**

副标题也请拟一句。

### 2.4 「通用」页瘦身之后

不需要重画整页，但请画一下**瘦身后的小节顺序**：外观 · 语言 · 系统通知 · 调试 · 数据维护 · 重置应用。「图片」和「实验功能」走了以后，「系统通知」直接接在「语言」后面是否突兀，「调试」和「数据维护」要不要合并成一节——给一个判断即可。

## 3. 视觉规范（硬约束，必须遵守）

- **风格**：克制的、现代的、Apple 式的。整体气质是「手稿」——像裁切的纸，不像圆角卡片。
- **圆角：全局为 0。** 所有容器、按钮、输入框、下拉都是直角。唯一允许的圆形是状态圆点、加载指示器、单选标记。**开关是方形的**：42×22 的轨道，1px 描边，14×14 的平面方块做旋钮，无阴影。
- **强调色：只有一个**——赭石色 sienna（设置页用它自己那档：浅色 `#A9512B`；深色跟随夜间色阶）。禁止在交互元素上用多色渐变、禁止给 Beta 行加第二种颜色。
- **设置页有自己的一层纸**：比主工作区更亮一点的米白底（浅色页面 `#FBF7EE`，输入框 `#FFFDF6`），标题用衬线（Source Serif 4 / Noto Serif SC）。
- **层次靠背景深度 + 1px 细线**，克制用阴影。小节 = eyebrow 大写小字 + 一条 1px 细线 + 若干行；行 = 左侧标题与说明、右侧控件，行与行之间 1px 细线，末行无线。
- **导航项**：选中态是强调色淡染 + 强调色文字 + 加粗；悬停是中性灰。分组标题是 eyebrow 大写小字。
- **字体**：正文衬线，UI 标签无衬线，**数字等宽**（那个 px 输入框里的数字要等宽）。
- **动效**：120–320ms，Apple 缓动。不要弹跳、不要大位移。导航里「排版格式」一项的出现 / 消失也在这个范围内。
- **深浅双主题**：两套都要出，不是深色改个背景色了事。
- **文案**：面向作者的词一律说「知识库 / 条目 / 文档」，不说「设定 / 词条 / 设定集」。

## 5. 数据边界（防止设计出画不出来的东西）

- 七个 Beta 开关每个只有**开 / 关**两态，没有「配置中」「已连接」之类的中间态；应用不知道翻译模型有没有绑上、ComfyUI 有没有登记——所以「去处」路标只能是「去那一页」，不能是「已完成 ✓」。
- 「最大长边」只是一个整数；没有预览、没有当前图片、没有「本项目里有多少张图会被缩」的统计。
- 导航项的出现 / 消失只有「排版格式」这一处会发生，其余项恒在。
- 这一页没有「保存」按钮：每个开关点下去即时生效并持久化，和 04 一致。
