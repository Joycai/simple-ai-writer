## 设计稿改了方案的两处

1. **主题文件的元数据从 `==theme==` 注释块改成 `--theme-name / --theme-scheme / --theme-extends` 自定义属性**（1f 的导出节选、1c 屏 02「缺 --theme-name / --theme-scheme」）。采纳，已写回方案 §5：校验器本来就用 `CSSStyleSheet` 解析文件，元数据写成属性同一次解析就读到了，不用再写注释解析器。

# 设计任务：在本项目里新建 `05i 主题 Themes.dc.html`

## 这一屏是什么

设置 → 通用 → 外观 这一节要长大。今天它是三行：主题（浅 / 深 / 跟随系统 三个芯片）、字体方案（四张卡）、Markdown 排版主题（五张带样张的卡）——见 `05a 系统设置 Settings.dc.html`。这次不是重画它，是给它加上**主题文件**的概念：作者能往一个文件夹里丢一份 CSS，它就出现在这里，和内置的并排。

两种主题文件，各自一根轴：

- **外观主题**（应用外壳的颜色）：一份只声明设计令牌的 CSS。它有明暗极性（浅或深），没有布局、圆角、字体——那些它改不了，也不该让作者以为能改。
- **排版主题**（Markdown 预览、知识库正文、导出的 HTML / PDF 的排版）：一份只作用于文档容器的 CSS，Typora 那种。它可以自带字体和颜色，也可以完全借外观主题的颜色。

其余背景请直接看 `05a`（设置页的纸色方言）、`05b 设置 · AI 配置`（实验室 / 上下文与记忆两个 pane 的分节写法）、`05c 模型编辑`（**虚线 = 未设置** 那条规矩，这次会用到）、`05e`–`05h Word 排版格式`（设置页里「一组卡 + 一行动作」最近的一次写法）。不用重新解释产品。屏号从 `05i` 起是因为 `05h` 已被 Word 排版格式（三）占用。

## 这次要解决的五个张力

**1. 「跟随系统」是一对主题，不是一个。**
模式是 浅 / 深 / 跟随系统。选了浅，只需要挑一张浅色主题；选了跟随系统，得挑**两张**——白天用哪张、夜里用哪张。今天的三个芯片下面直接是字体卡，这一对卡没有地方站。要一个既让「一张」时不显得空、又让「两张」时说得清哪张对应哪一头的布局。折叠、并排、两栏都可以，但**不要**做成两个 tab——作者要一眼看见白天和夜里各是什么。

**2. 内置、我的、本项目的三种来源并排，却不分组。**
作者挑主题的时候不关心它从哪里来；但坏了的时候必须知道文件在哪。来源应该是卡上的一处 mono 边注（`内置` / `~/…/themes/宣纸.css` / `.ai-writer/themes/…`），不是三个小节。排版主题多一种来源「本项目」（随仓库走的品牌排版），外观主题没有——**不要**给外观主题画项目来源。

**3. 坏主题不弹窗，卡片留在原地说话。**
三种坏法，都要有样子：
- 文件里有几条规则越界被忽略了（主题**能用**，只是少了那几条）——卡片正常显示样张，加一条 mono 边注：「已忽略 3 条规则 · body 越界 · 详情」。
- 文件解析不出元数据（主题**不能用**）——样张位置换成一句话，卡片不可选。
- 偏好里选着它、磁盘上找不到了（**已经回退**到基底）——这张卡以「缺席」的样子站在原位：虚线边（借 `05c` 的「虚线 = 什么都没发/没有」），一句「找不到 宣纸.css，已回到 纸」。作者把文件放回来它就复活，所以**不要**给它「移除」按钮。

**4. 两种卡，两种样张。**
- 外观主题卡的样张是**令牌本身**：一块迷你窗口（左侧栏带 / 编辑区 / 右侧 AI 栏 / 一个强调色点 / 一行正文色），全部由这张主题的五六个令牌画出来，不是截图。内置的「纸」和「夜」也是这样画的，作者的主题和它们长得一样规矩。
- 排版主题卡的样张是**一小页文档**：标题 + 一段正文 + 一个引用或一行代码，用这套排版渲染。实现上它是一个隔离的小窗（不受设置页纸色的影响），所以样张的底色是**这套排版在当前外观主题下**的底色——夜间模式下样张是深的。设计时按这个来，别把样张画成永远的白纸。
- 卡的尺寸：排版卡比今天 `05a` 里的略高一点也行，但网格列数请给出在设置页常见宽度（内容区 640–720px）下的档位。

**5. 作者入口是整套系统的上手路径。**
网格底下一行三个动作：`打开主题文件夹` · `重新载入` · `把当前主题导出为文件`。第三个最要紧——它写出一份完整的、每个令牌带角色注释的 CSS，作者改几行、改个名、放回文件夹，就有了自己的主题。它是**唯一**一条从零到一的路，所以不能藏在 ⋯ 菜单里；但它也不是主要操作（作者一年点一次），所以不是实心主按钮。三个动作要分得出主次而不抢卡片的戏。「重新载入」要有一个 1–2 秒的完成痕迹（借 `02c 提示词库` 里那种赭石细线 + 一句话），因为它成功时通常什么都不变。

## 交付什么

一个 `.dc.html`，屏号 1a 起，浅 / 深两套 + 中 / 英，带设计说明侧栏：

- **1a** 外观一节全貌——模式 = 浅色时：芯片行、一组浅色主题卡（纸 + 两张作者主题）、字体方案（不变）、排版主题网格（五张内置 + 一张我的 + 一张本项目）、作者三动作。
- **1b** 模式 = 跟随系统：两组主题卡同时在场的样子。
- **1c** 三种坏法各一张卡（可以拼在一屏）。
- **1d** 「已忽略 N 条规则 · 详情」点开之后：一个小小的列表（第几条 / 选择器 / 原因），mono，不是模态。
- **1e** 排版主题卡在夜间外观下的样张；一张自带字体的排版主题卡上「自带字体」怎么标。
- **1f** 「导出为文件」点下去：一个写盘完成的痕迹（文件名 + 位置 + 「打开文件夹」），不是保存对话框——文件直接写进主题文件夹。

## 数据边界（设计只能用这些字段，防止画出画不出来的东西）

每张卡背后是这样一条记录：

```
id            文件名去后缀（内置是保留字：paper / night / manuscript / clean / magazine / wechat / typewriter）
kind          ui | markdown
name          显示名（内置双语；作者主题只有一种语言，就是文件里写的那个）
scheme        light | dark（只有 ui 有）
extends       基底 id（作者主题叠在哪套内置之上）
source        builtin | user | project
path          文件路径（内置没有）
version, author   可选
problems[]    { 第几条规则, 选择器, 原因 } 的列表；空 = 干净
missing       true 时表示偏好选着它但文件不在
```

**没有**的东西：缩略截图、下载数、评分、更新时间、颜色数量、「作者头像」。外观主题卡的样张只能从它的令牌里取色；排版主题卡的样张只能是渲染出来的样文。

## 沿用 `05a` 的方言，以及这一轮容易踩的几条

- 设置页的纸色、行 / 节 / 卡 / 芯片的写法全部照 `05a`；全局零圆角；开关是方块。
- **虚线只表示「没有 / 缺席」**（`05c` 的规矩），不要拿虚线做「未选中」的卡边。未选中的卡就是普通卡，选中的卡是赭石 2px 边 + 左上角一个方形标记，与 `05a` 今天的排版卡一致。
- 来源 / 路径 / 问题计数一律 mono 小字（`--font-mono`），与全应用「计数与 id 用 mono」同规。
- 样张里的文字用真实的样文，不要「Lorem」，也不要把样张画成可交互的东西——它们是画，不是缩小的应用。
- 排版主题的样张在夜间是深底：请画出来，别默认白纸。
- 「跟随系统」两组卡之间的关系词请用 `浅色时` / `深色时`，不要 `白天` / `夜晚`（作者的系统不一定按时间切）。
- 不做：主题商店、在线安装、评分、可视化编辑器、按项目切外观主题、拖拽排序。
