## 现象

Anthropic 族（④ Messages）上，`temperature` 这条能力由规则里的条件
`{when: "categoryThinks", absent: "fire"}` 裁决：**思考类目不是 `off` 就算在想**，在想就不发温度，
抽屉里的温度输入框也跟着不显示。没设类目也算在想。

理由在规则注释里：官方 Messages API 在思考开时只收 `temperature: 1`。把作者填的 0.2 夹到 1
是「以尊重之名发出相反的东西」，所以宁可不发。这条对 `claude-adaptive` / `claude-budget` 是对的——
它们的「关闭」在线上是最低档（`offSpelling: "lowest"`），关了也还在想。

但 ④ 族上还有两个开关型类目，关闭时线上是真关：

| 类目 | 用在哪 | 「关闭」发什么 | 关了还在想吗 |
| --- | --- | --- | --- |
| `minimax` | MiniMax 的 ④ 端点 | `thinking: {type: "disabled"}` | 不想（landscape.md 第四个样本） |
| `doubao-switch` | 火山方舟 Coding Plan 的 ④ 线路 | `thinking: {type: "disabled"}` | 不想（landscape.md 火山方舟样本「思考，④ 面」） |

这两个类目选了「关闭」，类目仍是 `minimax` / `doubao-switch` 而不是 `off`，所以今天**照样不发温度**，
抽屉也不给填。作者想在关思考时压低温度，做不到；而这可能本来是可以的。

## 如果改

把条件换成按线上思考状态裁决（`{when: "thinking", is: "on"}`），逐格的变化只有一处：

- `minimax` / `doubao-switch` 设为「关闭」时，开始发作者填的温度；
- 其余不变：这两个类目没设或开着时仍在想，照旧不发；`claude-adaptive` / `claude-budget` 的「关闭」
  是最低档，仍在想；`off` 类目今天就发，照旧。

受影响的是 MiniMax、火山方舟 Coding Plan 两个平台的 ④ 线路，以及中转站 / 自定义渠道上作者手选了这两个类目的 ④ 行。

改动本身很小，但有一处连带：抽屉今天只拿**类目**问这一格；改成按思考状态后，还要带上强度，
温度输入框会随「开 / 关」出现和消失。这是界面上的变化，要不要这样呈现随改动一起定。

## 三种结论，三种做法

问的是这两家的 ④ 端点在思考关闭时收不收、听不听非 1 的温度。三种可能，结论各不相同：

1. **200 且生效** → 改。账本 B6 从「不排期」改为排期，金标差异只应出现在上面那一处。
2. **400**（像官方那样只收 1，或只收某个范围） → 不改；把实测写进规则注释与矩阵文档，今天的判断从「猜的」变成「量过的」。
3. **200 但被无视**（回显或输出分布显示没生效） → 不改：发一个没人听的字段，还要在抽屉里给一个改了没用的框，
   违反「抽屉不画不起作用的控件」。

已有的旁证不够下结论：New API 上转发 Claude 的 ④ 渠道，有的在思考**开**时对 `temperature: 0.3` 回 400，报错与官方同文
（landscape.md 第十六个样本 ④ 面「参数校验」一行）——那是开着的情形，而且背后是 Claude，不是这两家。

## 实测结果（2026-09-28）

`live.anthropic-temperature.test.ts`，走真实适配器，只在 fetch 这一层补上 `temperature`——就是改了规则之后适配器会发的请求体。
逐轮数据与判法记在 landscape.md：火山方舟在第十二个样本下、MiniMax 在第四个样本下，各一段「B6 补测」。

原定的第 2 条（0 与 1 各连发 5 次开放题、看一致性）量不出来：开放题每句都不一样，温度 0 下句子开头明显趋同，
不同句子的个数照样是 5。改成只有几个常见答案的题（水果、1–50 的数），每档 20 次，看低温度是否收敛到同一个答案。
只用一道题也不够：MiniMax 在水果题上不发温度就已经 19–20/20 答同一个，那道题对它说明不了什么。

| | 火山方舟 Coding Plan ④（doubao-seed-2.0-mini） | MiniMax ④（MiniMax-M3） |
| --- | --- | --- |
| 关思考 + `0.3` | 200，确实没想 | 200，确实没想 |
| 关思考 + `0.01`，数字题 | **收敛**：19/20（水果题 19–20/20） | **不收敛**：10–11/20，与不发、与 `1` 分不开 |
| 关思考 + `0` | **等于没发**：四轮都落在不发温度的范围里 | 同样分不开（本来就看不出温度） |
| 开思考 + `0.3` | 200，不是官方的 400 | 200，不是官方的 400 |
| 开思考 + `0.01` | 不收敛：10–13/20，远不到关思考时的 19–20 | 不收敛 |
| ① 面对照 | `0` 在 ① 面是生效的 | ① 面同样看不出温度（M3 在 ① 面总在想） |

- **`doubao-switch`：结论 1**，带一个例外——`0` 在 ④ 面等于没发。
- **`minimax`：结论 3**——200 但被无视。今天不发是对的，理由从「在想」换成「没人听」。
- **两家开思考时**都不报错也不收敛：今天「在想就不发」仍然对，理由同样从「会 400」换成「发了没人听」。

所以 B6 原来的写法——把条件整条换成按线上思考状态裁决——对 `minimax` 是错的：它会让 MiniMax 关思考时发一个没人听的温度，
抽屉还要画一个改了没用的框。

## 结论（作者 2026-09-28 拍板）

- **落在类目上**：`doubao-switch` 加 `temperatureWhenOff`，规则的条件改读「线上听不听温度」（`temperatureHeard`）。
  平台格那条路不走：请求条件在解析顺序里先于平台格，要让格子盖过条件是给求值顺序加特例。
  事实跟着类目走，中转站、自定义渠道上手选了这个类目的行也得到它（类目本来就是作者对「对面是谁」的声明）。
- **`0` 只加说明**：这一类目上温度栏下的说明写明「这条线路把 0 也当作没填，要最稳的输出，填 0.01」，不挂「确定性」标签。
  不在适配器里把 0 改发成极小正数——那是改写作者写下的值。
- `minimax` 不变：关思考时仍不发、抽屉仍不显示。
