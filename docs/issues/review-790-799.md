# PR #790–#799 review verification

> Status: `open`. Verified against `42fd2e78`; fixes and remaining follow-ups recorded on 2026-10-24.

## Fixed

- Document retrieval failures (including missing models, timeout, dimension changes and oversized catalogs) and zero admitted matches now retain contiguous prose up to the planned allocation, capped by assembly at 16,000 characters. The old 6,000-character fallback wasted available budget. Smaller/zero windows and the edit anchor remain hard limits; cancellation still propagates.
- A writing task snapshots semantic preferences for planning and both retrieval paths. The panel subscribes to preference saves so its forecast responds immediately to the document toggle.
- Both languages explicitly disclose that earlier manuscript passages go to the chosen embedding/reranking services.
- Error summaries now recognize arbitrary opening HTML tags and XML declarations, while the raw error remains escaped text.
- Thinking-only controls use the thinking label; whole-response controls use the effort label. Slider width is measured before paint.
- Effort-profile matching requires a generation boundary; `gpt-5.60-sol` and `claude-opus-50` no longer inherit adjacent profiles. Broad output-cap families retain their intentional prefix matching. Tests compare native catalog categories with platform resolution, including dated identities where the platform supports them (the exact `deepseek-flash` alias is not a dated family).
- Phycat Neon code accent is a border on the scroll container, so it stays visible during horizontal scrolling. Journal code backgrounds and Phycat code/row backgrounds request print colour preservation. Example theme versions advance to 3.

## Findings that do not justify the proposed change

- **Cache identity:** `indexIdentity` hashes the resolved URL, model ID and entire retrieval configuration. Format, path and both prefixes already invalidate the namespace; a regression test now pins this. Rotating credentials does not invalidate vectors.
- **Tools versus always-reasoning models:** the current `effortWithTools` refusal cells apply to GPT-5.4–5.9 on official Chat and the exact OrcaRouter GPT-5.6 Sol ID. They do not overlap GPT-6 Astra or GPT-6.1 Sol's no-off profiles. Newer Claude profiles do **not** declare `reasoningOff: false`, contrary to the report. A regression test covers the actual always-reasoning models on these routes. Returning low in a hypothetical contradictory cell would still violate the route's no-effort-with-tools restriction; do not silently introduce that workaround. Platform cells intentionally match raw endpoint IDs; catalog IDs must not replace that axis.
- **Opus 4.6 off:** `claude-adaptive.offSpelling` is `lowest`, and `ReasoningControls` already displays stored off as low. Removing the duplicate off stop for known Opus profiles was intentional (reasoning-plan §0.1). This is not a missing disabled-thinking option in the present category contract.
- **Retry focus:** the global doubled `:focus-visible` selector supplies the keyboard focus ring. A local duplicate is unnecessary.
- **Retry history:** keeping an explicit continuation turn is intentional and documented in the codemap. It preserves successful writes and the author's retry action through persistence; a transient instruction would make a reloaded conversation different. No adapter rejection was reproduced. Strict-relay/Gemini live acceptance remains unverified; do not claim universal acceptance from offline tests.
- **Collection references:** `collections:` contains membership names, not foreign entry IDs. Cross-entry citations and external file links can be dangling, but exporting a membership name itself does not lose a referenced entity.
- **Badge colours:** reusing existing type colours is an explicit choice in semantic-retrieval-beta; adding required appearance tokens would change the theme contract. Model type labels remain distinct.
- **Usage fallback:** retrieval supplies reported input tokens/search units to the existing fee snapshot and `recordUsage`; no second pricing formula is needed. Actual provider billing equivalence needs endpoint-specific evidence, not a guess from `total_tokens`.
- **Printing:** Phycat already preserves quote/header/code colours. Neon deliberately removes dark quote backgrounds in print. The confirmed missing backgrounds above are fixed without undoing that print design.
- Sequential snapshot copying, import-cleanup helper naming, mixed colour spaces, a single remaining Morandi token use, relative corner radii, default thumb placement, and the two-character paragraph delimiter allowance are not demonstrated correctness regressions. The historical PR grouping cannot be repaired by another code change. Version bumps remain a repository requirement.

## Open follow-ups

1. **Document cache lifecycle — addressed in 1.99.11:** namespace LRU now bounds live document-vector payload to 64 MiB and eight namespaces per project. Old file/model hashes are evicted by recency without guessing file identities. Tests cover legacy caches, byte/count limits, concurrent retrieval, and checkpointed backup restoration. See [cache lifecycle policy](../feature/lore/semantic-retrieval-beta.md#document-cache-lifecycle-19911). SQLite file compaction is deliberately separate: this limits live data, not an existing database’s physical high-water mark.
2. **Stable chunking — addressed in 1.99.12:** versioned content-defined local-minimum anchors replace offset-dependent packing, with bounded no-paragraph processing and surrogate-safe overlap. Offline tests measure over 85% embedding-input reuse after early insertion/deletion and over 90% chunk reuse in varied prose. Anchorless repetitive text can still shift; the first v2 retrieval rebuilds its namespace. See [algorithm and tradeoffs](../feature/lore/semantic-retrieval-beta.md#stable-document-chunks-19912).
3. **Partial bundle dependencies — addressed in 1.99.13:** selected-entry exports inspect the copied Markdown and gallery metadata, warn about unresolved bundle-local citations/files, and allow cancellation before saving. Selection and original references remain unchanged. See [scope and limitations](../reference/architecture.md#partial-bundle-dependency-warnings-19913). Path normalization is a defensive follow-up, not a reproduced mismatch between today's scanner and export paths. Narrow-width collection-button layout still needs visual verification.
4. **Retyping/deleting a bound retrieval model — addressed in 1.99.14:** model saves and model/channel deletion warn about known active-project retrieval bindings (including disabled retrieval) and explicitly unverified other projects. Selections remain intact for explicit replacement; no project count or paid work is inferred. See [shared model mutation policy](../feature/lore/semantic-retrieval-beta.md#shared-model-changes-and-deletion-19914).
5. **Retrieval UX:** first indexing lacks incremental progress; cosine and reranker scores share one threshold. A separate threshold changes saved preference semantics and needs migration/default decisions. Inline endpoint validation remains a usability enhancement.
6. **Failed-stream usage:** incomplete failed calls are not fully metered. Predates these PRs; requires partial-usage provenance and exactly-once accounting across retries, never estimated billing disguised as reported tokens.
7. **Reasoning controls:** unknown `lowest` categories can still offer synonymous off/low stops; Default's parked thumb is an explicit current affordance. Budget ceilings versus output/answer reserves require protocol-specific validation; the report does not establish that Qwen's declared thinking budget must be clamped by the conversational output cap on every route.
8. **Provider scope:** the compatible Qwen batch limit is intentionally tied to the measured host/path/model, not inferred for every international host. Live route behaviour, unsupported old-build downgrade behaviour, dark-theme hover contrast and browser print appearance remain unverified.

## Validation

Regression coverage exercises fallback budgets/anchor fences, timeout recovery, dimensions, namespace identity, preference snapshots, HTML error summaries and model/category matching. Type-check, offline suite and production builds are run for this patch. Live provider tests require network access and are not evidence of offline correctness; no paid endpoint verification is part of this change. No Rust implementation changed.
